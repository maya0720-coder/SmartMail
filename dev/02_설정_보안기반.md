# 02. 설정 · 보안 기반

메인 문서: `dev/00_MAIN_개발진행.md` · 다음 단계: `dev/03_저장소_보관기간_지표원장.md`

## 목표

모든 단계가 공통으로 쓰는 설정 로딩, 민감정보 마스킹, 로그·오류 정책을 먼저 만든다.

## 관련 요구사항

AI-03, GK-07(전송 전 마스킹), AUTH-08(로그 정책), 기획서 5장(비기능)

## 작업

1. `src/config/settings.py`
   - pydantic-settings로 `.env`와 설정 파일을 읽는다. 필수값 누락·형식 오류는 시작 시 명확하게 실패.
   - 항목: 서버 바인딩(기본 `127.0.0.1`만 허용, 다른 값이면 시작 거부), 포트, 외부 사이트 URL 4종(위키·G-Knowledge·AI-Ground·그룹웨어, 기본값 없음), 보관 기간(기본 7일), 지표 원장 보관 플래그(기본 false), 타임아웃.
   - 자격증명 관련 설정 키는 만들지 않는다.
2. `src/security/masking.py`
   - 마스킹 대상: 주민등록번호, 계좌번호, 카드번호, 전화번호, 이메일 주소(선택), 비밀번호·인증번호 문맥, API 키·토큰 패턴.
   - `MaskedText` 타입(불변 객체)을 정의하고 `mask(text) -> MaskedText`로만 생성되게 한다. 외부 전송 함수는 `MaskedText`만 인자로 받는다.
3. `src/security/logging_policy.py`
   - 로그 필터: 마스킹 적용, ID·암호·토큰·세션 쿠키 키워드가 포함된 레코드 차단.
   - 로그 내용: 이벤트 종류, 시각, 성공/실패, 대상 사이트 이름만.
4. `src/app/errors.py`: 사용자에게는 일반 메시지만, 내부 경로·스택은 숨김(디버그 모드는 로컬 개발에서만, 기본 꺼짐).

## 검증(필수 테스트)

- 마스킹: 각 패턴 정상 마스킹, 비슷하지만 대상이 아닌 문자열은 유지, 빈 문자열·매우 긴 문자열 경계
- `MaskedText`를 거치지 않은 문자열을 전송 함수에 넣으면 타입 검사(mypy)에서 실패하는지 확인
- 설정: 필수값 누락 시 시작 실패, 바인딩 주소가 `127.0.0.1`이 아니면 거부
- 로그: 'password=' 같은 문자열이 로그 파일에 남지 않음
