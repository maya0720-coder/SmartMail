# 09. 이력 조회 · 업무 히스토리 · 보관 알림

메인 문서: `dev/00_MAIN_개발진행.md` · 다음 단계: `dev/10_위키_주간보고.md`

## 목표

유사 업무를 앱(최근 7일) → G-Knowledge → AI-Ground g-llm 순서로 찾고, 앞 단계에서 찾으면 멈춘다. 완료 업무는 삭제 전에 G-Knowledge 등록을 안내한다.

## 관련 요구사항

HIST-01 ~ HIST-06, SRCH-01 ~ SRCH-05, RET-02 · RET-03

## 작업

1. 히스토리 카드(HIST-01·02): 완료 시 회신 메일에서 문제·원인·조치 초안을 만들고 사용자 확인 후 저장. 공개 범위 기본 '팀'(HIST-05, 로컬 버전은 표시만).
2. `src/domain/search/pipeline.py`: 3단계 조회
   - SRCH-01: 앱 히스토리 키워드 + 필터(모듈·기간·태그)(HIST-03). 유사도 검색(HIST-04)은 선택 구현.
   - SRCH-02: 없으면 08단계 `KnowledgeStore.search`.
   - SRCH-03: 그래도 없으면 06단계 `KnowledgeAI.suggest_solution`(마스킹, 'AI 생성·검증 필요' 표시).
   - SRCH-04: 결과마다 출처 배지(앱 / G-Knowledge / AI), 사용자가 다음 단계 강제 실행 가능.
   - SRCH-05: 유용한 AI 답변은 검토 후 G-Knowledge 등록(08단계 재사용).
3. 해결 단계와 '도움 됨/안 됨'(HIST-06)을 이벤트로 기록.
4. 보관 알림(RET-02): 삭제 2일 전 G-Knowledge 미등록 완료 업무 알림 + 등록 버튼.

## 검증(필수 테스트)

- 앱에서 찾으면 G-Knowledge·AI 호출 0회, 앱에 없고 G-K에 있으면 AI 호출 0회
- 세 단계 모두 실패 시 '해결 방안 없음' 처리
- 7일 경과로 앱 기록이 삭제된 뒤 G-Knowledge에서 조회되는 흐름(Fake)
- 알림 경계값(삭제 2일 전 정확히)
