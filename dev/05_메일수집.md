# 05. 메일 수집 (클래식 아웃룩 COM · 그룹웨어 전환)

메인 문서: `dev/00_MAIN_개발진행.md` · 다음 단계: `dev/06_AI-Ground_g-llm_연동.md`

## 목표

사용자 PC의 아웃룩 메일을 로컬에서 읽어 업무 추출에 넘긴다. 새 아웃룩처럼 읽을 수 없는 PC는 그룹웨어 메일함으로 전환한다.

## 관련 요구사항

MAIL-01 ~ MAIL-10

## 작업

1. `src/collectors/base.py`: `MailCollector` 인터페이스 — `list_threads(since, until)`, `get_message(ref)`(화면 표시용 일시 조회), `open_in_client(ref)`.
   - 반환 모델: 참조 ID, 스레드 ID, 제목, 보낸 사람 표시명, 수신·발신 시각, 본문(메모리에서만 사용, 저장 금지), 첨부 파일명 목록.
2. `src/collectors/outlook_com.py`(MAIL-01): pywin32로 클래식 아웃룩 받은편지함·보낸편지함 읽기, 스레드 묶음(MAIL-03), 기간 지정(기본: 주간보고 주기 목~수)(MAIL-04). 첨부는 열지 않음(MAIL-06).
3. `src/collectors/detect.py`(MAIL-07): 클래식/새 아웃룩 감지. COM 연결 실패 시 그룹웨어 경로 제안.
4. `src/collectors/groupware.py`(MAIL-02): 인터페이스와 Fake만 구현. 실제 연동 방식(API/IMAP)은 `확인 필요`로 두고 추측 구현 금지. 로그인은 04단계 로그인 창 사용.
5. 제외 규칙(MAIL-05): 공지·뉴스레터·자동발송·지정 발신자/폴더. 규칙은 설정 파일로.
6. 원본 참조(MAIL-08~10): 저장은 참조 ID만. 화면에서 볼 때마다 원본 조회, 없으면 '원문 없음'. '아웃룩에서 열기'는 클래식에서만.
7. 수집 결과는 03단계 `mail_ref`(요약 제외)와 이벤트(수신)로만 기록.
8. (2026-11-12 개정, 결정기록 0009) 자동·증분·기간 지정 수집(MAIL-04)
   - 처음 실행(수집 기준 시각 없음): 실행 시각 기준 최근 `SMARTMAIL_MAIL_INITIAL_DAYS`일(기본 30일)을 자동 수집한다.
   - 이후: 마지막 수집 성공 시각 − 1시간(늦게 도착한 메일 대비)부터 지금까지 증분 수집한다. 앱 시작 시 1회 + `SMARTMAIL_MAIL_SYNC_MINUTES`분(기본 10분)마다 자동 실행하고, 화면 '메일 새로고침'도 같은 증분 수집이다. 새 회신은 기존 업무에 연결되고(TODO-04) 회신 감지(TODO-05)가 다시 적용된다.
   - 수집 기준 시각은 `sync_state` 테이블에 시각만 저장한다. 수집에 실패하면 옮기지 않는다. 한 번에 읽는 범위는 최대 366일이다.
   - 수동 기간 지정: 시작일~종료일(포함, KST)을 골라 따로 수집한다. 자동 수집 기준 시각은 바꾸지 않는다. 역순·미래 종료일·366일 초과는 거부한다.
   - 자동 수집과 화면 버튼이 겹쳐도 수집·업무 반영은 한 번에 하나만 실행한다.

## 검증(필수 테스트)

- `tests/fixtures/`의 합성 메일로 만든 Fake 수집기로 스레드 묶음·기간 경계(목 00:00, 수 23:59)·제외 규칙 검증
- 본문이 DB에 저장되지 않음을 검사
- 원본 삭제 상황(Fake)에서 '원문 없음' 처리
- 처음 30일 자동 수집, 증분 수집(겹침 구간 중복 없음), 실패 시 기준 시각 유지, 기간 지정 경계·거부 조건(`tests/unit/test_mail_sync.py`)
- COM 연결 실패 시 그룹웨어 전환 제안이 뜨는지
- 실제 아웃룩 연동 테스트는 수동 점검 항목으로 분리하고 결과를 보고(자동 테스트에서 실제 메일함 접근 금지)
