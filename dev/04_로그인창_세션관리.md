# 04. 로그인 창 · 세션 관리 (자격증명 비저장)

메인 문서: `dev/00_MAIN_개발진행.md` · 다음 단계: `dev/05_메일수집.md`

## 목표

위키·G-Knowledge·AI-Ground·그룹웨어 로그인을 앱의 로그인 창으로 처리하되, ID·암호는 어디에도 저장하거나 기억하지 않는다.

## 관련 요구사항

AUTH-01 ~ AUTH-10 (기획서 4.7)

## 작업

1. `src/security/credentials.py`
   - 로그인 요청 1회 동안만 ID·암호를 받고, 대상 사이트 어댑터에 넘긴 즉시 참조를 끊는다(가능하면 `bytearray`로 받아 사용 후 0으로 덮어쓰기).
   - 반환값은 `SessionHandle`(사이트 이름, 만료 시각, 내부 세션 객체 참조)뿐. ID·암호를 담는 필드 없음.
2. `src/security/sessions.py`: 세션은 메모리에만 보관. 로그아웃·유휴 시간 초과(설정값)·앱 종료 시 폐기. 일괄 로그아웃 함수.
3. 브라우저 자동화 세션(G-Knowledge 등): Playwright 비저장 컨텍스트(임시 프로필)만 사용. 종료 시 쿠키·캐시·임시 폴더 삭제.
4. `src/security/residue_check.py`(AUTH-07): 앱 시작·종료 시 임시 폴더, 로그, 브라우저 프로필 흔적을 검사하고 자격증명·세션 쿠키가 발견되면 즉시 삭제하고 '발견·삭제 건수'만 로그에 남긴다.
5. 로그인 API(`src/app`): POST 본문으로만 받기(쿼리스트링 금지), 응답·로그에 입력값 미포함, 실패 시 일반 메시지. CSRF 방어, 요청 속도 제한.
6. 로그인 창 화면: 사이트명 표시, `autocomplete="off"`, 암호 칸 `autocomplete="new-password"`, '저장하지 않음' 안내, 자동 로그인·기억하기 옵션 없음. 제출 후 입력칸 즉시 비우기.
7. AUTH-09: 2단계 인증·SSO 사이트는 해당 사이트 로그인 화면을 브라우저 창으로 띄워 사용자가 직접 입력(앱이 값을 받지 않음). 실제 적용 사이트는 확인 후 설정으로 지정.

## 검증(필수 테스트, AUTH-10)

- 로그인 후 DB·로그·임시 폴더·브라우저 프로필 경로를 검색해 테스트용 ID·암호 문자열이 없음
- 잘못된 입력·빈 값·매우 긴 값 거부, 실패 응답에 입력값 미포함
- 세션 만료·로그아웃·앱 종료 후 세션 사용 시 거부
- 잔존 검사: 가짜 흔적 파일을 만들어 두면 시작 시 삭제됨
- 로그인 테스트는 Fake 사이트 어댑터로만 실행(실제 사이트 접속 금지)
