## 0. 확정 사항

| 항목 | 결정 |
|---|---|
| 화면 컨셉 | **A안 트리아지**: 왼쪽 목록 + 오른쪽 근거 메일 |
| 빠른 정리 모드 | **포함**: B안 카드 화면을 A안 상단 전환 버튼으로 제공(3단계) |
| 결정지 | 할 일로 / 나중에 / 업무 아님 (+ 되돌리기) |

| '업무 아님' 학습 | **확신도만 낮춤**: 자동 제외 없음. 규칙은 PC 로컬에만 저장, 설정에서 초기화 |

Claude Code는 시작 전에 아래 결정기록을 `docs/결정기록/0015_제안된업무_트리아지_개편.md`로 만들고, `dev/00_MAIN_개발진행.md` 진행표에 '15. 제안된 업무 트리아지' 행을 추가한다.

```text
# 0015 제안된 업무 트리아지 개편
- 결정: 제안된 업무 화면을 트리아지(목록+근거 메일)로 바꾸고, 결정지를 할 일로·나중에·업무 아님 3종으로 한다.
- 나중에: 상태는 '제안됨' 유지, snooze_until(다음 근무일 08:00 KST)까지 숨김. 공휴일은 고려하지 않음(사내 달력 연동 전).
- 업무 아님 학습: 보낸 사람 주소·제목 말머리의 키 해시만 로컬 저장, 확신도 감점만 하고 자동 제외하지 않음. 설정에서 초기화.
- 되돌리기: 결정 후 60초 안에 같은 화면에서만 허용(승인 → 제안됨 복귀 포함). 일반 상태 전이 표(TODO-03)는 바꾸지 않고 '결정 취소' 전용 경로로 처리.
- 업무 제목: '대상 + 행동' 규칙, 일반 문구만 남으면 메일 제목 유지(점검 D1).
- 이유: 판단 근거 부족·결정지 부족으로 아웃룩을 다시 여는 문제 해소(컨셉안 1장).
```

## 2. 화면 명세

### 2-1. 기본 화면(A안) — `templates/suggestions.html` 재작성

```text
┌ 제안된 업무   오늘 정리 4/9 ▓▓▓░░   나중에 2건(내일 아침)   [전체][일반업무][전자결재][확신도 낮음]  [⚡ 빠른 정리] ┐
├ 목록(380px, 자체 스크롤) ────────┬ 상세 ─────────────────────────────────────────────────────────┤
│ 오늘                            │ {업무 제목}  [✎]                                   ▮▮▮▯ 확신도 │
│ ▌제목 · 구분 · 기한 · 부서 09:12  │ ✉ 원래 메일 제목: {원본 제목}                                    │
│  …                              │ [구분 ▾] [기한] [요청 부서] [주간보고 예상 위치 ▾]   ← 읽기 모드   │
│ 어제 / 이번 주 / 이전            │ ✦ 왜 제안됐나요: (이유 칩)                                        │
│                                 │ ✉ 메일에서 찾은 요청 문장 (본문 일부, 요청 문장 <mark>)            │
│                                 │ ⏱ 비슷한 지난 업무 (앱 7일 범위, 최대 2건)                          │
│                                 │ ───────────────────────────────────────────────────────────── │
│                                 │ [할 일로 A] [나중에 S] [업무 아님 D]  (전자결재면 [결재함 열기])    │
└─────────────────────────────────┴─────────────────────────────────────────────────────────────┘
키보드: ↑↓ 이동 · A 할 일로 · S 나중에 · D 업무 아님 · E 제목 고치기 · Q 빠른 정리 모드
```

| 영역 | 명세 |
|---|---|
| 머리 | 제목, 오늘 정리 진행 막대(오늘 결정 수 / 오늘 처음 본 제안 수), '나중에 n건(다음 근무일 아침)' 링크(누르면 숨긴 목록 펼침), 탭 4개(건수 표시), 빠른 정리 전환 버튼 |
| 목록 | 묶음: 오늘·어제·이번 주(목~수)·이전(받은 시각 기준). 항목: 제목(1줄 말줄임), 구분 칩(전자결재는 청록), 기한 칩(지남=빨강, 3일 이내=주황), 요청 부서, 스레드 메일 수(2통 이상), 받은 시각, 확신도 막대 4칸. 선택 항목은 왼쪽 강조선 |
| 상세 머리 | 제목(읽기 모드, E 또는 ✎로 편집. Enter 저장·Esc 취소), 확신도, '원래 메일 제목'(상세를 열 때 원본에서 읽음, 원본이 없으면 '원문 없음') |
| 필드 4칸 | 구분(설정 목록), 기한(날짜), 요청 부서, 주간보고 예상 위치(금주 실적·차주 계획·이슈·넣지 않음). 평소 읽기 모드, 누르면 편집. 바뀐 값은 '할 일로' 때 함께 저장 |
| 왜 제안됐나요 | 이유 코드(3-2장)를 사람이 읽는 문구로 표시. 학습 감점이 있으면 "비슷한 메일을 '업무 아님'으로 고른 적 있음" 칩 |
| 요청 문장 | `GET /api/tasks/{id}/context` 결과의 본문 앞부분(최대 12줄, 회신 기록 앞까지). 요청 문장 위치를 `<mark>`로 표시. 첨부는 파일명만(MAIL-06) |
| 비슷한 지난 업무 | 기존 검색 1단계(앱 7일)만 자동 실행해 최대 2건 표시. G-Knowledge·AI는 실행하지 않음(로그인·비용 부담) |
| 행동 줄 | 할 일로(주 버튼), 나중에, 업무 아님(글자 버튼). 전자결재면 '결재함 열기'(그룹웨어 주소가 설정돼 있을 때만, `security/links.py` 허용 목록 사용) |
| 처리 후 | 항목이 왼쪽으로 빠지며 사라지고(200ms) 다음 항목 자동 선택. 토스트 "{제목} · {결과}" + [되돌리기](60초) |
| 빈 상태 | "정리할 제안이 없습니다" + 마지막 수집 시각 + [메일 새로고침] |
| 좁은 화면(≤900px) | 목록만 보이고, 항목을 누르면 상세가 오른쪽 서랍으로 열림(대시보드 서랍 부품 재사용) |

### 2-2. 빠른 정리 모드(B안) — 같은 페이지 안 전환

| 항목 | 명세 |
|---|---|
| 진입 | 머리의 '⚡ 빠른 정리' 버튼 또는 Q. 현재 탭(필터)의 목록을 그대로 카드 대기열로 씀 |
| 화면 | 가운데 카드 1장(뒤에 2장 겹쳐 보임), 왼쪽 결정 집계·대기열, 아래 버튼 3개 |
| 카드 내용 | 순번, 받은 시각, 확신도, 제목, 구분·기한·요청자 칩, 요청 문장 하이라이트 본문, 이유 칩 |
| 조작 | → 할 일로 / ← 업무 아님 / ↓ 나중에. 마우스·터치로 끌기(가로 110px 또는 세로 110px 넘으면 결정). 끌기에는 항상 같은 버튼 대안 |
| 편집 | 빠른 모드에서는 편집하지 않는다. 고칠 게 있으면 E → 해당 항목을 A안 상세로 열고 모드 종료 |
| 종료 | 대기열을 다 처리하면 "모두 정리했어요 · 할 일 n · 나중에 n · 업무 아님 n" + [대시보드로], Esc나 Q로도 종료 |
| 동작 줄이기 | `prefers-reduced-motion`이면 날아가는 효과 없이 바로 다음 카드 |

### 2-3. 대시보드 연계(점검 D3)

- 대시보드 '내 할 일' 기본 필터를 **'제안됨 제외'**로 바꾼다(전체 필터는 그대로 둠).
- 목록 위에 "정리할 제안 n건 → 제안된 업무" 배너를 두고, 0건이면 숨긴다.

## 3. 데이터·도메인 변경

### 3-1. 저장 필드 (스키마 1 → 2 마이그레이션)

| 대상 | 추가 | 형식 | 비고 |
|---|---|---|---|
| `tasks` | `snooze_until` | TEXT(ISO, KST) NULL | 이 시각 전에는 제안 목록에서 숨김 |
| `tasks` | `confidence` | REAL NULL | 추출 시 확신도(0~1). 학습 감점 반영 전 원값 |
| `tasks` | `reasons` | TEXT NULL | 이유 코드 쉼표 목록(3-2), 최대 6개 |
| `tasks` | `weekly_section` | TEXT NULL | `done`·`planned`·`issues`·`none`, 사용자가 고른 경우만 |
| 새 표 `triage_rules` | `key_hash` TEXT PK, `kind` TEXT(`sender`·`prefix`), `dismiss_count` INT, `updated_at` TEXT | | 원문 주소·말머리 저장 금지. 키는 `data/` 아래 로컬 키 파일로 HMAC |

- `storage/db.py`의 `SCHEMA_VERSION`을 2로 올리고 `ALTER TABLE … ADD COLUMN` 마이그레이션을 추가한다(기존 DB 보존). 마이그레이션 테스트 필수.
- '로컬 데이터 전체 삭제'에 `triage_rules`와 로컬 키 파일을 포함한다.

### 3-2. 이유 코드 (`domain/tasks/extract.py`에서 계산)

| 코드 | 판단 근거(이미 있는 신호 재사용) | 화면 문구 |
|---|---|---|
| `request_phrase` | 본문 요청 문장 발견(`_evidence`) | 요청 표현이 있음 |
| `subject_request` | `REQUEST_SUBJECT` 일치 | 제목이 요청 형태 |
| `due_phrase` | `parse_due` 결과 있음 | 기한 표현이 있음 |
| `to_me` | `message.to_me` | 받는 사람: 나 |
| `cc_only` | 참조로만 받음 | 참조(CC)로 받음 |
| `thread_waiting` | 스레드 2통 이상 + 내 회신 없음 | 대화 n통 · 내 회신 대기 |
| `approval` | 구분이 전자결재로 판별 | 결재 키워드 |
| `ai_judged` | 점수가 애매해 AI가 판정 | AI가 업무로 판단 |
| `learned_penalty` | 학습 규칙 감점 적용 | 비슷한 메일을 '업무 아님'으로 고른 적 있음 |

`TaskCandidate`에 `reasons: tuple[str, ...]`를 더하고, 생성 시 `tasks.reasons`에 저장한다. 문장은 저장하지 않는다.

### 3-3. '나중에' (`domain/tasks/service.py`)

- `snooze(task_id)`: 상태가 '제안됨'일 때만 허용. `snooze_until = next_business_morning(now)`.
- `domain/calendar.py`에 `next_business_morning(now, hour=8)` 추가: 월~목 → 다음 날, 금·토·일 → 다음 월요일, 08:00 KST.
- 제안 목록 조회는 `snooze_until`이 없거나 지난 것만 돌려준다. '나중에 n건' 수는 따로 돌려준다.
- 이벤트 `SNOOZED` 추가(`TaskEventType`, detail 없음).

### 3-4. '업무 아님' 학습 (`domain/tasks/triage_rules.py` 신규 + `storage/` 저장소)

- 무시할 때 원본 메일의 보낸 사람 주소와 제목 말머리(첫 `[…]` 묶음, 없으면 생략)를 **소문자 정규화 → HMAC-SHA256** 키로 바꿔 `dismiss_count`를 1 올린다. 원본은 메모리에서만 읽는다.
- 추출 시 같은 키가 있으면 확신도 감점: 보낸 사람 일치 −0.15×min(횟수,3), 말머리 일치 −0.1×min(횟수,3), 하한 0.05. **자동 제외는 하지 않는다**(점수와 관계없이 후보는 만든다).
- 감점이 적용되면 이유에 `learned_penalty`를 붙인다. '확신도 낮음' 탭 기준은 0.7 미만.
- 설정 화면에 "업무 아님 학습 초기화(규칙 n개)" 행과 버튼 추가 → `DELETE /api/triage-rules`.
- domain은 해시 함수를 인터페이스로 받는다(키 파일 접근은 security/ 또는 storage/).

### 3-5. 되돌리기 ('결정 취소')

- `revert_triage(task_id, decision_token)`: 결정 API가 돌려준 일회용 토큰(메모리 저장, 60초 유효)이 맞을 때만 실행.
  - 할 일로(→대기) 취소: 상태를 '제안됨'으로, 승인 때 바꾼 제목·기한·구분은 이전 값으로 되돌린다.
  - 나중에 취소: `snooze_until` 제거.
  - 업무 아님 취소: 상태를 '제안됨'으로, 학습 카운트 1 감소.
- 이벤트 `TRIAGE_REVERTED` 추가(detail: `approved`·`snoozed`·`dismissed`). 지표(승인률)는 취소를 반영해 계산한다.
- `ALLOWED_TRANSITIONS`는 바꾸지 않는다(결정 취소만 별도 경로).

### 3-6. 업무 제목 규칙(점검 D1)

- `integrations/ai/prompts.py` `SUMMARIZE_TEMPLATE`에 규칙을 추가한다.
  - "무엇을(대상: 시스템·문서·T-code) + 어떻게(행동)"로 쓴다. 예: "KSB1 조회 권한 부여", "PO 결제 조건 문구 변경".
  - 인사·요청 어미("부탁드립니다", "요청드립니다")는 쓰지 않는다.
- `config/rules/task_categories.toml`(또는 새 `title_rules.toml`)에 일반 문구 목록을 둔다. 예: 확인 부탁, 검토 요청, 회신 부탁, 문의드립니다.
- 요약이 일반 문구만이거나 8자 미만이면 요약을 버리고 **메일 제목 정리본을 유지**한다(`summarize.py`).
- 같은 이유로 `CLASSIFY_TEMPLATE`의 SAP 모듈 질문을 '업무 여부 + 확신도'로 줄인다(점검 C7, 구분은 규칙 판별 유지).

| 메서드·경로 | 변경 | 요청 / 응답 요지 |
|---|---|---|
| `GET /api/tasks?status=suggested` | 응답 필드 추가 | `confidence`, `reasons[]`, `weekly_section`, `thread_count`. 숨김(`snooze_until` 미도래) 제외. 헤더 메타 `snoozed_count` 또는 별도 `GET /api/tasks/suggested/summary` |
| `GET /api/tasks/{id}/context` | **신규** | 원본 다시 읽기: `subject`, `sender_name`, `received_at`, `lines[]`(최대 12줄), `highlight`(줄 번호·시작·끝), `attachments[]`, `missing`. 저장·로그 기록 없음. 기존 `/api/mail/{ref}` 로직 재사용 |
| `POST /api/tasks/{id}/approve` | 필드 추가 | 기존 수정 필드 + `weekly_section`. 응답에 `decision_token` |
| `POST /api/tasks/{id}/snooze` | **신규** | 응답 `snooze_until`, `decision_token` |
| `POST /api/tasks/{id}/dismiss` | 동작 추가 | 학습 카운트 반영. 응답 `decision_token` |
| `POST /api/tasks/{id}/revert` | **신규** | 요청 `decision_token`. 토큰 불일치·만료 시 409 "되돌릴 수 있는 시간이 지났습니다" |
| `DELETE /api/triage-rules` | **신규** | 학습 규칙 전체 삭제, 응답 `deleted` 건수 |

- 모든 상태 변경 API는 기존 CSRF·Origin·JSON 검사를 그대로 거친다(`web_security.py`).
- 입력 검증: `weekly_section` 허용 목록, `decision_token` 길이·형식 검사.
