## 0. 요약

| 구분 | 내용 |
|---|---|
| 문제 | 1차 적용본은 색·글꼴·아이콘 같은 **겉모양은 미리보기와 같지만**, (1) 화면 배치가 다르고 (2) 미리보기에서 되던 도표 표현과 조작 기능이 빠져 있다. |

### 1-2. 1024×768에서 보이는 차이

- KPI가 2×2(각 185px)로 바뀌고 도넛이 한 줄을 통째로 차지한다. 그래서 내 할 일이 y≈740에서야 시작한다.
- 상세 패널은 목록 **아래**로 내려가 업무를 누르면 스크롤해야 보인다. 미리보기에서는 1100px 이하일 때 오른쪽 서랍으로 열린다.

## 3. 배치 수정 명세

### 3-1. 대시보드 앱 셸 (L1)

조건: 대시보드(`body[data-page="dashboard"]`), 폭 1025px 이상, 높이 700px 이상. 이 조건이 아니면 지금처럼 문서형(스크롤)을 유지한다.

```text
┌ 데모 배너(있으면 24px) ───────────────────────────────────────────────┐
│ 상단 내비(떠 있음, 52px)                                               │
├ 제목·기간 줄 36px: 대시보드 · 수집 상태 ……………… [연간 반기 분기 월 주] ┤
├ KPI 줄 ≈96px: [완료][준수율][지식][재사용][상태 도넛]                  ┤
├ 경고 줄(있을 때만 32px, 한 줄 가로 스크롤) ─────────────────────────────┤
├ 본문(남은 높이 전부) ───────────────────────────────┬─────────────────┤
│ 내 할 일  [필터 세그먼트]        [↻][📅][+] 아이콘   │ 상세(320px)      │
│ ☐ 업무 ⇅            모듈 요청부서 기한 ⇅ 상태        │ (내부 스크롤)    │
│ … 행 40px × 남은 높이만큼                            │                 │
│ ─────────────────────────────────────────────────── │ ─────────────── │
│ 1–14 / 163건                     ‹ 1 2 … 12 ›       │ [주요 버튼 고정] │
└─────────────────────────────────────────────────────┴─────────────────┘
```

```css
@media (min-width:1025px) and (min-height:700px){
  body[data-page="dashboard"]{height:100dvh;overflow:hidden;display:flex;flex-direction:column}
  body[data-page="dashboard"] main{flex:1;min-height:0;display:flex;flex-direction:column;gap:10px;max-width:none;padding:10px 12px 12px}
  body[data-page="dashboard"] .grid2{flex:1;min-height:0;grid-template-columns:minmax(0,1fr) 320px;align-items:stretch}
}
```

- 데모 배너는 테스트가 "데모 모드" 글자를 확인하므로 남긴다. 높이만 24px로 줄인다.
- `main`의 `max-width:1440px` 제한은 대시보드에서만 풀어 미리보기처럼 화면 폭을 다 쓴다(1920px 이상에서는 상세 360px).

### 3-2. 제목·기간 줄, 지표 설명, 표로 보기 (L2, C3)

- `.mhead`를 한 줄로 만든다: 왼쪽 `h2`(18px) + 수집 상태(`#sync-status`, 12px, 말줄임), 오른쪽 `#seg`. 수집 경로·보관 안내 문구는 `title` 속성(마우스 올리면 보임)으로 옮긴다.
- `.mnote`(`#m-desc`, `#toggle-table`)는 KPI 줄 아래가 아니라 제목 줄의 기간 버튼 왼쪽에 'ⓘ 기준 · 표로 보기' 작은 링크로 둔다. `#m-desc` 문장은 `title`과 표 모달 머리말에 넣는다.
- `#m-tbl`(표로 보기)은 화면 안에 펼치지 말고 기존 모달 틀(`.dim` + `.modal.wide`)로 연다. id는 유지한다.

### 3-3. KPI 줄과 도표 (L3, L4, C1, C2)

```text
┌ ✓ 완료 건수          [참고] ┐   카드 높이 88–96px
│ 0건   ▁▂▁▃▅ (작은 그래프)  │   그래프: 값 오른쪽, 120×28px
│ 직전 대비 +0건 · 개선       │
└────────────────────────────┘
```

- `.kpi-row`를 `grid-template-columns: repeat(4, minmax(0,1fr)) minmax(240px,1.2fr)`의 한 그리드로 바꾼다. `#mk`는 `display:contents`로 두어 `#mk .kpi` 4개 조건(기존 테스트)을 지키면서 같은 그리드에 들어가게 한다.
- KPI 안 구성: ① 아이콘+이름(+참고 배지 오른쪽 끝) ② 값 + 작은 그래프(같은 줄) ③ 직전 대비 1줄.
  - 날짜 축(`.chart-range`)과 정의 문구(`.kdef`)는 화면에서 빼고 카드 `title`과 그래프 툴팁에 넣는다. 지표 정의는 사라지면 안 되므로 툴팁 첫 줄에 둔다.
- 그래프 표본이 모두 0이면 평평한 선 대신 회색 글자 "데이터 없음"을 표시한다. 툴팁·표로 보기는 그대로 둔다.
- 1280px 이하: 5칸 → `repeat(5, minmax(150px,1fr))` 가로 스크롤(한 줄 유지). 720px 이하: 2열 카드(문서형).
- 상태 도넛(`#status-donut`):
  - 범례에 대기·제안됨·진행 중·완료 후보·보류·완료 6개를 항상 표시한다(0건은 `--muted`).
  - 범례 항목을 누르면 내 할 일 필터를 그 상태로 바꾼다. `#filters` 버튼과 같은 상태값을 쓰고, 대기·보류처럼 필터 버튼이 없는 상태는 '전체'로 둔다.
  - 도넛 지름 64px, 가운데 총 건수, 범례 2열.

### 3-4. 내 할 일 패널 (L5, L6, L7, F8)

- `.todo-card`: `display:flex; flex-direction:column; min-height:0; padding:0`.
  - 머리(`.card-head`): 제목 + 필터 세그먼트 + 오른쪽 아이콘 버튼 3개(`#btn-collect`, `#btn-range-toggle`, `#btn-manual`).
  - 아이콘 버튼은 id 유지, `aria-label`·`title`에 기존 문구를 넣는다. 기간 지정 폼(`#range-form`)은 버튼 아래로 떠서 열리는 작은 팝오버로 둔다.
- `#todo-wrap`: `flex:1; min-height:0; overflow:hidden`. 머리행은 이 영역 안에서 고정한다(지금의 `top: nav + 62px` 계산 제거).
- `.pg`: 패널 바닥에 고정(`border-top:1px solid var(--line); padding:8px 14px`).
- 표 열 너비(`table-layout:fixed`): 체크 32px · 업무 자동 · 모듈 72px · 요청 부서 112px · 기한 88px · 상태 92px. 제목은 한 줄 말줄임 + `title`.
- 페이지 크기 계산(`todo_list.js`의 `computePerPage` 교체):

```js
// 목록 영역의 실제 높이 기준(앱 셸). 문서형(좁은 화면)에서는 기존 창 높이 기준을 유지한다.
function computePerPage(wrap, tbody) {
  const head = wrap.querySelector("thead");
  const first = tbody.querySelector("tr.row");
  const rowH = first ? first.getBoundingClientRect().height : DEFAULT_ROW_HEIGHT;
  const room = wrap.clientHeight - (head ? head.getBoundingClientRect().height : 0);
  return Math.max(3, Math.floor(room / rowH));
}
```

- 다시 계산하는 시점: `window.resize` 대신 `ResizeObserver`로 `#todo-wrap`을 관찰한다(경고 줄이 생기거나 사라질 때도 반영). 보던 첫 항목을 유지하는 로직은 그대로 둔다.

```text
│ 제목 15px (2줄 말줄임)          │
│ ┌ 요청 부서 │ IT운영팀 ┐        │  키-값 표: 요청 부서·기한·수신·근거·지식 등록
│ └ …                   ┘        │
│ [✉ 원본 보기] [🔍 유사 이력]     │  누르면 아래에 결과 영역이 생김(빈 회색 상자 미리 두지 않음)
│ (결과 영역: 원본 / 3단계 이력)   │
│ ──────────── 내부 스크롤 ────── │
│ [ 주요 버튼(전체 폭) ] [보조]    │  패널 바닥 고정
│ 보관 D-n 안내(있을 때)          │
└────────────────────────────────┘
```

- `#detail`: `display:flex; flex-direction:column; overflow:hidden; position:static`(앱 셸에서는 sticky 불필요). 본문 래퍼 `.d-body{flex:1;overflow:auto}`, 바닥 `.d-foot{border-top;padding}`.
- 섹션 제목('원본 메일 참조', '유사 이력 …')은 버튼 이름으로 대신하고 화면에서 뺀다. 원본 메일 참조가 여러 개면 첫 번째만 버튼, 나머지는 '원본 n건' 펼침.
- 빈 회색 상자(`mailBox` 기본 안내)는 처음에 그리지 않는다. 버튼을 누르면 그때 결과 영역을 만든다.
- 바닥 고정 버튼(상태별):

| 상태 | 주요 버튼 | 보조 버튼 |
|---|---|---|
| 제안됨 | 승인(`POST /api/tasks/{id}/approve`) | 무시(`/dismiss`) |
| 대기·보류 | 진행 시작(`/status` in_progress) | 완료 확정 · 보류 |
| 진행 중·완료 후보 | 완료 확정 | 보류 |
| 완료 | G-Knowledge 지식 등록 | 히스토리 카드 |
| 공통 | — | AI 지식 요청(본문 버튼 줄로 이동) |

- 업무를 선택하지 않았을 때: 아이콘 + "업무를 선택하세요" + 키보드 안내(↑↓ 선택, Enter 열기).

### 3-6. 좁은 화면 상세 서랍 (L9, F7)

- 1100px 이하에서 `#detail`은 오른쪽 서랍이 된다: `position:fixed; top:0; right:0; bottom:0; width:min(400px,92vw)`, 기본 `transform:translateX(104%)`, 열림 클래스 `.det-open`.
- 서랍 뒤에 흐린 배경(`.scrim`) 요소를 두고, 누르면 닫는다. 서랍 첫 줄에 ✕ 닫기 버튼, Esc로도 닫는다.
- 접근성: 열리면 `role="dialog"`·`aria-modal="true"`를 붙이고 포커스를 ✕로 옮긴다. Tab은 서랍 안에서만 돌게 하고, 닫으면 선택한 행으로 포커스를 돌려준다.
- 720px 이하에서는 하단 탭바 위로 서랍을 띄운다(바텀시트 아님, 오른쪽 서랍 유지).
- 템플릿 인라인 스타일은 금지라, 위치·변형은 모두 CSS 클래스로 처리한다.

## 4. 조작 기능 명세

### 4-1. 다중 선택·일괄 작업 (F1, L10)

- 표 첫 열에 체크박스를 둔다(`<input type="checkbox">`, 라벨은 업무 제목). 머리칸 체크박스는 현재 페이지 전체 선택이며, 일부만 선택됐으면 `indeterminate` 상태로 표시한다.
- 선택 상태(`Set<id>`)는 메모리에만 둔다. 필터·검색이 바뀌어도 유지하고, 목록에서 사라진 id는 정리한다.
- 1건 이상 선택하면 목록 패널 바닥 위에 일괄 작업 바를 띄운다: "n건 선택 · [진행 시작] [완료 후보로] [보류] [선택 해제]".
  - 제안됨이 포함되면 [승인] [무시]도 함께 보인다.
- 처리 방식:
  - 건별로 기존 API(`/status`, `/approve`, `/dismiss`)를 차례로 호출한다. 동시 호출 수는 3 이하로 둔다(rate limit 고려).
  - 서버가 거부한 건(허용되지 않는 상태 변경)은 건너뛰고, 끝나면 "성공 n · 실패 m(허용되지 않는 변경)" 토스트를 띄운다.
  - 화면에서 전이 규칙을 따로 판단하지 않는다(도메인 규칙 중복 금지).
- [무시]는 되돌릴 수 없으므로 확인 모달을 거친다.

### 4-2. 상단 검색 바로 거르기 (F2)

- 대시보드에서 `#search-form input`에 입력하면 150ms 뒤 내 할 일을 제목·요청 부서·모듈로 거른다(화면 안에서만, 서버 호출 없음). 이때 페이지는 1로 돌아간다.
- Enter는 기존대로 `/history?q=` 검색으로 이동한다. 입력칸 아래 안내 줄: "Enter: 히스토리에서 찾기 · Esc: 지우기".
- 결과가 없으면 목록에 "검색 결과가 없습니다 · Esc로 지우기"를 보여준다.
- 다른 화면에서는 지금처럼 동작한다(Ctrl+K 이동 + Enter 검색).

### 4-3. 키보드 (F4)

| 키 | 동작 | 조건 |
|---|---|---|
| ↑ / ↓ | 이전·다음 행 선택(상세 갱신). 첫·마지막 행에서는 이전·다음 페이지로 넘어가 끝 행 선택 | 입력칸·모달 밖 |
| ← / → | 이전·다음 페이지 | 입력칸·모달 밖 |
| Enter | 1100px 이하에서 상세 서랍 열기 | 행 선택 상태 |
| Esc | 서랍 닫기 → 검색어 지우기 순 | — |
| Space | 선택 행 체크 토글 | 입력칸 밖 |

- 행은 `tabindex="-1"`로 두고 선택 시 포커스를 옮긴다. 선택 행에는 `aria-selected="true"`를 붙인다.
- 지금 `#todo-wrap`에만 걸려 있는 ←→ 처리는 대시보드 전체 처리로 합친다.

### 4-4. 상태 변경과 되돌리기 (F5)

- 상태 변경 성공 시 토스트: "'{제목}' → {상태}" + [되돌리기].
- 되돌리기는 이전 상태로 `/status`를 호출한다. 서버가 거부하면 "되돌릴 수 없는 변경입니다" 토스트를 띄운다.
- 승인(제안됨 → 대기)과 무시는 되돌리기 버튼을 보이지 않는다(되돌리는 전이가 허용되지 않음).

### 4-5. 토스트 확장 (F6)

```js
// 기존 호출 toast("문구")는 그대로 동작해야 한다(하위 호환).
toast(message, { kind: "ok" | "warn" | "error", action: "되돌리기", onAction: () => {...}, ms: 2600 })
```

- 구성: 아이콘(ok=check, warn=alert-triangle, error=x-circle) + 문구 + (있으면) 행동 버튼 + 하단 진행 막대.
- 행동 버튼이 있으면 표시 시간 5초, 마우스를 올리면 멈춤.
- 모든 요소는 `el()`로 만든다(`innerHTML` 금지). 토스트 상자는 `role="status"`를 유지하고, 행동 버튼은 Tab으로 갈 수 있어야 한다.

## 8. 확인이 필요한 사항

1. **KPI 그래프 크기:** dev/12는 '추이 그래프'를 요구한다. 미리보기처럼 아예 빼지 않고 작게(28px) 유지하는 안으로 썼다. 빼려면 기획 변경 결정이 필요하다.
2. **일괄 작업 범위:** 1차 명세에서 3차(선택)로 미룬 기능을 이번에 넣는다. 상태를 바꾸는 기능이므로 사용 여부를 확인한다.
3. **상단 검색 동작:** 대시보드에서만 바로 거르기, Enter는 히스토리로 가는 두 동작을 함께 두었다. 히스토리 검색 요구사항(SRCH)과 충돌하지 않는지 확인한다.
