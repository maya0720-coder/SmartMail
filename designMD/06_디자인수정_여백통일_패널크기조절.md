## 1. 현재 상태 (데모 모드 실행 후 측정)

### 1-1. 탭별 여백 (1440×900)

| 항목 | 대시보드 | 제안된 업무 | 주간보고·히스토리·설정 |
|---|---|---|---|
| `main` 안쪽 여백(위 / 좌우 / 아래) | **8 / 12 / 12** | 18 / 12 / 40 | 18 / 12 / 40 |
| 메뉴 바 아래 ~ 제목까지 | **8px** | 18px | 18px |
| 제목(h2) 크기 | **18px** | 20px | 20px |
| 제목 영역 높이 | 32px (제목+상태 한 줄) | **112px** (세 줄로 접힘) | 51px (제목 + 설명) |
| 제목 영역 ~ 첫 카드 | 6px | 10px | **16px** |
| 카드 사이 간격 | 8~10px(세로), 12px(가로) | 10px(세로), 12px(가로) | 16px |
| 화면 높이 사용 | 화면에 고정(스크롤 없음) | 문서형(내용만큼) | 문서형 |
| 카드 안쪽 여백 | 목록 0 / 상세 14 | 목록 0 / 상세 14 | 14 |

### 1-2. 넓은 화면에서의 폭 (1920×1080)

| 항목 | 대시보드 | 그 밖의 탭 |
|---|---|---|
| 본문 폭 | **1896px**(화면 전체) | **1416px**(가운데 정렬, 최대 1440px) |
| 본문 왼쪽 시작 위치 | 12px | **252px** |
| 메뉴 바 | 12px부터 1896px 폭 | 같음 |

→ 탭을 바꾸면 본문이 좌우로 240px씩 움직이고, 메뉴 바와 본문의 왼쪽 선이 맞지 않는다. 사용자가 느끼는 '여백 차이'의 가장 큰 원인이다.

### 1-3. 제안된 업무 제목 영역이 세 줄로 접히는 이유

- `triage.css` 70행 `#tr-tabs{flex-basis:100%}` 때문에 탭이 한 줄을 통째로 차지한다.
- 그 아래에 단축키 안내와 '빠른 정리' 버튼이 또 한 줄을 쓴다.
- 결과: 대시보드는 제목 영역이 32px인데 제안된 업무는 112px이다.

### 1-4. 패널 폭을 강제로 바꿔 본 결과 (지금은 조절 기능 없음)

| 화면 | 폭 | 결과 |
|---|---|---|
| 대시보드 상세 | 240px | 넘침 없음. 다만 '근거' 값이 두 줄로 꺾이고 버튼 3개가 두 줄이 됨 |
| 대시보드 상세 | 640px | 넘침 없음. 키-값 표와 버튼이 왼쪽에만 몰려 오른쪽이 빔 |
| 대시보드 상세 | 800px | 목록의 업무 열이 198px로 줄어 제목이 말줄임(…) 처리됨 |
| 제안 목록 | 240px | 제목 말줄임 발생, 받은 시각이 다음 줄로 밀려 행 높이가 늘어남 |
| 제안 목록 | 700px | 넘침 없음. 상세의 필드 4칸이 좁아짐(상세 폭 704px) |

- 가로로 넘쳐 잘리는 요소는 측정 범위(240~800px)에서 발견되지 않았다.
- 문제는 '잘림'보다 **말줄임, 줄 꺾임, 빈 공간**이다. 4장의 폭 구간별 규칙으로 해결한다.

## 2. 여백 통일 규칙

### 2-1. 간격 토큰 (`app.css` `:root`에 추가)

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--page-x` | 16px | 메뉴 바와 본문의 좌우 여백(같은 값) |
| `--page-top` | 14px | 메뉴 바 아래 ~ 제목 영역 |
| `--page-bottom` | 16px | 본문 아래 여백(문서형 화면은 24px) |
| `--head-h` | 36px | 제목 영역 최소 높이 |
| `--head-gap` | 12px | 제목 영역 ~ 첫 카드 |
| `--gap` | 12px | 카드와 카드 사이(가로·세로 모두) |
| `--card-pad` | 14px | 카드 안쪽 여백 |
| `--page-max` | 1680px | 본문 최대 폭 |

- 720px 이하에서는 `--page-x: 8px`, `--page-top: 10px`로 줄인다.
- 숫자를 직접 쓴 여백(`margin-bottom:6px`, `mt16`, `mb16` 등)은 토큰으로 바꾼다.

### 2-2. 공통 골격

모든 탭이 같은 틀을 쓴다. `base.html`에 제목 영역 블록을 만든다.

```text
┌ 메뉴 바 (좌우 --page-x) ────────────────────────────────────────────┐
│ ↕ --page-top                                                        │
│ ┌ .page-head (최소 높이 --head-h) ─────────────────────────────────┐ │
│ │ 제목(h2 20px) · 보조 설명(한 줄, 말줄임)        오른쪽 도구 영역  │ │
│ └──────────────────────────────────────────────────────────────────┘ │
│ ↕ --head-gap                                                        │
│ ┌ .page-body (카드 사이 --gap) ────────────────────────────────────┐ │
│ └──────────────────────────────────────────────────────────────────┘ │
│ ↕ --page-bottom                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

| 규칙 | 내용 |
|---|---|
| 본문 폭 | 모든 탭 `max-width: var(--page-max)`, 가운데 정렬. 대시보드의 `max-width:none` 예외를 없앤다 |
| 메뉴 바 폭 | 본문과 같은 `--page-max`와 `--page-x`를 써서 왼쪽·오른쪽 선을 맞춘다 |
| 제목 | 모든 탭 h2 20px, 굵기 700. 대시보드의 18px 예외를 없앤다 |
| 보조 설명 | 제목 오른쪽 같은 줄에 12.5px 회색으로. 길면 말줄임 + `title`. 주간보고·히스토리·설정의 설명 문단(`.desc`)을 이 자리로 옮긴다 |
| 오른쪽 도구 | 대시보드: 기간 버튼 / 제안된 업무: 탭·빠른 정리 / 주간보고: 단계 표시 / 히스토리·설정: 없음 |
| 카드 간격 | 전부 `--gap`. `mt16`·`mb16` 사용 중단 |

### 2-3. 화면별 적용

| 화면 | 바꿀 것 |
|---|---|
| 대시보드 | `main` 여백 `8/12/12` → 토큰. h2 20px. 본문 최대 폭 적용. `.kpi-row`·`.sugg-banner`·`#alerts` 아래 간격을 `--gap`으로 |
| 제안된 업무 | 제목 영역을 한 줄로: `[제목 · 정리할 제안 n건 · 진행 막대 · 나중에 n건] …… [탭] [빠른 정리]`. `#tr-tabs{flex-basis:100%}` 삭제. 단축키 안내는 제목 줄에서 빼고 상세 패널 아래 행동 줄 오른쪽으로 옮긴다. 1100px 이하에서만 탭이 둘째 줄로 내려간다 |
| 제안된 업무 | 대시보드처럼 **화면 고정형**으로 바꾼다(1025px 이상·높이 700px 이상). 목록과 상세가 화면 아래까지 차고, 각자 안에서 스크롤한다. 요약 상태 막대(`.sum-bar`)는 높이 36px 한 줄 |
| 주간보고 | 설명 문단을 제목 줄로. 카드 사이 `--gap`. 편집 3열 사이도 `--gap` |
| 히스토리 | 설명 문단을 제목 줄로. 검색 카드와 카드 목록 사이 `--gap` |
| 설정·연결 | 설명 문단을 제목 줄로. 설정 카드는 읽기 편하게 최대 폭 960px, **왼쪽 정렬**(본문 왼쪽 선에 맞춤) |
| 데모 배너 | 모든 탭 같은 높이(24px) |

## 3. 패널 크기 조절

### 3-1. 동작

| 항목 | 대시보드(오른쪽 상세) | 제안된 업무(왼쪽 목록) |
|---|---|---|
| 손잡이 위치 | 목록과 상세 사이 간격(12px) 전체 | 목록과 상세 사이 간격(12px) 전체 |
| 기본 폭 | 320px (1920px 이상 360px) | 380px |
| 최소 폭 | 280px | 280px |
| 최대 폭 | 640px, 그리고 **목록이 520px 아래로 줄지 않는 범위** | 560px, 그리고 **상세가 520px 아래로 줄지 않는 범위** |
| 끌기 | 좌우로 끌면 실시간으로 폭이 바뀜 | 같음 |
| 더블클릭 | 기본 폭으로 되돌림 | 같음 |
| 키보드 | 손잡이에 포커스 후 ←→ 16px씩, Shift+←→ 64px씩, Home 최소, End 최대, Enter 기본 폭 | 같음 |
| 좁은 화면 | 1100px 이하(서랍 방식)에서는 손잡이 숨김 | 900px 이하에서는 손잡이 숨김 |
| 창 크기 변경 | 저장된 폭이 새 최대값보다 크면 최대값으로 자동 축소 | 같음 |

### 3-2. 구현 방식

| 항목 | 명세 |
|---|---|
| 폭 변수 | 대시보드는 기존 `--detail-w`를 그대로 쓴다. 제안된 업무는 `--tr-list-w`를 새로 만들고 `.triage{grid-template-columns: var(--tr-list-w) 12px minmax(0,1fr)}`로 바꾼다. 대시보드도 `minmax(0,1fr) 12px var(--detail-w)`(가운데 12px이 손잡이 칸, `gap:0`) |
| 손잡이 요소 | `<div class="splitter" role="separator" aria-orientation="vertical" tabindex="0" aria-label="패널 크기 조절" aria-controls="…" aria-valuemin aria-valuemax aria-valuenow>` |
| 손잡이 모양 | 평소 투명. 마우스를 올리거나 포커스하면 가운데 2px 세로선(강조색) + 점 3개 손잡이. 커서 `col-resize`. 터치용 실제 잡는 영역은 12px 전체 |
| 끌기 처리 | Pointer Events(`pointerdown` → `setPointerCapture` → `pointermove` → `pointerup`). 이동 중 계산은 `requestAnimationFrame`으로 묶는다 |
| 값 적용 | `element.style.setProperty("--detail-w", px)`. 스크립트로 넣는 값이라 CSP(`style-src 'self'`)에 걸리지 않는다. 템플릿에 `style=` 속성은 쓰지 않는다 |
| 끄는 동안 | `body`에 `.resizing` 클래스 → 글자 선택 방지(`user-select:none`), 전체 커서 `col-resize`, 패널의 전환 효과 끔 |
| 공용 모듈 | `static/js/splitter.js` 신규. `initSplitter({handle, target, cssVar, side, min, max, otherMin, defaultWidth, onChange})`. 두 화면이 같이 쓴다 |
| 방향 | 대시보드는 손잡이를 왼쪽으로 끌면 상세가 커지고(`side:"right"`), 제안된 업무는 오른쪽으로 끌면 목록이 커진다(`side:"left"`) |

### 3-3. 조절한 폭 기억하기

| 항목 | 내용 |
|---|---|
| 제약 | 브라우저 저장소(`localStorage` 등)는 테스트로 금지돼 있다(`test_scripts_do_not_use_unsafe_sinks_or_storage`) |
| 방식 | 기존 `app_settings`(위키 제목 규칙·업무 구분을 저장하는 로컬 DB 설정)에 숫자 2개를 저장한다 |
| API | `GET /api/ui-prefs` → `{"detail_w": 320, "triage_list_w": 380}` / `PUT /api/ui-prefs`(CSRF 필요) |
| 검증 | 정수만 허용, 200~800 범위 밖이면 400. 허용 키 2개 외에는 거부 |
| 저장 시점 | 끌기를 끝냈을 때(`pointerup`)와 키보드 조절 후 400ms 뒤 한 번만 |
| 처음 그릴 때 | 서버가 템플릿을 그릴 때 `<body data-detail-w="…" data-tr-list-w="…">`로 내려주고, `common.js`가 첫 줄에서 CSS 변수로 옮긴다(화면이 한 번 튀는 것 방지) |
| 초기화 | 설정·연결에 "화면 배치 초기화" 행 추가. '로컬 데이터 전체 삭제'에도 포함 |
| 개인정보 | 화면 폭 숫자만 저장한다. 개인정보·업무 내용 없음 |

## 4. 폭에 맞춰 내용 다시 배치하기 (잘림 방지)

화면 전체 폭이 아니라 **패널 자신의 폭**을 기준으로 배치를 바꾼다. CSS 컨테이너 쿼리를 쓴다(`container-type:inline-size`). 사내 표준 브라우저(Edge·Chrome 최신)에서 동작한다.

### 4-1. 공통 원칙

| 원칙 | 내용 |
|---|---|
| 가로 스크롤 금지 | 어떤 폭에서도 패널 안에 가로 스크롤이 생기지 않는다 |
| 값은 줄바꿈, 이름표는 고정 | 키-값 표의 값은 `overflow-wrap:anywhere`로 줄바꿈. 이름표 칸은 줄지 않는다 |
| 제목은 2줄까지 | 업무 제목은 2줄까지 보여주고 넘으면 말줄임 + `title`(전체 제목) |
| 버튼은 줄바꿈 | 버튼 줄은 `flex-wrap:wrap`. 좁으면 전체 폭 버튼으로 쌓인다. 글자가 버튼 밖으로 나가지 않는다 |
| 최소 폭 보장 | 3-1의 최소 폭(280px)과 상대 패널 최소 폭(520px)으로 깨지는 구간 자체를 막는다 |
| 부드러운 전환 | 끄는 동안에는 전환 효과를 끄고, 놓은 뒤 배치가 바뀔 때만 0.2초 전환 |

### 4-2. 대시보드 상세 패널(`#detail`, 280~640px)

| 패널 폭 | 배치 |
|---|---|
| 280~339px (좁음) | 키-값 표 이름표 칸 64px. 버튼(원본 보기·유사 이력·AI 지식 요청)은 한 줄에 하나씩 전체 폭. 아래 고정 버튼은 세로로 쌓음 |
| 340~479px (보통) | 현재 배치(이름표 72px, 버튼 한 줄에 2~3개, 아래 고정 버튼 세로) |
| 480~640px (넓음) | 키-값 표를 2열로(요청 부서·기한 / 수신·지식 등록, '근거'는 두 칸 차지). 아래 고정 버튼은 가로 한 줄(주 버튼이 넓게). 원본 메일 본문 최대 높이 240 → 360px |

### 4-3. 대시보드 목록(`.todo-card`, 상세가 커지면 줄어듦)

| 목록 폭 | 배치 |
|---|---|
| 900px 이상 | 현재 열 전부: 선택 · 업무 · 구분 · 요청 부서 · 기한 · 상태 |
| 700~899px | '요청 부서' 열 숨김(업무 제목 아래 작은 글씨로 내려 표시) |
| 520~699px | '구분' 열도 숨김(제목 옆 작은 칩으로). 필터는 가로 스크롤 한 줄, 아이콘 버튼 3개는 유지 |

- 숨긴 정보는 없애지 않고 제목 아래 보조 줄로 옮긴다. 이때 행 높이가 40 → 52px로 바뀌므로 페이지 행 수를 다시 계산한다.
- `#todo-wrap`을 `ResizeObserver`로 관찰해 폭·높이가 바뀌면 한 페이지 행 수를 다시 계산한다(현재 로직 재사용, 보던 첫 항목 유지).
- KPI 줄은 패널 폭과 무관하므로 그대로 둔다.

### 4-4. 제안 목록(`.tr-list`, 280~560px)

| 목록 폭 | 배치 |
|---|---|
| 280~339px (좁음) | 제목 2줄까지. 둘째 줄: 구분 칩 + 기한 칩만. 요청 부서·대화 수는 숨기고, 받은 시각은 날짜만(`11/12`). 확신도 막대는 제목 오른쪽 유지 |
| 340~459px (보통) | 현재 배치(제목 1줄, 칩 줄에 부서·대화 수·받은 시각) |
| 460~560px (넓음) | 한 줄 배치: 제목 · 구분 · 기한 · 부서 · 받은 시각 · 확신도. 행 높이 62 → 44px로 줄어 더 많이 보임 |

- 받은 시각이 다음 줄로 밀려 행 높이가 들쭉날쭉해지는 문제(1-4)를 없앤다: 받은 시각 칸은 줄바꿈 금지 + 좁으면 날짜만 표시.

### 4-5. 제안 상세(`.tr-detail`, 목록이 커지면 줄어듦)

| 상세 폭 | 배치 |
|---|---|
| 900px 이상 | 필드 4칸 한 줄(현재) |
| 640~899px | 필드 2×2 |
| 520~639px | 필드 1열. 행동 버튼은 줄바꿈 허용, 단축키 안내 숨김 |

- 지금은 화면 폭 기준(`@media (max-width:1280px)`)으로 필드 칸 수를 정한다. 이를 **상세 패널 폭 기준**으로 바꾼다(목록을 넓히면 화면은 넓어도 상세는 좁아지기 때문).
- 요청 문장 상자는 폭에 맞춰 줄바꿈하고, 하이라이트(`<mark>`)가 줄 끝에서 잘리지 않게 `box-decoration-break:clone`을 준다.
