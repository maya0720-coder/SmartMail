# 13. 통합 검증 · 로컬 실행 패키지

메인 문서: `dev/00_MAIN_개발진행.md` · 다음 단계: 없음(완료 후 사용자 보고)

## 목표

전체 흐름을 합성 데이터로 끝까지 검증하고, 사용자 PC에서 한 번에 실행할 수 있는 로컬 테스트 버전을 만든다.

## 작업

1. 통합 시나리오(Fake 어댑터): 메일 수집 → 업무 제안·승인 → 회신 감지·완료 → 히스토리 카드 → G-Knowledge 등록 → 7일 경과 삭제 → G-Knowledge 조회 → (없으면) AI 제안 → 주간보고 초안·승인·게시 → 성과 지표 반영.
2. 보안 점검: 정적 분석(ruff 보안 규칙 등), 의존성 취약점 검사, 시크릿 탐지, 자격증명 잔존 검사(AUTH-10), 로그 민감정보 검사, 127.0.0.1 바인딩 확인.
3. `docs/요구사항추적표.md` 최종 갱신: 요구사항 ID별 구현 위치·테스트·상태(완료/보류(확인 필요)).
4. 실행 패키지: `scripts/run.ps1`(가상환경 생성·의존성 설치·서버 실행), `docs/로컬실행가이드.md`(한글), `.env.example` 작성 안내.
5. 수동 점검 체크리스트(`docs/수동점검.md`): 실제 아웃룩 1주 수집, 로그인 창 4개 사이트, G-Knowledge 테스트 등록 1건, 위키 미리보기(게시는 승인 후).
6. 웹 배포 전환 메모(`docs/결정기록/`): PC 아웃룩은 서버에서 읽을 수 없으므로 수집 방식 재설계 필요, SSO·권한·지표 원장 보관 기간·개인정보 검토 항목.

## 검증

- 전체 테스트·린트·타입·시크릿 탐지 통과 결과 첨부
- 실행하지 못한 검증(실제 사이트 연동 등)과 이유를 최종 보고에 명시
