# 00. 메인 개발 진행 문서

이 문서는 개발 전체의 진입점이다. Claude Code는 아래 순서대로 단계 파일을 **하나씩** 읽고 실행한다. 한 단계의 완료 기준(게이트)을 통과하기 전에는 다음 단계로 넘어가지 않는다.

- 기준 문서: `CLAUDE.md`(개발 지침), `docs/기획서_v1.0.md`(요구사항), `docs/샘플화면_v1.0.html`(화면)
- 대상: 로컬 테스트 버전(사용자 PC, 127.0.0.1). 최종 목표는 IE팀 운영의 사내 웹 배포
- 모든 설명·보고·md는 한글로 작성한다.

## 1. 실행 규칙

1. 이 문서의 「2. 진행 현황」 표에서 **상태가 `대기`인 첫 번째 단계**를 찾는다.
2. 해당 단계 파일을 처음부터 끝까지 읽는다. 「선행 조건」이 충족되지 않았으면 멈추고 보고한다.
3. 단계 파일의 「작업」을 수행한다. 파일은 `CLAUDE.md` 0-1장의 하네스 폴더 구조에 맞는 위치에만 만든다.
4. 단계 파일의 「검증」을 모두 실행한다(포맷·린트·타입·테스트·시크릿 탐지). 실패하면 고치고 다시 실행한다.
5. 「완료 기준」을 모두 만족하면 아래 표의 상태를 `완료`로, 완료일과 메모를 갱신하고 `docs/요구사항추적표.md`를 갱신한다.
6. 단계 보고를 한글로 남긴다(형식은 「4. 단계 보고 형식」). 사용자가 "계속"이라고 하면 다음 단계로 간다. 사용자가 "끝까지 진행"이라고 했으면 확인 없이 다음 단계를 이어서 진행하되, `확인 필요` 항목을 만나면 멈춘다.
7. 단계 진행 중 기획서와 다르게 판단해야 하면 `docs/결정기록/`에 기록하고 사용자 확인을 받는다.
8. 외부 시스템 정보(URL, API 규격, 화면 필드)가 `확인 필요`인 부분은 **추측해서 구현하지 않는다.** 인터페이스와 가짜(Fake) 어댑터로 진행하고, 실제 연동 자리는 설정값 placeholder와 `확인 필요` 표시로 남긴다.

## 3. 단계 간 공통 규칙

- **선행 의존성:** 각 단계는 앞 단계의 인터페이스만 사용한다. 앞 단계 코드를 고쳐야 하면 그 이유를 보고서에 적는다.
- **요구사항 ID 연결:** 테스트 함수 이름이나 docstring, 커밋 메시지에 요구사항 ID를 넣는다(예: `test_auth03_password_not_written_to_disk`).
- **합성 데이터만:** 테스트·샘플에는 가상 이름(예: 홍길동, 김가상)과 가짜 메일만 쓴다. 실제 메일·계정을 쓰지 않는다.
- **자격증명:** 어떤 단계에서도 ID·암호를 파일·DB·로그·환경 변수·테스트 fixture에 남기지 않는다.
- **외부 전송:** 위키·G-Knowledge·AI-Ground로 가는 모든 데이터는 02단계의 마스킹 타입을 거친다.
- **커밋:** 단계마다 의미 있는 단위로 커밋하되, 원격 저장소 푸시·공개는 사용자 승인 없이 하지 않는다.

## 4. 단계 보고 형식

```text
[단계 NN 완료 보고]
- 구현 요약:
- 관련 요구사항 ID:
- 생성·수정 파일:
- 검증 결과: 포맷 / 린트 / 타입 / 테스트(통과 n, 실패 n) / 시크릿 탐지
- 미실행 검증과 이유:
- 확인 필요(외부 정보 대기):
- 개인정보·보안 주의점:
- 다음 단계:
```
