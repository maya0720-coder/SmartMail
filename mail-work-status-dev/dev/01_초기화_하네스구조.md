# 01. 초기화 · 하네스 구조

메인 문서: `dev/00_MAIN_개발진행.md` · 다음 단계: `dev/02_설정_보안기반.md`

## 목표

하네스 폴더 구조와 개발 도구를 갖춰, 이후 단계가 정해진 위치에 코드를 만들고 자동 검증을 받게 한다.

## 선행 조건

- 사용자 PC: Windows, Python 3.11 이상(설치 버전 확인 후 `docs/결정기록/`에 기록)
- 기술 스택은 `CLAUDE.md` 0-1장의 권장안. 바꿔야 하면 먼저 사용자 확인

## 작업

1. `CLAUDE.md` 0-1장의 폴더 구조를 만든다(`src/app`, `src/domain`, `src/collectors`, `src/integrations`, `src/security`, `src/storage`, `src/config`, `tests/unit`, `tests/integration`, `tests/security`, `tests/fixtures`, `scripts`, `docs/결정기록`).
2. `pyproject.toml`: 의존성 버전 고정(잠금 파일 생성), ruff·mypy·pytest 설정. 운영 의존성과 개발 의존성 분리.
   - 운영 후보: fastapi, uvicorn, jinja2, pywin32(Windows 전용 선택 설치), playwright, pydantic-settings
   - 개발 후보: pytest, ruff, mypy, 시크릿 탐지 도구(예: detect-secrets 또는 gitleaks)
   - 추가 전에 유지보수 상태·알려진 취약점 확인 결과를 보고서에 적는다.
3. `.gitignore`: `.env`, 로컬 DB, 로그, 브라우저 프로필·캐시, `__pycache__`, 빌드 산출물.
4. `.env.example`: 키 이름과 placeholder만(예: `WIKI_BASE_URL=<확인 필요>`). 실제 값·자격증명 키는 만들지 않는다(ID·암호는 환경 변수로도 받지 않는다).
5. `.claude/settings.json`: 위험 명령(원격 push, 파일 대량 삭제) 확인 요구. `.claude/hooks/`: 편집 후 ruff format, 커밋 전 시크릿 탐지.
6. `.claude/agents/`: `보안검토.md`, `테스트작성.md`, `기획대조.md`(기획서 요구사항 ID와 구현 대조) 서브에이전트 정의.
7. `.claude/commands/`: `점검.md`(포맷·린트·타입·테스트·시크릿 탐지 일괄 실행), `다음단계.md`(00_MAIN 다음 대기 단계 실행).
8. `docs/요구사항추적표.md`가 없으면 생성(이 패키지에 포함된 템플릿 사용), `docs/변경이력.md` 생성.
9. `scripts/check.ps1`(또는 `.py`): 6번 점검 명령을 한 번에 실행.
10. AXHub AI 활용 기록: 설정 방법이 확인되면 적용하고, 아니면 `확인 필요`로 보고한다.

## 검증

- `ruff check`, `ruff format --check`, `mypy src`, `pytest`(빈 스모크 테스트 1개) 통과
- 시크릿 탐지 실행 결과 0건
- `git status`에 `.env`, DB, 로그가 추적되지 않음

## 완료 기준

- [ ] 훅·서브에이전트·명령 파일 생성
- [ ] 점검 스크립트 한 번으로 전체 검증 실행 가능
