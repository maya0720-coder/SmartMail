# 03. 저장소 · 보관기간 · 지표 원장

메인 문서: `dev/00_MAIN_개발진행.md` · 다음 단계: `dev/04_로그인창_세션관리.md`

## 목표

로컬 DB, 업무 이벤트 기록, 완료 7일 후 자동 삭제, 지표 원장을 만든다. 메일 원문은 저장하지 않는다.

## 관련 요구사항

MAIL-08(원문 미저장·참조 ID), RET-01·RET-04, 기획서 7장 데이터 모델, 4.9 지표 원장

## 작업

1. `src/storage/db.py`: SQLite, 매개변수화 쿼리 또는 ORM. DB 파일 위치는 설정값. 저장 시 암호화 적용 여부를 검토하고 결과를 `docs/결정기록/`에 남긴다.
2. 테이블(최소 항목만)
   - `mail_ref`: 메일 참조 ID(EntryID, Internet Message-ID), 스레드 ID, 수신 시각, 요약(사용자 확인분). 본문·첨부 저장 금지.
   - `task`: 업무 ID, 제목, 요청 부서, 기한, 상태(제안됨·대기·진행 중·완료 후보·완료·보류), 모듈 태그, 출처(메일/수동), 완료 시각, G-Knowledge 등록 여부·링크.
   - `task_event`: 업무 ID, 이벤트 종류(수신·제안·승인·수정·무시·회신·완료·GK등록·검색해결·초안생성·게시), 시각.
   - `history_card`: 업무 ID, 문제·원인·조치, T-code/프로그램, 태그, 공개 범위.
   - `metric_ledger`: 완료일, 담당자, 기한 유무·준수, 해결 단계, G-Knowledge 등록 여부. 제목·본문·상대방 정보 없음.
3. `src/storage/retention.py`: 완료 후 7일 지난 `task`·`mail_ref`·`history_card`·`task_event`를 복구 불가하게 삭제(SQLite는 삭제 후 VACUUM). 진행 중 업무는 제외. 삭제 건수만 로그.
   - `metric_ledger`는 설정 플래그가 false면 같은 규칙으로 삭제, true면 유지(기획서 결정 대기).
4. 앱 시작 시 1회 + 하루 1회 실행되는 보관기간 작업 등록.
5. 사용자 전체 삭제 기능(설정 화면에서 호출): 로컬 DB 전체 삭제 함수.

## 검증(필수 테스트)

- 완료 7일 경과 건만 삭제, 6일 23시간은 유지(경계값), 진행 중 업무는 유지
- 지표 원장 플래그 true/false 각각 동작
- 스키마에 본문·첨부·자격증명 컬럼이 없는지 검사하는 테스트
- 전체 삭제 후 DB에 업무 데이터 0건
