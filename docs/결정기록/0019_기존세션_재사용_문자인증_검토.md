# 0019 기존 로그인 세션 재사용 · 문자(SMS) 인증 우회 검토

- 날짜: 2026-11-13
- 상태: 검토 결과(코드 변경 없음). 아래 '권장'은 설정·운영으로 적용, '보류'는 사용자·정보보안 확인 대기
- 관련 요구사항: AUTH-02·03·05·06·09, AI-05, 기획서 8장(각 사이트 로그인 방식 미확인)

## 질문(사용자, 2026-11-13)

1. 기존에 로그인된 세션이 있으면 먼저 확인해 그 세션으로 연결할 수 없나?
2. 로그인이 안 되는 게 문자 인증(SMS OTP) 알림 때문 같은데, 이를 우회할 방법이 있나?

## 현재 동작(코드 확인)

- **같은 실행(앱 1회 구동) 안에서는 이미 세션을 재사용한다.**
  - `SessionStore`가 사이트별 세션을 메모리에 두고, `login_all.py`의 `pending_sites()`는 `sessions.current(site)`가 있으면 그 사이트를 건너뛴다(다시 로그인·입력 요구 없음).
  - 회사 계정(Entra ID) 사이트(AI-Ground·G-Knowledge)는 한 곳을 로그인하면 나머지는 SSO로 연결한다(`try_sso`). 즉 **회사 계정 2단계 인증은 실행당 1회만** 필요하다.
  - 회사 계정 로그인 창(`run_entra_login`)은 이미 로그인돼 있으면(완료 표시가 보이면) 입력 없이 끝나고, 계정 선택 타일(`account_tile`)도 눌러 기존 로그인을 잇는다.
- **앱을 껐다 켜면 세션은 사라진다(의도된 동작).** 세션은 메모리에만 있고(AUTH-05), 브라우저 자동화는 비저장(시크릿) 컨텍스트로만 돌며 종료 시 쿠키·캐시를 모두 지운다(AUTH-06, 결정기록 0017). 그래서 앱을 다시 켜면 다시 로그인(필요 시 2단계 인증)해야 한다.

## 2단계 인증 처리 범위

`login_fields.toml [entra]`가 다루는 2단계 인증 화면:
- `mfa_number`: Authenticator **번호 일치**(화면에 번호를 보여주고 앱에서 같은 번호 선택).
- `mfa_marker`: 승인 대기(푸시 승인).

문자(SMS)로 받은 **코드를 입력하는 화면**은 지금 흐름에 입력 단계가 없다. 그래서 테넌트가 SMS OTP를 요구하면 코드를 넣지 못하고 대기하다 시간 초과로 실패한다. 사용자가 겪는 "문자 인증 때문에 안 됨"이 이 경우로 보인다.

## 결정·권장

### 우회는 하지 않는다
문자 인증은 로그인을 지키는 보안 통제다. 이를 끄거나 건너뛰는 방식(통제 비활성화, 토큰을 디스크에 저장해 재인증 생략 등)은 보안·개인정보 수준을 낮추므로 하지 않는다(CLAUDE.md, AUTH-03·06). "우회" 대신 **인증을 정상적으로 완료**하거나 **재인증 빈도를 줄이는** 방향으로 해결한다.

### 지금 적용 가능(코드 변경 없음)
1. **회사 계정의 2단계 인증 방식을 Authenticator 푸시/번호 일치로 설정**하면 현재 흐름이 그대로 처리해, 문자 코드 입력 없이 로그인된다(사용자 측 계정 보안 설정).
2. **유휴 세션 시간(`SMARTMAIL_SESSION_IDLE_MINUTES`, 기본 30분, 최대 480분)을 늘리면** 근무 중 재로그인(=재인증) 횟수가 준다. 세션은 여전히 메모리에만 있고 앱을 끄면 사라진다. 유휴 폐기(AUTH-05)를 약화하는 쪽이라 값은 사용자가 정한다.

### 보류(확인 후 결정)
3. **SMS OTP 코드 입력 단계 추가**: 코드 입력칸·제출 버튼·오류 표시의 실제 Entra 화면 선택자가 '확인 필요'다(기획서 8장). 추측해 구현하지 않는다. 선택자를 확인하면, 코드를 **앱 화면에서 사용자가 직접 입력해 인증을 완료**하는 단계(우회가 아님)를 `login_flows.py`에 추가할 수 있다.
4. **앱 재시작 후 세션 유지(재인증 생략)**: 세션/토큰을 앱 종료 후에도 남기는 것은 AUTH-03·06(비저장)과 정면으로 어긋난다. 파일럿에서는 적용하지 않으며, 필요하면 기획서 개정 + 정보보안 담당자 승인이 선행돼야 한다.
5. **사용자의 평소 브라우저 세션에 붙기**: 앱은 화면 없는 비저장 브라우저에서만 로그인하므로 사용자의 일반 브라우저 로그인과 공유되지 않는다(결정기록 0017). 공유하려면 사용자 프로필을 재사용해야 하는데, 이는 AUTH-06 위반이라 하지 않는다.

## 요약

- "기존 세션 재사용"은 **한 번 실행하는 동안에는 이미 동작**한다(회사 계정은 1회 인증 후 SSO). 앱을 다시 켜면 보안상 의도적으로 다시 로그인한다.
- 문자 인증 **우회는 불가·부적절**. 대신 ① 인증 방식을 푸시/번호 일치로 바꾸거나 ② 유휴 시간을 늘려 재인증을 줄이는 것을 권장한다. SMS 코드 입력 단계는 실제 화면 선택자 확인 후 추가할 수 있다.
