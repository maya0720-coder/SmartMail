## 배경

02단계 구현 후 `보안검토` 서브에이전트가 높음 3건, 중간 6건, 낮음 7건을 보고했다. 아래와 같이 반영했다.

## 남은 한계(이후 단계에서 처리)

- **L-6 보안 응답 헤더(CSP 등)·`Server` 헤더:** 앱 구성 시(04단계 로그인 창, 12단계 화면) 적용한다.
- **uvicorn 실행 설정:** 13단계 `scripts/run.ps1`에서 `log_config=None`으로 실행해 루트 로깅 설정을 따르게 한다(레코드 팩토리 정화로 이미 보호되지만 출력 형식 일원화 목적).
- **마스킹이 놓칠 수 있는 형태:** 조사나 공백만으로 구분된 숫자 없는 비밀번호(예: '비밀번호는 abcdef'), 공백으로 나뉜 계좌번호(문맥 키워드가 없는 경우), `hong(at)example.com` 같은 우회 표기. 일반 문장을 과도하게 가리지 않으려고 둔 절충이다. 외부 전송 전 사용자 검토 화면(WIKI·GK 단계)에서 보완한다.
- **MaskedText 완전 봉쇄 불가:** Python 특성상 의도적인 우회(모듈 내부 객체 직접 사용)는 막을 수 없다. 금지 패턴 검사와 코드 리뷰로 통제한다.
- **루트 외 핸들러의 extra 속성:** 레코드 팩토리 단계에서는 extra가 아직 붙지 않으므로, 루트가 아닌 로거에 직접 붙은 핸들러에서는 extra 값이 제거되지 않는다. 코드에서 로그 `extra` 사용을 피한다.
