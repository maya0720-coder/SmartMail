# 0006. 웹 배포 전환 메모

- 날짜: 2026-11-11
- 단계: 13
- 상태: 검토 필요(웹 배포 착수 전 IE팀·정보보안·법무 확인)

로컬 테스트 버전을 사내 웹 배포(운영: IE팀)로 옮길 때 다시 설계하거나 확인해야 할 항목입니다.

## 1. 다시 설계해야 하는 부분

| 항목 | 로컬 버전 | 웹 배포 시 |
| --- | --- | --- |
| 메일 수집 | PC의 클래식 아웃룩 COM | 서버에서는 PC 아웃룩을 읽을 수 없습니다. Exchange/그룹웨어 서버 API를 쓰거나, 사용자 PC 에이전트가 참조 ID만 올리는 방식 중에서 골라야 합니다 |
| 인증 | 앱 자체 계정 없음(PC 사용자 = 사용자) | 사내 SSO. 사용자별 데이터 격리와 서버 측 권한 검사가 필요합니다 |
| 외부 사이트 로그인 | 로그인 창에 1회 입력, 메모리 세션 | 사용자별 세션 격리. 서비스 계정·위임 토큰(OAuth 등)을 쓸 수 있는지 확인 필요 |
| 브라우저 자동화(G-Knowledge) | 사용자 PC의 비저장 Chromium | 서버에서 사용자 대신 자동화하는 것을 허용할지 검토. 가능하면 공식 API로 전환 |
| CSRF·세션 | 프로세스 단위 토큰 1개 | 사용자 세션별 CSRF 토큰, HttpOnly·Secure·SameSite 쿠키 |
| DB | 로컬 SQLite, 암호화 없음(결정기록 0004) | 서버 DB의 저장 시 암호화와 키 관리, 백업에도 보관기간 적용 |
| 배포 | `scripts/run.ps1` | 컨테이너·서버 배포 파이프라인, 의존성 잠금 파일 해시 검증 유지 |

## 2. 권한 모델(기획서 5장)

- 일반 사용자는 본인 데이터만 다룹니다.
- 팀장은 공유 표시(`Task.shared`, TODO-08)된 업무만 봅니다.
- 관리자는 설정과 로그만 봅니다. 메일 본문은 열람할 수 없습니다.
- 개인별 성과 지표 화면은 본인만 봅니다. 팀·개인 간 비교 화면은 인사 평가에 쓸지 결정한 뒤 만듭니다.

## 3. 개인정보·보안 검토 항목

- **처리 근거:** 직원 메일 분석의 처리 근거와 동의 방식(법무·개인정보 담당)
- **보유 기간:** 앱 기록 7일, 지표 원장 장기 보관 여부(`SMARTMAIL_METRICS_LEDGER_KEEP`, 기획서 9장 미정)
- **외부 전송:** g-llm 전송 범위(마스킹 요약만, AI-02·03)와 AI-Ground의 보관·학습 정책
- **로그:** 감사 로그(위키 게시, G-Knowledge 등록, g-llm 호출, 로그인 성공/실패)의 보관 기간과 접근 통제
- **삭제·정지:** 정보주체의 열람·삭제·처리정지 요청 절차. 로컬 버전의 '전체 삭제'를 서버에서는 사용자 단위 삭제로 바꿉니다
- **마스킹 한계:** 결정기록 0003의 마스킹 한계는 화면 검토 단계로 보완하고 있습니다. 서버 배포 전에 탐지 규칙을 보강하고 다시 시험합니다

## 4. 지금 구조에서 그대로 쓸 수 있는 부분

- 의존 방향(app → domain ← collectors·integrations·storage)과 domain의 인터페이스. 화면과 업무 규칙은 그대로 옮길 수 있습니다.
- 수집기, AI, G-Knowledge, 위키 어댑터 인터페이스. 서버용 구현을 추가하면 됩니다.
- 마스킹 게이트웨이(`MaskedText`), 로그 정화, 오류 응답 정책, 승인 객체 기반 위키 게시 흐름.
