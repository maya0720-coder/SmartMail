# 0026 AI-Ground 요약 실패 진단·화면 단계 보강

- 날짜: 2026-11-15
- 상태: 구현(실제 AI-Ground에서 원인 확인 중)
- 관련 요구사항: AI-01·05·06, TODO-01, 결정기록 0008·0010·0023

## 배경

- 실행 중인 앱에서 요약 대기 161건이 하나도 처리되지 않았다. 로그에는 모든 AI-Ground 호출이 `AI-Ground 화면 자동화 실패` 한 줄로만 남았다.
- 이 실패는 병렬 요약(0023)을 넣기 전인 21:50부터 있었다. 따라서 병렬화 때문에 생긴 문제가 아니라 원래 있던 문제다.
- 예외를 그대로 삼켜서, 어느 단계(열기·새 대화·입력·보내기·답변 대기)에서 왜 실패했는지 알 수 없었다.

## 결정

1. **실패 진단 로그**(`integrations/ai/ground_diag.py`): 실패하면 다음만 남긴다.
   - 단계 이름
   - 오류 종류와 Playwright의 알려진 대기 사유(시간 초과·숨김·비활성 등)
   - 화면 구조: 같은 사이트인지(다르면 호스트 이름만), 경로, 선택자별 개수·보임·비활성 상태

   질문·답변·화면 글자, 쿼리 문자열, 쿠키는 남기지 않는다(0010·0020과 같은 기준).
2. **화면 단계 보강**(`ground_parallel.begin_chat`):
   - 열기: `domcontentloaded`까지만 기다리고, 채팅 입력칸이 보일 때까지 최대 20초 기다린다. 이미지·스트림 같은 리소스 때문에 `load`가 늦어지는 경우에 대비했다.
   - 입력칸이 나타나지 않았는데 다른 호스트(SSO 로그인 화면)에 있으면, '로그인 만료'로 안내한다.
   - '새 대화' 버튼은 보일 때만 누른다. 화면 없는 브라우저(1280×720)에서 대화 목록이 접히면 숨은 버튼을 누르려다 시간 초과가 날 수 있다. 첫 화면이 이미 새 대화이므로 버튼을 건너뛰어도 된다.
   - 보내기 버튼이 보이지 않으면 입력칸에서 Enter로 보낸다.
3. 답변 대기 시간 초과·답변 읽기 실패·브라우저 작업 자체의 실패(대기열 시간 초과 등)도 같은 형식으로 남긴다.

## 검증

- `tests/unit/test_ai_ground_browser.py`
  - 숨은 '새 대화' 버튼은 건너뛰고, 보이는 버튼은 누른다.
  - SSO로 넘어가면 '로그인 만료'로 안내하고, 로그에 쿼리·질문 글자가 없다.
  - 입력칸이 없으면 단계·오류·구조만 기록한다.
- 실제 AI-Ground 확인 결과는 아래에 이어 적는다.

## 실제 확인 결과(2026-11-15, 실행 중인 앱 로그)

### 원인 1: 그룹웨어 인증문자 대기가 브라우저 스레드를 막음(확인)

- 브라우저 실행기는 스레드가 1개다. 그룹웨어 로그인이 인증문자 입력을 최대 180초 기다리는 동안, AI-Ground 요청은 그 뒤에 줄을 섰다.
- 23:12:23에 `브라우저 작업 실패 오류=TimeoutError`가 났다. 대기열에서 시간 초과된 것이다.
- 23:12:36에 그룹웨어 대기가 끝난 직후 탭이 열렸지만, 남은 시간이 141ms뿐이라 `단계=열기 … Timeout 141ms exceeded`로 실패했다.
- 조치: 그룹웨어 로그인은 형제 실행기(`BrowserRuntime.sibling()`, 별도 스레드·별도 브라우저)에서 돌린다. 종료·임시 폴더 삭제는 본 실행기가 함께 처리한다.

### 원인 2: 질문이 입력만 되고 전송되지 않음(확인, 기존부터 있던 실패의 원인)

- 23:15에 브라우저가 비어 있을 때도 5개 탭 모두 `단계=답변 대기 TimeoutError`로 실패했다.
- 화면 상태는 `host=same path=/ new_chat=1v prompt=1v submit=1h answer=0`이었다. 채팅 화면은 정상이지만, 보내기 버튼(`#chatForm button.send`)이 숨어 있었다.
- 90초 동안 주소가 바뀌지 않았고 답변도 없었다. 질문이 아예 전송되지 않은 것이다.
- 예전 코드는 숨은 버튼을 누르려다 시간 초과됐다. 0023 이전의 `화면 자동화 실패`가 이 경우다.
- 조치(`integrations/ai/ground_send.py`): 전송 여부를 확인한다. 입력칸이 비워지거나, 새 답변이 나타나거나, 주소가 바뀌면 전송된 것으로 본다.
  - 전송되지 않았으면 보이는 보내기 버튼 → Enter → 폼 제출(`requestSubmit`) 순서로 시도한다.
  - 앞 방법이 전송된 것으로 확인되면 다음 방법은 쓰지 않는다(중복 전송 방지).
  - 모두 실패하면 답변 대기 없이 바로 실패하고, 입력칸 주변 버튼 구조만 기록한다.
- 실제 Chromium에서 모의 채팅 화면으로 확인했다.
  - 숨은 버튼 + Enter 미동작이면 폼 제출로 1회 전송된다.
  - Enter가 동작하면 Enter로 1회 전송된다.
  - 아무 방법도 안 되면 바로 실패한다.
- 실제 AI-Ground에서 어느 방법으로 전송되는지는 앱을 다시 시작한 뒤 로그(`AI-Ground 질문 전송 방법=`)로 확인한다.

### 수정 후 실제 결과(23:22~23:27, 재시작한 앱)

- 질문이 실제로 전송된다(`질문 전송 방법=Enter` 대부분, `폼 제출` 여러 번). 폼 제출 폴백이 없었다면 그 질문들은 답변 대기 90초 뒤에 실패했을 것이다.
- `ai_call … success`가 이어졌고, 요약 대기는 161건에서 126건으로 줄었다(35건 요약).
- 백그라운드 호출 상한(10분당 14회)에 닿으면 설계대로 멈췄다가 다음 주기에 이어서 처리한다.

### 원인 3: 묶음 답변 해석 실패로 호출 상한을 소모(추정, 보강)

- 화면 오류 없이 실패한 묶음이 있었고, 바로 뒤에 1건씩 다시 보낸 호출이 이어졌다. 묶음 답변의 머리(`[메일 N]`)가 기대한 꼴과 달라 해석에 실패한 것으로 보인다.
- 조치:
  - 해석기가 채팅 답변에 흔한 꼴을 받도록 넓혔다(`1. [메일 1]`, `[메일 1] 제목: …` 같은 줄, `메일 1:`, `### 메일 1`, 굵게 표시). 단, `메일 1건`처럼 숫자 뒤에 글자가 붙으면 머리로 보지 않는다.
  - 해석에 실패하면 답변의 '모양'만 기록한다. 글자를 종류로 바꿔 남기므로(한글→가, 영문→a, 숫자→9) 내용은 남지 않는다.
- 이 보강은 다음 재시작부터 적용된다.

## 남은 한계

- 처리량은 호출 상한이 정한다. 백그라운드 14회 × 4건으로 10분당 최대 56건이고, 해석 실패가 있으면 더 적다.
- 실제 AI-Ground 보내기 버튼(`#chatForm button.send`)이 숨겨진 이유는 확인하지 못했다(화면 개편 추정). 지금은 Enter·폼 제출로 보낸다.
- 'AI 해결 방안'도 같은 전송 경로(`begin_chat`)를 쓴다. 다만 이번 확인은 요약 위주였다.

## 추가 결정: 그룹웨어는 일괄 로그인에서 제외(사용자 결정 2026-11-15)

- 시작 로그인 창의 일괄 로그인 대상은 AI-Ground·G-Knowledge·위키다. 그룹웨어는 시도하지 않는다(`AUTO_SITES`).
- 그룹웨어는 필요할 때 사용자가 직접 로그인한다. 설정·연결의 그룹웨어 '로그인' 버튼을 누르면 같은 로그인 창이 그룹웨어 전용 모드로 열린다.
  - 그룹웨어 한 곳만 표시하고, 아이디만 입력한다.
  - 인증문자·보안문자 입력칸을 쓴다.
  - 서버는 `only=groupware` 요청일 때만 그룹웨어 로그인을 시도한다.
- `GET /api/login/pending`에 `manual_sites`(직접 로그인 대상 중 미로그인)를 추가했다. `?site=groupware`로 그룹웨어만 조회할 수 있다. 기존 필드는 그대로다.
- 그룹웨어 전용 창을 닫아도 시작 창 자동 띄움('나중에')은 바뀌지 않는다.
