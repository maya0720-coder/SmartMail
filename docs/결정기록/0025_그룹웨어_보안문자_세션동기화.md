# 0025. 그룹웨어 보안문자(CAPTCHA) 로그인: 같은 화면 캡처로 세션 동기화

- 날짜: 2026-11-15 / 요구사항: AUTH-01·09 / 관련: 0017, 0020

## 원인(가설 검증 결과)

- 앱 로그인 창은 번호 입력칸만 있고 그룹웨어의 보안문자 이미지를 보여 주지 못했다. 사용자가 다른 브라우저에서 그룹웨어를 열어 본 보안문자는 그 브라우저 세션에 발급된 값이라, 앱의 화면 없는 브라우저(다른 세션 쿠키)에 제출하면 항상 불일치한다.
- 보안문자 입력칸이 인증문자 선택자(`id/name*=otp`)에 잡히지 않으면 입력 자체가 되지 않는다.
- 코드상 이미지를 별도 HTTP 요청으로 받거나 쿠키를 따로 다루는 부분은 없었다(Playwright 컨텍스트 1개가 쿠키를 자동 유지). 실제 화면 구조는 아직 확인하지 못해 선택자는 추정값이다.

## 결정

1. 이미지는 로그인 중인 **같은 비저장 컨텍스트의 page 요소 스크린샷(PNG)** 으로만 얻는다. 별도 요청으로 다시 받지 않는다(새 보안문자가 발급돼 세션과 어긋나기 때문). 쿠키·hidden 토큰(csrf, captchaKey 등)은 같은 화면의 폼 제출로 그대로 전송된다. 흐름에는 `goto` 재호출·새로고침·폼 밖 POST가 없다.
2. 이미지는 `CaptchaChannel`(메모리)에만 두고 화면이 한 번 가져가면(또는 답·취소·시간 초과) 버린다. 크기 상한 200KB, 저장·로그 금지. API 응답은 `Cache-Control: no-store`. 화면은 `data:image/png;base64,`로 시작하는 서버 생성 값만 `img src`에 넣는다. CSP는 이미 `img-src 'self' data:`라서 변경하지 않았다.
3. 입력값: 앞뒤·내부 공백 제거, 대소문자 기본 보존(`captcha_case = keep|upper|lower`), 영문·숫자 + 길이 범위(`captcha_length`)를 서버에서 검사. 값은 흐름이 꺼내 가는 즉시 지우고 저장·로그·응답에 담지 않는다.
4. 이미지를 캡처한 뒤 사용자가 입력하는 사이 주소·이미지 src가 바뀌면(재발급) 낡은 값을 쓰지 않고 새 이미지로 다시 묻는다(최대 2회). '새 이미지' 버튼은 화면의 새로고침 요소를 눌러 지원한다.
5. 제출: 입력칸에서 Enter, 3초간 주소·화면 이동·알림창·이미지 변화가 없으면 제출 버튼(`submit`)을 눌러 폴백. 제출 직전 폼 안 hidden 입력의 **개수와 이름만** 로그에 남긴다(값 금지).
6. 오류: 알림창·화면 오류 영역(`error_area`)의 원문은 기록하지 않고 범주(보안문자 불일치 / 아이디·암호 오류 / 인증문자 안내 / 기타)로만 분류해 로그에 남긴다(경로 로그도 `;jsessionid=` 같은 경로 매개변수를 자르고 영문·숫자·`/._-`만 남긴다). **보안문자 재요청은 명확한 신호(보안문자 불일치 범주, 오류 영역의 보안문자 범주+화면 이동, 이미지 src 재발급)일 때만** 한다. 아이디·암호 오류 범주(알림창·오류 영역)는 즉시 중단하고, 범주 불명(기타)·시간 경과는 재제출 없이 기존 규칙대로 실패 처리한다. 폼을 다시 제출하는 횟수는 `captcha_max_tries`(기본 2, 설정 상한 3)로 제한한다(계정 잠금 방지, 보안 검토 M4).
7. 암호는 직접 한 번만 입력한다. 재시도 때는 보안문자 칸만 채워 제출하며, 화면이 암호칸을 비웠으면 빈 암호를 제출하지 않고 중단한다(계정 잠금 방지). 단 보안문자 칸 제출 시 폼에 남은 암호는 화면 동작상 함께 전송된다.
8. 상태 API 하위 호환: `/api/login/progress`에 `kind`(otp|captcha|null), `captcha_waiting|retry|seq`를 추가했고 기존 필드는 그대로다. 새 API: `POST /api/login/captcha/image`(이미지, 1회, 가져가면 버리는 동작이라 GET이 아닌 POST로 CSRF 검사 대상), `POST /api/login/captcha`(code | refresh | cancel).
9. 성공하면 기존처럼 세션이 등록되어 '• 그룹웨어' 상태가 녹색으로 바뀐다(경로 변경 없음).

## 실제 화면에서 확인할 것

`login_fields.toml [groupware]`의 `captcha_image`, `captcha_input`, `captcha_refresh`, `submit`, `error_area`는 일반 이름 기반 추정값이다. 실제 로그인 화면에서 보안문자 이미지·입력칸·새로고침·로그인 버튼·오류 영역의 id/name을 확인해 고친다. 실패 로그의 `visible=[...]`(화면 구조)와 hidden 입력 이름 목록이 단서다.
