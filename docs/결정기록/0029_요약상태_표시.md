# 0029 제안된 업무 제목에 요약 상태 칩 표시

- 날짜: 2026-11-16
- 상태: 구현
- 관련 요구사항: TODO-02, AI-01·05, 수정사항 R4

## 배경

- 제목이 AI 요약 제목인지, 아직 기다리는 중인지, 요약을 포기한 원래 제목인지 화면에서 구분되지 않았다.

## 결정

1. `mail_ref.summary_state`를 새로 둔다(스키마 4). 업무의 상태는 첫 메일 기준이다.

   | 값 | 뜻 | 칩 |
   | --- | --- | --- |
   | pending | 요약 대기 | 요약 대기 |
   | (running) | 지금 요약 중(저장하지 않고 응답 때 합성) | 요약 중 |
   | done | AI 요약 제목 | (대시보드는 숨김) |
   | kept | 실패 상한·일반 문구로 원래 제목 유지 | 원래 제목 |
   | missing | 원본 메일 없음 | 원본 없음 |

2. 이전 행은 한 번만 이관한다(`MIGRATION_4_SUMMARY_STATE`).
   - 요약 없음 → pending.
   - 구조화 요약이 있고 제목이 요약과 같음 → done.
   - 그 밖 → kept.
3. 칩은 글자와 `aria-label`로 구분한다(색만으로 구분하지 않음). 제안 목록·상세·빠른 정리·대시보드에 같은 함수(`summaryChip`)를 쓴다.
4. 요약 작업이 끝나면 목록 전체를 다시 그리지 않는다. 칩과 제목만 제자리에서 바꾼다(`patchSummaryStates`).
