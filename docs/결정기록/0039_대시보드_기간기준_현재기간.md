# 0039 대시보드 기간 기준: 현재 기간과 기간 필터

- 날짜: 2026-11-17
- 상태: 구현 완료
- 관련 요구사항: MET-01~04(기획서 4.9), TODO-03(상태 분포·할 일 목록)
- 근거 문서: `수정사항_20261117072857.md` A1, 결정 D2(기본안 적용)

## 배경(원인 P1~P3)

- P1: 지표 카드가 진행 중인 기간을 뺀 '최근 완료 기간'만 보여 줬다. 앱을 11월부터 써서 연간·반기·분기·월 버튼을 눌러도 0건·'데이터 없음'이었다. 그래서 필터가 동작하지 않는 것처럼 보였다.
- P2: 기간 버튼은 지표만 다시 불렀다. 상태 도넛과 할 일 목록은 기간과 관계없이 전체를 보여 줬다.
- P3: 카드 '완료 건수'는 지표 원장 기준이고, 도넛 '완료'는 업무 상태 기준이다. 정의가 달라 숫자가 맞지 않아 보였다.

## 결정

### 1. 지표 카드: 현재 기간 기준(`domain/metrics/aggregate.py`)

- `basis`를 두 가지로 나눈다.
  - `current`(기본): 진행 중인 현재 기간 [시작, 지금]의 값이다. 비교 대상은 직전 기간의 **같은 경과 구간**이다(예: 2026년 1/1~11/17 vs 2025년 1/1~11/17).
  - `last_complete`: 이전 방식이다. '기준·표로 보기' 창의 체크로 바꿀 수 있다(메모리에만 둠).
- 직전 기간이 더 짧으면 직전 기간 끝에서 멈춘다(예: 3/31 기준 월간은 2월 전체와 비교).
- `GET /api/metrics?grain=…&basis=current|last_complete` 응답에 다음 필드를 추가했다(기존 필드는 그대로).
  - `basis`
  - `period_start`: 할 일 목록의 `since` 값
  - `current_label`: 예 "2026년(진행 중)"
  - `period_text`: 예 "2026년 · 11/17까지"
  - `compare_label`: 예 "전년 동기 대비"
  - `compare_text`: 예 "2025.01.01~2025.11.17"
- 카드 아래 문구는 `직전 대비` 대신 `전년/전반기/전분기/전월/전주 동기 대비`다. 기간 이름은 기간 버튼 옆에 보인다.
- 표본 5건 미만이면 '참고' 표시를 유지한다.
- 추이 그래프는 그대로 둔다(최근 n개 기간, 진행 중 기간은 흐리게).

### 2. 상태 도넛·할 일 목록 기간 필터(D2 기본안)

- 상단 기간 버튼은 **대시보드 전체의 기간**을 정한다. 맨 앞에 `전체`를 추가했다(기간 무관, 지표 카드는 연간으로 표시).
- 고른 값은 ui_prefs `dashboard_grain`(`app_setting.ui_dashboard_grain`, 허용 값만)에 저장하고, 다음에 열 때 그대로 쓴다.
- 기간에 포함하는 규칙(`domain/tasks/period_view.py` `in_period`, 순수 함수): 현재 기간 [시작, 지금]에 다음 중 하나라도 맞으면 포함한다.
  - 요청일(없으면 만든 시각) 또는 최근 메일 시각이 기간 안
  - 완료일이 기간 안
  - **이월**: 기간 시작 전에 생겼고 아직 끝나지 않은 업무(완료·무시가 아님). 기본은 포함이고, 할 일 머리의 `이월 포함`으로 끈다.
- 서버 `GET /api/tasks?since=<ISO, 시간대 필수>&carry=true|false`
  - 시간대가 없으면 400, 형식이 틀리면 422다.
  - 기간 시작은 지표 응답의 `period_start`(`bucket_of`)를 그대로 쓴다.
- 도넛 숫자, 범례, 상태 필터, 검색, 정렬은 이렇게 거른 결과 안에서 동작한다.

### 3. 카드·도넛 숫자

- 도넛 '완료'는 지금 완료 상태인 업무 수다. 카드 '완료 건수'는 기간 안에 완료가 확정된 원장 건수다. 두 정의를 툴팁과 '기준·표로 보기'에 적었다.
- **원장 누락 보정**(`domain/metrics/backfill.py`): 앱이 시작될 때(컨테이너 구성 때) 1회 실행한다.
  - 완료 상태인데 원장에 없는 업무를 숫자 항목만으로 채운다(완료일·기한 유무·기한 준수·지식 등록).
  - 완료일이 없으면 추정하지 않고 건너뛴다.
  - 남아 있는 업무만 대상으로 하므로 `SMARTMAIL_METRICS_LEDGER_KEEP` 설정을 그대로 따른다.

### 4. 함께 고친 문제

- 지표 코드를 `dashboard_metrics.js`로 나누면서 스크립트 순서 경합이 생겼다. 캐시로 응답이 빨리 오면 첫 새로고침이 지표 스크립트를 읽기 전에 실행됐다(`loadMetrics is not defined`).
- `dashboard_metrics.js`를 `dashboard.js`보다 먼저 읽도록 순서를 바꿨다.

## 보안·개인정보

- 기간 필터는 서버에서 계산한다. `since`는 시간대가 있는 시각만 받는다.
- ui_prefs는 허용 값 6개만 저장한다(이름 허용 목록 `SqliteAppSettings.ALLOWED`).
- 원장 보정은 숫자 항목만 쓴다. 제목·본문·상대방 정보는 원장에 넣지 않는다(테스트로 확인).
