# 0024. 주간보고 참고 링크 양식 초안과 게시 폴백·게시 캐시

- 날짜: 2026-11-15 / 요구사항: WIKI-01~06 / 관련: 0015, 0021

## 결정

1. **참고 링크 등록(설정·연결)**: https만, URL 500자·이름 40자·최대 10개, 사용자 정보·제어 문자·비ASCII 거부(서버 검증). 플랫폼은 순수 함수로 판별한다. 슬랙은 호스트가 `slack.com` 또는 `*.slack.com`일 때만(`slack.com.evil.example`은 기타 웹), 위키는 설정된 위키 호스트와 같거나 Confluence 경로 패턴(`/display/`, `/pages/viewpage.action`, `/wiki/spaces/`, `/spaces/*/pages/`), 나머지는 기타 웹.
2. **SSRF 회피**: 서버는 임의 외부 URL을 가져오지 않는다. 위키 링크의 양식은 위키 어댑터(`WikiApi.get_page_by_link`)로만 읽는다. Confluence 실구현은 규격 미확인이라 로그인 확인 후 `WikiUnavailableError`(미구현), Fake는 동작한다. 슬랙·기타 웹은 사용자가 링크 등록 시 붙여 넣은 '양식 목차(머리글 줄)'만 쓴다(최대 30줄·줄당 60자, 마스킹).
3. **양식 → 머리글 매핑**: 목차의 머리글을 키워드 규칙(`config/rules/weekly_form.toml`)으로 금주 실적(완료·진행) / 차주 계획(예정) / 이슈·요청에 매핑한다. 판정 순서는 이슈 → 계획 → 실적(첫 일치), '진행 중'은 금주 실적으로 본다. 매핑되는 머리글이 없거나 가져오기 실패·링크 미선택이면 기본 양식(WikiTemplate 머리글)으로 되돌리고, 화면에 사용한 양식과 사유를 안내한다. `/api/weekly/draft` 응답은 `form` 필드만 추가했다.
4. **머리글 전달**: 초안 응답의 `form`을 화면이 그대로 되돌려 보내고, 서버는 길이·마스킹을 다시 검증한다. 머리글은 HTML 이스케이프를 거쳐 미리보기·게시에 쓰이고, 승인 지문(digest)에 포함된다.
5. **형식 변환·복사**: 슬랙 mrkdwn(`&<>` 치환, 전체 멘션 무력화), 위키 마크업(서식 기호 이스케이프)·위키 HTML, 일반 텍스트. 변환은 마스킹된 초안에서만 만들고, 복사는 `navigator.clipboard`(위키는 text/html+text/plain), 실패 시 선택 영역 복사, 그것도 실패하면 선택된 수동 복사 칸을 보여 준다.
6. **승인 → 게시 → 폴백**: 승인(1회용 번호·지문) 흐름은 그대로이며 승인 없는 게시 경로는 없다. 위키 대상은 API 게시를 시도하고, 사용 불가(`WikiUnavailableError`)면 클립보드 폴백이다. 위키 로그인 필요는 폴백하지 않고 기존처럼 로그인 후 재시도한다. 슬랙·기타 웹은 API가 없어 항상 폴백이다. 폴백 시 서버는 변환본과 `safe_link`를 통과한 https 대상 주소를 돌려주고, 화면이 복사 후 새 창(noopener)으로 연다. `fallback=false`(기본)면 기존 동작(오류 응답)을 유지한다.
7. **게시 캐시**: 새 테이블 `weekly_publish_cache`(주차·플랫폼·방식 api/clipboard·시각·링크·마스킹 본문 스냅샷). 기존 `weekly_report`는 그대로 둔다. 스냅샷에는 본인 이름 머리글을 넣지 않는다. 보관기간(`retention_days`)이 지나면 `RetentionJob`이 지운다. 참고 링크는 새 테이블 `weekly_link`. 두 테이블 모두 전체 삭제 대상에 포함했다. 두 테이블은 `CREATE TABLE IF NOT EXISTS`로 추가해 기존 DB도 그대로 열린다.

## 실제 위키·슬랙에서 확인할 것

- Confluence REST API 허용·인증 방식(미확인이라 현재는 항상 폴백). 확인되면 `get_page_by_link`은 위키 기준 주소 밖 링크를 거부해야 한다.
- 위키 편집기에 text/html 붙여넣기가 머리글·목록 구조를 유지하는지, 슬랙 입력창에 mrkdwn 붙여넣기 서식이 맞는지.
- 실제 위키 양식 페이지의 머리글 구조와 키워드 규칙이 맞는지.
