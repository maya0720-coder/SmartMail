# 0021 요약·해결 방안 품질 개선 · 공모전용 합성 데이터

- 날짜: 2026-11-13
- 상태: 구현(실제 AI-Ground 응답 형식 준수율은 사용 후 확인 필요)
- 관련 요구사항: TODO-01, AI-01~06, HIST-03·04·06, SRCH-01~05, MET, 결정기록 0008·0014·0015

## 배경

- 앱의 목적은 메일을 읽고 요약해 해결 방안을 미리 제안하는 것인데, 사용자 평가로 "요약과 제안이 매우 취약"했다.
- 코드 분석 결과 원인(우선순위 순):
  1. 해결 방안 요청에 업무 제목(40자)만 보내고, 유사 사례는 항상 비어 있었다.
  2. 이력 조회가 앞 단계에서 결과가 나오면 멈춰, AI 제안 대신 링크 목록만 나왔다. 앱 이력 검색은 모든 단어가 일치해야 해서 거의 걸리지 않았다.
  3. 요약 입력이 첫 메일 본문 700자뿐이었다. 전달 메일은 실제 요청(인용부)이 잘렸고, 서명이 글자 수를 차지했으며, 후속 메일은 반영되지 않았다.
  4. '요약'은 40자 제목 한 줄뿐이었다(요청 사항·기한·필요 조치 없음).
  5. AI 분류가 실패하면 메일이 조용히 빠졌다. 묶음 답변 하나가 형식을 깨면 6건이 모두 실패했고, 계속 다시 보내졌다.
  6. 품질을 측정할 수단이 없었다.
  7. 요약 작업과 해결 방안 요청이 AI 호출 상한(10분당 20회)을 함께 써서, 사용자 요청이 막힐 수 있었다.
- 사내 AX 공모전 제출 조건: 실제 데이터 사용 금지.

## 결정

### 요약(TODO-01 개정)

- AI가 메일마다 **제목·요청 사항(최대 5개)·기한·필요 조치**를 정해진 4줄 형식으로 답한다(`prompts.py`의 역할 안내와 예시 포함). 제목은 업무 제목으로, 나머지는 마스킹된 구조화 요약(`mail_ref.digest`, 1,500자 이하)으로 저장한다. 메일 원문은 여전히 저장하지 않는다.
- 요약 입력(`domain/tasks/mail_text.py`):
  - 인사말·서명·면책 문구를 빼고, 줄바꿈을 살린다.
  - 인용 앞 내용이 짧으면 전달 메일로 보고, 인용된 원래 메일 본문을 붙인다.
  - 같은 업무의 최신 후속 메일 발췌(300자)와 첨부 파일명을 붙인다.
  - 건당 1,500자로 하고, 묶음은 6건에서 4건으로 줄였다.
- 실패 처리:
  - 묶음 답변을 해석하지 못하면(`AiParseError`) 1건씩 다시 보낸다.
  - 1건 해석 실패는 횟수를 센다(`mail_ref.summary_tries`). 3회가 되면 메일 제목을 유지하고 더 보내지 않는다.
  - 일반 문구 답변은 한 번 더 요청한다.
- 스키마 3: `mail_ref.digest`, `mail_ref.summary_tries`. 기존 데이터를 보존하는 마이그레이션이다.

### 해결 방안(SRCH 흐름 변경, 기획서와 다름)

- 기획서 SRCH-01~03의 "앞 단계에서 찾으면 멈춤"을 바꿨다. **앱 이력과 G-Knowledge를 모두 찾은 뒤, 찾은 사례(앱 최대 3건 + G-Knowledge, 합계 5건)를 근거로 붙여 AI 해결 방안을 만든다.**
  - 앞 단계 결과를 보여 주는 것은 그대로다.
  - 해결 단계(지표)는 가장 앞에서 결과가 나온 단계로 기록한다. 따라서 MET 정의는 바뀌지 않는다.
- 화면 '유사 이력'은 사례 찾기만 한다(AI 호출 없음, `suggest=false`). 'AI 해결 방안'은 사례 찾기에 AI 제안까지 실행한다. 히스토리 화면 검색도 기본은 찾기만 하고, 버튼을 누르면 AI를 부른다.
- AI 입력에는 업무 맥락을 마스킹해 넣는다(`domain/search/context.py`): 제목·구분·요청 부서·기한·구조화 요약·메일 발췌·첨부 파일명.
- 앱 이력 검색:
  - 모든 단어 일치(AND) 대신 단어별 점수를 매긴다. 조사와 일반 단어는 빼고, T-code가 일치하면 가중치 3을 준다.
  - 단어가 3개 이상이면 2점 이상인 카드만 점수순으로 돌려준다.
- 답변 형식: 원인 추정·확인 순서·조치 방안·관련 T-code·참고한 사례. 확실하지 않은 내용은 '추정'으로 표시한다.

### 분류·호출 상한

- 애매한 메일에서 AI 분류가 실패하면, 버리지 않고 확신도 0.35의 제안으로 남긴다(이유 코드 `ai_unavailable`). AI가 '아님'이라고 답하면 지금처럼 제외한다.
- 분류 입력에 본문 발췌(400자)를 더했다.
- AI-Ground 호출 상한 10분당 20회 중 **백그라운드(요약·분류)는 14회까지**만 쓴다. 나머지는 사용자가 누른 해결 방안 요청 몫이다.

### 품질 측정

- `GET /api/metrics/ai-quality`: 최근 30일의 해결 방안 '도움 됨' 비율과 AI 호출 성공률. 이벤트 코드값 개수만 센다. 대시보드 '기준 · 표로 보기' 창에 표시한다.
- 합성 평가 세트로 요약의 핵심어 포함률을 재는 스크립트: `scripts/measure_summary.py`.

### 공모전용 합성 데이터

- 실제 메일은 쓰지 않는다(완전 합성). 데모 모드(`-Demo`)의 가상 메일함을 SAP ERP 운영 업무 유형으로 확장했다. 다음을 모두 포함한다:
  - 전달 메일, 긴 서명·면책 문구, 여러 요청이 든 메일, 후속 요청 회신
  - 오류 번호·T-code, 다양한 기한 표현, 이미 처리 완료된 스레드
  - 업무가 아닌 메일
- 사람·부서는 가상이고, 주소는 `example.invalid`이다. 데모용 과거 해결 사례(히스토리 카드)와 가상 G-Knowledge 문서를 시작할 때 메모리 DB에 넣어 '유사 이력'과 사례 근거 제안을 시연할 수 있게 했다.

## 보안·개인정보

- AI·G-Knowledge로 가는 맥락·사례는 모두 마스킹 타입(`MaskedText`)이고 길이 상한이 있다(게이트웨이 재검사).
- 구조화 요약은 AI 답변의 모든 칸을 다시 마스킹해서 저장한다.
- 메일 원문·첨부는 저장하지 않는다. 발췌는 요청할 때 메모리에서만 만든다.
- 구조화 요약은 업무가 삭제되면 함께 지워진다(`mail_ref` 외래 키 연쇄 삭제, 보관기간 작업).

### 보안검토 결과(2026-11-13, 상 0·중 3·하 7)

반영함:
- AI 호출 기록(`ai_call_log`)에는 메일 발췌를 남기지 않고 호출 종류·건수만 남긴다(중3).
- `/api/search`의 `suggest` 기본값을 거짓으로 바꿨다. AI 호출은 화면에서 명시할 때만 한다(하4).
- 그룹웨어 알림창은 안내(alert) 창만 인증번호 안내로 수락한다. 확인·입력 창은 취소한다(하5).
- 번호를 묻기 전에 일반 알림창이 뜨면 인증 칸이 보여도 아이디·암호 오류로 끝낸다(하6).
- 실패 진단 로그(화면 구조)는 제어 문자를 지우고, 암호칸 type은 `secret`으로 적는다(하7).

사용자 확인 필요(미반영):
- 중1 저장 요약 잔존 위험: AI 요약 칸은 다시 마스킹하지만, `mask()`는 정해진 형식(전화·메일·주민번호 등)만 가린다. 사람 이름·거래처명이 요약에 남아 DB에 저장될 수 있다. 후보 대책은 두 가지다. ① 메일 머리글(보낸 사람·받는 사람)의 이름으로 메모리 전용 사전을 만들어 가린다. ② 원문 문장과 길게 겹치는 요약 칸은 버린다.
- 중2 전송 범위 확대: AI-Ground로 가는 발췌는 최대 1,000자이고 후속 메일 300자와 첨부 이름이 포함된다. 본문 속 이름과 첨부 파일명은 가리지 않는다. 후보 대책은 세 가지다. 위 ① 이름 사전, 첨부는 종류(확장자)만 보내기, 인용 머리글 블록 건너뛰기.
- 하8(인증번호 취소 직전 경합)·하9(지표 라우트의 저장소 직접 참조)·하10(묶음 프롬프트 구분자)은 영향이 작아 다음 개선 후보로 둔다.

## 확인 필요

- 실제 AI-Ground가 4줄 형식·해결 방안 형식을 얼마나 지키는지. 형식을 깨면 1건씩 재시도하므로 호출 수가 늘 수 있다.
- 후속 메일이 요약 뒤에 도착하면 구조화 요약을 다시 만들지는 않는다(다음 개선 후보).
