# 0012. 화면 디자인 개편 — ui-ux-pro-max(Data-Dense Dashboard)

- 날짜: 2026-11-12
- 상태: 1차·2차 구현 완료, 3차(일괄 작업) 미구현
- 근거 문서: `designMD/01_디자인변경_ui-ux-pro-max.md`
- 관련: 기획서 6장(화면), 12단계

## 배경

직전에는 ui-patterns 토큰으로 디자인을 바꿨다(커밋 "레이아웃변경 버전 최초"). 이번에는 사용자가 디자인 명세 01을 지정했다. 명세의 목적은 업무 대시보드의 정보 밀도와 조작 효율을 높이는 것이다.

## 결정

1. **골격**
   - 사이드바를 없애고, 떠 있는 상단 내비(radius 14, 반투명·blur)로 바꾼다.
   - 1180px 이하에서는 메뉴를 아이콘만 표시하고, 720px 이하에서는 하단 탭바를 쓴다.
2. **글꼴·아이콘**: 모두 로컬에 번들한다. CSP와 외부 리소스 금지 규칙 때문이다.

   | 리소스 | 버전 | 라이선스 | 위치 |
   | --- | --- | --- | --- |
   | Pretendard Variable | 1.3.9 | SIL OFL 1.1 | `static/fonts/` |
   | Fira Code VF | 6.2.0 | SIL OFL 1.1 | `static/fonts/` |
   | Lucide 아이콘 21개(스프라이트) | 0.460.0 | ISC | `static/img/` |

   - 받은 곳: 공식 npm 패키지(jsDelivr), 버전 고정
   - 받은 뒤 확인한 것:
     - 파일 형식이 WOFF2인지 확인했다.
     - 아이콘에 스크립트나 외부 참조가 없는지 확인했다.
     - 라이선스 파일을 함께 넣었다.
   - SHA-256 값:
     - Pretendard `9599f12f…2d900b4`
     - Fira Code `408e876a…db96dd49f`
3. **목록 기본 정렬**: "최근 생성순"으로 한다.
   - 명세 4장에서 구현 전에 정하라고 한 항목이다.
   - 수동으로 추가한 업무가 1페이지에 오고, 기존 브라우저 테스트도 그대로 통과한다.
4. **페이징**: 표가 시작하는 위치부터 창 아래까지 들어가는 행 수로 페이지 크기를 정한다(최소 5행).
   - 창 크기가 바뀌거나 글꼴이 적용된 뒤 다시 계산한다.
   - 다시 계산할 때 보던 첫 항목이 계속 보이도록 페이지 번호를 맞춘다.
   - 필터나 정렬을 바꾸면 1페이지로 간다.
   - 목록에 포커스가 있을 때 ←/→ 키로 페이지를 옮긴다.
   - 정렬·페이지 상태는 메모리 변수에만 둔다(브라우저 저장소 금지).
5. **상태 도넛**: `#mk` 밖의 형제 요소(`#status-donut`)로 둔다.
   - 기존 테스트의 `.kpi` 4개 조건을 지키기 위해서다.
   - 새 API는 만들지 않고, 이미 불러온 업무 목록으로 계산한다.
6. **범위 밖**
   - 3차 체크박스 일괄 작업과 표의 선택 체크박스 열은 넣지 않았다. 명세 6장에서 '선택' 단계다.
   - API·도메인·보안 미들웨어는 바꾸지 않았다.
7. **함께 고친 버그**: `replaceChildren(..., 조건 ? 요소 : null)`이 화면에 "null" 글자를 표시하는 문제를 고쳤다.
   - 해당 위치: 업무 상세, 메일 원본, 유사 이력, 히스토리 검색, 주간보고 미리보기
   - 방법: 빈 항목을 거르는 공통 함수 `fill()`로 일괄 수정했다.

## 대안

- 직전 버전(ui-patterns 토큰, 커밋 `15f8cd3` "레이아웃변경 버전 최초")
  - 여백이 넓고 카드가 큰 단순한 화면이다.
  - 이번 버전이 맞지 않으면 그 커밋으로 되돌릴 수 있다.

## 검증

- **기존 테스트**: 화면 렌더링(인라인 금지·위험 함수 금지·외부 리소스 금지), 브라우저(기간 전환·XSS)가 모두 통과했다.
- **추가 테스트**
  - 1440×900, 1024×768, 390×844 화면에서 페이지 크기가 창에 맞는지 확인했다.
  - 페이저의 다음·이전·번호 버튼과, 필터를 바꾸면 1페이지로 가는 동작을 확인했다.
  - 정렬 상태(`aria-sort`)가 오름 → 내림 → 해제로 순환하는지, Enter 키와 →키로도 동작하는지 확인했다.
  - 모든 요청이 같은 출처인지 확인했다.
  - 번들한 파일의 라이선스와 스프라이트 안전성을 확인했다.
- **수동 확인(데모 데이터 캡처, 로컬에만 저장)**
  - 대상: 1440·1024·768·390·320px, 라이트·다크
  - 결과: 가로 스크롤 없음, 콘솔 오류 없음, 외부 요청 없음
