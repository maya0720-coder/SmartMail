# 0034 필요할 때만 일괄 로그인(시작 로그인 창 대체)

- 날짜: 2026-11-17
- 상태: 구현 완료(데모·가짜 인증기로 검증)
- 관련 요구사항: AUTH-01·05·09, 결정기록 0014 3장(시작 로그인 창)을 대체
- 근거 문서: `수정사항_20261117020320.md` N3·U8(사용자 승인 2026-11-17)

## 배경

- 앱을 열 때마다 로그인되지 않은 사이트가 있으면 시작 로그인 창이 자동으로 떴다(0014 3장).
- 외부 연동이 필요 없는 작업(목록 정리 등)만 하려는 경우에도 창을 닫아야 했다.
- 진입점마다 로그인 확인 방식이 달랐다(`requireLogin` 1개 사이트, 503 응답 후 처리 등).

## 결정

1. **시작 시 자동 띄움 제거.** 연결 상태 칩과 1분 주기 갱신만 남겼다.
   - `/api/login/later`와 `dismissed`는 하위 호환으로 남기고 화면에서는 쓰지 않는다.
   - 창의 '나중에' 버튼은 '닫기'로 바꿨다.
2. **공통 함수 `ensureLogin(sites, action, { label, force })`**(`login.js`)
   - 필요한 사이트 중 로그인되지 않은 사이트를 확인한다. 모두 로그인되어 있으면 `action()`을 바로 실행한다.
   - 처리 순서
     1. 사이트 로그인 화면을 직접 여는 사이트는 그 흐름을 쓴다.
     2. 그룹웨어(일괄 대상 외)는 그 사이트만 묻는 창을 연다.
     3. 회사 계정이 이미 연결돼 있으면 입력 없이 SSO(`/api/login/all {sites}`)를 먼저 시도한다.
     4. 남은 사이트가 있으면 일괄 로그인 창을 연다.
   - 창 제목에는 작업 이름을 넣는다(예: "AI 일괄 요약 · 로그인이 필요합니다").
   - 창에는 이번 작업에 필요한 사이트와 '아직 로그인 안 된 다른 사이트도 함께 로그인' 체크(기본 켬)를 보여 준다.
   - 로그인에 성공하면 `action()`을 자동으로 다시 실행한다. 닫으면(Esc 포함) "로그인 후 다시 시도해 주세요"를 안내한다.
3. **'로그인이 필요한 사이트' 판정은 서버가 정한다.** `/api/connections`에 `needs_login`을 추가했다.
   - 데모·가짜 어댑터처럼 로그인 없이 동작하는 사이트와, 아웃룩 수집일 때의 그룹웨어는 `false`다(`Container.login_free_sites`).
   - 그래서 데모에서는 기능 버튼이 로그인 창 없이 바로 동작한다.
   - 지시서에 없던 판단이다. 이렇게 하지 않으면 로그인이 필요 없는 실행에서도 창이 떠서 이번 목적과 맞지 않는다.
4. **서버 `/api/login/all`에 `sites`(사이트 목록)를 추가했다.**
   - 목록에 그룹웨어도 넣을 수 있다. `only`와 함께 쓰면 400을 돌려준다.
   - 빈 목록·모르는 이름·5개 이상은 422로 거부한다.
5. **연동 진입점 연결**

| 진입점 | 필요 사이트 | 방식 |
|---|---|---|
| 제안된 업무 `[AI로 일괄 요약]` | ai-ground | 실행 전 확인 |
| 상세 `AI 해결 방안` | ai-ground | 실행 전 확인 |
| 상세 `유사 이력`(G-Knowledge 검색 포함) | g-knowledge | 실행 전 확인 |
| 상세 `AI로 진행 요약` | ai-ground | 실행 전 확인 |
| `지식 등록` | g-knowledge | 실행 전 확인 + 503 응답 시 다시 확인 |
| 메일 `[지금 수집]`·범위 수집·빈 목록에서 수집 | groupware(그룹웨어 경로일 때만) | 실행 전 확인 |
| 위키 게시 | wiki | **서버가 로그인 필요(503)라고 할 때만** |

   - 위키 게시는 API가 승인되지 않으면 로그인 없이 클립보드 폴백으로 동작한다. 그래서 미리 묻지 않고 서버 응답으로 판단한다(지시서와 다름).
   - 주간보고 양식 읽기는 4단계(0037)에서 같은 함수로 연결한다.
   - 회사명 확정의 AI 조회는 지금 화면 진입점이 없다. 백그라운드 작업(`CompanyJob`)만 있어서 연결하지 않았다.
6. **백그라운드 작업은 창을 띄우지 않는다.** 요약 주기 작업, 자동 메일 수집, keep-alive는 로그인이 없으면 조용히 건너뛴다(기존 `ready()` 판정 유지).
   - 안내는 제안 화면 요약 막대 문구와 버튼으로 한다.
7. **U8 연결 칩**
   - 로그인되지 않은 칩은 `<button>`으로 그린다. 누르면 그 사이트 로그인 창이 열린다(`force`: 가짜 어댑터여도 연다).
   - 로그인된 칩은 지금처럼 사이트를 새 탭으로 연다(`<a>`, https만).
   - 칩 옆 `모두 연결`은 로그인 안 된 사이트가 있을 때만 보인다. 그룹웨어는 이번 실행에 필요할 때만 포함한다.
8. 창이 열려 있으면 입력칸에 초점이 오기 전에 누른 Esc도 창을 닫는다(문서 단위로 처리).

## 보안·개인정보

- 자격증명 처리 방식은 바꾸지 않았다. 입력은 전송 직후 지우고, 서버는 bytearray로 받아 0으로 덮어쓴다.
- SSO 시도 요청에는 ID·암호를 넣지 않는다(테스트로 확인).
- 사이트 목록은 허용된 이름만 받는다(`SiteName`).
