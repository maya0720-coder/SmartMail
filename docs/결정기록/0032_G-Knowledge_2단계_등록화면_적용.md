# 0032 G-Knowledge 2단계 등록 화면 적용

- 날짜: 2026-11-16
- 상태: 구현 완료(가짜 페이지 검증). 실제 사이트 자동 등록 1회 점검 필요
- 관련 요구사항: GK-03·04·06, 결정기록 0008·0010

## 배경 — 오류 원인

- 완료 업무를 G-Knowledge에 등록하면 "G-Knowledge 화면 필드가 확인되지 않아 자동 등록·검색을 할 수 없습니다(확인 필요)"가 나왔다.
- 원인: `gknowledge_fields.toml [register]`에 등록 경로만 있고 제목·본문·등록 버튼·결과 확인 방법이 모두 비어 있었다.
  - 어댑터(`BrowserKnowledgeStore.register`)는 설정이 비면 브라우저를 열지 않고 이 안내를 낸다.
  - 이는 추측 구현을 막기 위한 의도된 동작이다(결정기록 0008).
- 또 2026-11-12에 확인한 실제 화면은 2단계(작성 → AI 분석 → 등록요청)였다(결정기록 0010). 그런데 어댑터는 1단계(작성 → 등록)를 전제로 했다. 그래서 선택자를 채우는 것만으로는 동작하지 않았다.

## 결정(사용자 승인 2026-11-16)

1. **선택자**: 0010에서 확인한 값을 넣었다.
   - 제목 `#title`, 본문 `.ql-editor`(Quill), AI 분석 `#analyze-btn`, 분석 완료 표시 `#c-title`, 등록요청 `#confirm-btn`.
2. **2단계 흐름**: `analyze`·`analysis_ready` 설정을 새로 두었다. 비우면 기존 1단계로 동작한다.
   - 순서: 제목·본문 입력 → 본문이 들어갔는지 확인 → AI 분석 → 분석 결과 칸이 보일 때까지 최대 60초 대기 → 등록요청.
   - **AI 분석 결과 칸은 G-Knowledge가 채운 그대로 둔다**(사용자 결정). 앱은 결과 칸을 고치지 않는다.
3. **보내기 전 실패는 '보내지 않음'**: 본문 입력 확인 실패와 분석 시간 초과는 등록요청 전에 멈춘다. 그래서 다시 시도해도 중복 등록이 생기지 않는다.
   - 본문 확인은 공백·줄바꿈을 빼고 비교한다. Quill이 줄을 문단으로 바꿔 담을 수 있기 때문이다.
4. **등록 결과 확인**:
   - 사용자가 한 건을 직접 등록하고, '등록요청' 뒤 이동한 주소 형식을 알려 주면 `result_path`에 넣는다(사용자 결정). → 실제로는 주소가 바뀌지 않아 아래 '등록요청 뒤 화면 확인'에서 `result_message` 방식으로 바꿨다.
   - 그 전까지는 자동 등록하지 않는다. 안내에 비어 있는 설정 이름만 덧붙인다(`— 미설정: result_path(또는 result_link)`).
5. 전체 등록 제한 시간을 90초에서 150초로 늘렸다. 화면 열기 30초 + 분석 60초 + 결과 확인 30초 + 여유다.

## 남은 한계

- 검토 대기(REVIEW) 이후 반려되거나 게시되는 결과는 앱이 따라가지 않는다. 앱에는 '등록 요청함'까지만 남는다.
- 화면 안내 문구가 바뀌면 결과 확인이 실패한다. 이때는 다시 보내지 않고 사용자 확인을 요청하므로 중복은 생기지 않는다.
- 실제 Quill 편집기에서 줄바꿈이 원하는 모양으로 들어가는지는 실제 화면에서 확인해야 한다.
- 검색(같은 제목 중복 확인) 화면 구조는 아직 모른다. `[search]`는 비워 두었고, 중복 확인은 지금처럼 건너뛴다.

## 작성 화면 재확인(2026-11-16, 사용자 화면 캡처)

- 주소 `/knowledge/new`, 순서 '제목 → 내용(Quill) → 첨부 → AI 분석'이 설정과 같다. 선택자 변경은 없다.
- 제목은 '(선택)' 항목이다. 앱은 항상 제목을 넣으므로 동작 변경은 없다.
- 첨부(선택, 최대 20MB·5개)는 자동화하지 않는다(메일 첨부 미저장·미전송 원칙 유지).
- 안내 문구가 "확인/수정 후 등록을 요청하세요"다. '등록요청'이 승인 대기일 가능성이 있어, 등록 뒤 이동 화면은 여전히 실제 1건 등록으로 확인해야 한다.
- 캡처는 1단계(작성) 화면뿐이라 `result_path`는 이번에도 채우지 않았다.

## 분석 결과 화면 확인(2026-11-16, 사용자 화면 캡처)

- 'AI 분석' 뒤 같은 주소(`/knowledge/new`) 아래에 'AI 분석 결과(확인/수정 후 등록 요청)' 영역이 나타난다.
  - 칸: 제목·요약·본문·부서·분류·키워드(쉼표 구분). 0010에서 확인한 `#c-*` 칸과 같다.
  - 버튼: 재분석·등록요청·취소.
- 분석 전 작성 화면에는 이 영역이 보이지 않았다. 따라서 '`#c-title`이 분석 전부터 보여 너무 일찍 판단하는' 위험은 화면상 해소됐다.
- **주의(개인정보)**: G-Knowledge AI가 분석 본문에 로그인한 제출자의 이름·소속을 '담당자'로 넣었다.
  - 앱이 보낸 내용이 아니라 G-Knowledge가 로그인 정보로 추가한 것이다.
  - **사용자 결정(2026-11-16): 그대로 둔다.** 사내 지식에 작성자 정보가 남는 것은 G-Knowledge 자체 처리로 보고, 앱은 분석 결과 칸을 고치지 않는다.
- 등록요청 뒤 이동 주소는 이번 캡처에도 없어 `result_path`는 계속 비워 둔다.

## 등록요청 뒤 화면 확인과 결과 확인 방식(2026-11-16, 사용자 1건 등록)

- '등록요청' 뒤 주소는 `/knowledge/new` 그대로다. 화면에는 "등록 요청이 접수되었습니다. (REVIEW / Review)" 안내와 '새로 등록하기' 버튼만 나온다.
  - 즉시 게시가 아니라 **검토 대기(REVIEW)** 로 접수된다.
  - 지식 상세 링크가 없어 `result_path`(주소가 바뀌어야 함)·`result_link`(링크 요소)는 쓸 수 없다.
- 결정: 결과 확인 방법 `result_message`를 새로 두고 `"text=등록 요청이 접수되었습니다"`(화면에 보인 글자)로 확인한다.
  - 안내가 30초 안에 보이지 않으면 지금처럼 '결과 확인 못 함'으로 멈추고 다시 보내지 않는다(중복 방지).
  - 업무에 남기는 링크는 지식 상세가 없으므로 G-Knowledge 첫 화면 주소로 한다. '내 지식' 화면으로 바꾸는 안은 적용하지 않기로 했다(사용자 결정 2026-11-16).
- 분석 완료 판단 보강(사용자 요청): 결과 제목 칸(`#c-title`)이 보인 뒤 **글자가 들어올 때까지** 기다린다.
  - 두 대기를 합쳐 60초 안이다. 넘으면 등록요청 전이므로 보내지 않는다.



- `tests/unit/test_gknowledge_two_step.py`: 기본 설정은 결과 주소만 비어 있음, 미설정 이름 안내·브라우저 미실행, 분석 완료 표시 필수, 2단계 순서(결과 칸 미수정), 분석 시간 초과 시 미전송, 본문 미입력 시 미전송, 편집기 줄바꿈 차이 허용.
- 추가: 결과 제목 빈 값이면 미전송, 분석 대기는 남은 시간만 사용, 같은 주소에서 접수 안내로 성공, 접수 안내가 없으면 '확인 못 함'·재전송 없음.
- 기존 `tests/unit/test_gknowledge.py`(1단계 흐름·결과 확인·중복 방지)는 그대로 통과한다.
