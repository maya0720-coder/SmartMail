# 0009. 메일 자동 수집: 처음 30일 + 증분 + 기간 지정

- 날짜: 2026-11-12
- 상태: 승인(사용자 요청)
- 관련 요구사항: MAIL-04 (연관: TODO-01·04·05, RET-01)

## 배경

기존 MAIL-04는 "기간 지정 수집(기본: 주간보고 주기) + 수동 새로고침"이었다. 사용자는 화면에서 '메일 수집(이번 주)'을 눌러야 했다. 사용자가 다음과 같이 바꿔 달라고 요청했다.

- 처음 실행하면 실행일 기준 30일을 자동으로 수집한다.
- 이후 새로 온 메일은 자동으로 반영한다.
- 그 밖의 기간은 수동으로 지정해 따로 수집한다.

## 결정

1. 자동 수집 기준 시각(커서)을 `sync_state` 테이블에 저장한다. 시각 값만 저장하고 메일 내용은 저장하지 않는다.
2. 처음 실행할 때(커서 없음)는 `now − SMARTMAIL_MAIL_INITIAL_DAYS`(기본 30일)부터 `now`까지 수집한다.
3. 그 다음부터는 `커서 − 1시간`부터 `now`까지 수집한다.
   - 1시간을 겹치는 이유: 아웃룩 캐시 모드에서 늦게 동기화된 메일을 놓치지 않기 위해서다.
   - 겹친 구간의 메일은 Message-ID 고유 인덱스로 걸러진다.
4. 수집이 성공했을 때만 커서를 옮긴다. 아웃룩을 쓸 수 없으면 다음 주기에 같은 구간을 다시 읽는다.
5. 앱을 시작할 때 1회 자동 수집하고, 이후 `SMARTMAIL_MAIL_SYNC_MINUTES`분(기본 10분)마다 자동 수집한다. 값이 0이면 시작할 때만 자동 수집한다.
6. 수동 기간 지정은 시작일~종료일(포함, KST)을 받는다. 이 수집은 커서를 바꾸지 않는다.
   - 상한은 366일이다.
   - 시작일과 종료일이 역순이거나 종료일이 미래이면 거부한다.
7. 자동 수집과 화면 버튼이 동시에 수집하지 않도록 잠금을 둔다. 수집과 업무 반영을 한 번에 하나만 실행한다.
8. '로컬 데이터 전체 삭제'를 하면 커서도 지운다. 다음 수집은 다시 최근 30일부터 읽는다.

## 영향·한계

- 처음 실행할 때 30일치 메일에서 업무 제안이 한꺼번에 생길 수 있다.
  - 사용자는 '제안된 업무'에서 승인하거나 무시한다.
  - 아웃룩 폴더별 읽기 상한(5,000건)은 그대로 둔다.
- 업무가 완료되고 7일이 지나 삭제된 뒤(RET-01), 같은 기간을 수동으로 다시 수집하면 해당 스레드가 새 제안으로 다시 나올 수 있다. 무시하면 된다.
- 자동 수집은 앱이 실행 중일 때만 동작한다. 앱을 꺼 둔 기간은 다음 실행 때 커서부터 읽어서 채운다.
