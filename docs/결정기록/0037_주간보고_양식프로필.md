# 0037 조직별 주간보고 양식 프로필·지난주 이월·마감 알림

- 날짜: 2026-11-17
- 상태: 구현 완료(가짜 위키로 검증). 실제 위키에서 본문 선택자와 내 영역 머리글 구조 1회 확인 필요
- 관련 요구사항: WIKI-01~06(이번 변경은 WIKI-01·02·03), 결정기록 0010·0024·0030·0034
- 근거 문서: `수정사항_20261117020320.md` N4·U5·U6(사용자 승인 2026-11-17)

## 배경(원인 W1~W3)

- W1: `ConfluenceWiki`는 양식을 한 번도 읽지 못했다. 그래서 초안이 늘 기본 양식으로 돌아갔다.
- W2: 양식에서 머리글 3개만 썼다. 표·열·고정 문구는 버렸다.
- W3: 편집기 초기 모양이 앱 기본 템플릿이었다.

## 결정

### 1. 양식 가져오기

- **브라우저 읽기(기본, 위키 링크만)**
  - `ConfluenceWiki.read_page_html`은 위키 로그인 세션(비저장 브라우저 컨텍스트)으로 페이지를 열고, 본문 영역 HTML만 가져온다(`integrations/wiki/reader.py`).
  - REST API는 쓰지 않는다.
  - 링크와 이동 후 주소는 위키 기준 주소와 출처가 같아야 한다(SSRF 방지).
  - 크기는 500KB, 시간은 30초까지다. 본문 선택자는 `config/rules/wiki_read.toml`에 있다(`#main-content`, 추정값).
  - 세션이 만료되어 로그인 화면으로 가면 '로그인 필요'로 안내한다. 화면은 `ensureLogin(["wiki"])`로 로그인한 뒤 다시 읽는다(0034).
- **붙여넣기(보조)**
  - 설정의 참고 링크 줄에서 `양식 붙여넣기`를 누르고 클립보드의 `text/html`을 붙여넣는다.
  - 붙여넣은 HTML은 화면에 그리지 않고 문자열로만 서버에 보낸다(XSS 방지). 보낸 뒤 메모리에서 지운다.

### 2. 내 영역만 구조로 저장(`domain/weekly/template_profile.py`)

- **위키에서 읽을 때**
  - 내 영역 머리글(h2, 본인 이름)을 찾아 그 아래만 쓴다.
  - 찾지 못하면 **거부**하고 붙여넣기를 안내한다. 다른 팀원 영역과 이름이 섞이지 않게 하기 위해서다.
  - 지시서는 '찾으면 그 아래만'이라고만 했다. 못 찾을 때의 처리를 이렇게 더 엄격하게 정했다.
- **붙여넣기일 때**
  - 내 영역 머리글이 있으면 그 아래만 쓴다.
  - 없으면 붙여넣은 전체를 쓴다. 이때 h1·h2 머리글은 양식 키워드(실적·계획·이슈)와 맞을 때만 남긴다. 이름일 수 있는 머리글은 버린다.
- **블록**
  - `heading(level, text)`: 단계는 3~4로 맞춘다. 내 영역 안이므로 h1·h2는 h3이 된다.
  - `table(columns, header_rows, sample_rows)`: 데이터 행은 **개수만** 센다.
  - `list(style)`: 항목 글자는 버린다.
  - `paragraph(text)`: `※`·`참고`·`단위` 등으로 시작하는 **고정 안내 문구만** 남긴다. 그 밖의 문단은 지난 보고 내용이라 버린다.
  - 글자는 마스킹한다. 머리글은 60자, 열 이름은 40자, 고정 문구는 200자까지다. 블록은 80개까지다.
- **저장**: `weekly_template_profile` 표(스키마 6)
  - 참고 링크마다 1개다. 링크를 지우면 함께 지워지고(CASCADE), 전체 삭제 대상이다.
  - 칼럼: `blocks_json`(64KB 이하), `bindings_json`, `source_hash`, `source`(wiki|paste), `fetched_at`

### 3. 칸 연결(바인딩)

- **머리글**: 데이터 원천을 고른다(금주 실적·차주 계획·이슈·고정 문구·비움).
  - 자동 제안은 `weekly_form.toml`의 키워드로 한다.
- **표 열**: 업무 필드를 고른다(업무 제목·구분·요청 부서·상태·기한·완료일·진행 요약·비고(빈칸)).
  - 자동 제안은 열 이름 규칙으로 한다. 예: 업무명·내용 → 제목, 요청 → 요청 부서, 일정·기한 → 기한, 상태·진척 → 상태.
  - 맞는 규칙이 없으면 비고(빈칸)다.
- AI 제안은 쓰지 않는다.
- 서버는 블록 번호와 종류, 열 수, 허용 값을 다시 검증한다.

### 4. 양식이 바뀌었는지 확인

- 주간보고 화면에서 양식이 등록된 링크를 고르면 `POST …/profile/check`를 부른다.
  - 위키 세션이 **이미 있을 때만** 다시 읽어 구조 지문을 비교한다. 로그인 창은 띄우지 않는다.
- 지문이 다르면 새 구조로 저장하고 "양식이 바뀌었습니다 · 연결 다시 확인"을 안내한다.
  - 같은 글자의 머리글과 같은 이름의 열은 연결을 이어받는다. 새 칸은 비움(비고)으로 둔다.

### 5. 초안과 편집기

- 프로필이 있으면 초안을 블록 순서대로 만든다.
  - 머리글에 연결된 데이터는 그 아래 첫 표(행) 또는 첫 목록(항목)에 넣는다.
  - 아래에 표·목록이 없으면 목록을 새로 만든다.
  - 업무 분류는 기존 `classify_week`와 같은 규칙이다(`classify_week_tasks`로 분리).
- 프로필이 없으면 기본 양식을 쓰고 "조직 양식이 등록되지 않아 기본 양식을 사용 중 [양식 등록]"을 보인다. 링크를 고르지 않았으면 이 안내는 숨긴다.
- **편집기**(`weekly_profile.js`)
  - 구조 잠금: 머리글과 표 머리칸은 `contenteditable=false`로 회색 표시한다. `구조 잠금 해제`로 풀 수 있다.
  - `양식과 비교`: 머리글·표 열 순서가 다른 곳을 점선으로 표시한다.
  - `양식으로 되돌리기`: 내용은 두고 머리글과 표 열 구조만 복원한다.
  - 업무 목록 버튼을 누를 때 커서가 표 안이면, 열 연결대로 표 행을 만든다.
  - 잠금 표시는 화면 속성일 뿐이다. 직렬화·서버 정리 대상이 아니다.
- **정리기**: 바꾸지 않았다.
  - 본문 전체가 이미 내 영역이다. 그래서 'h2→h3 낮춤은 내 영역 안에서만'이라는 조건을 이미 만족한다.
  - h3·h4는 그대로 둔다.
- 게시(nonce·승인·본인 영역만 갱신)와 클립보드 폴백은 그대로다.

### 6. 지난주 이월(U5, `domain/weekly/carryover.py`)

- **출처**: 지난주 내 보고를 읽는다.
  - 위키 세션이 있고 공간 키가 있으면, 지난주 제목의 페이지에서 **내 영역만** 읽는다.
  - 그렇지 않으면 게시 캐시(마스킹 사본)를 쓴다.
- '차주 계획' 항목을 이번 주 업무와 맞춰 본다.
  - 제목 포함 관계를 먼저 보고, 없으면 유사도 0.6 이상이면 같은 업무로 본다.
- **분류**
  - 완료 → 금주 실적
  - 진행·완료 후보이거나 이번 주에 메일이 오감 → 금주 실적(진행)
  - 그 밖 → 차주 계획 유지
- 사용자가 체크한 것만 편집기에 넣는다. 화면에서 색으로 구분한다(초록 완료, 노랑 진행, 회색 유지).
- 비교는 메모리에서만 한다. 지난주 내용과 결과는 저장하지 않는다.

### 7. 마감 알림(U6, `domain/weekly/remind.py`)

- **설정** `SMARTMAIL_WEEKLY_REMIND_AT`
  - 형식은 `WED 15:00`이다. 비우면 끈다. 형식이 틀리면 시작할 때 실패한다.
- 마감일이 주말·공휴일이면 직전 근무일로 앞당긴다.
  - 공휴일은 `config/rules/holidays.toml`에 있다. 기본은 비어 있고, 사내 달력으로 채워야 한다(확인 필요).
  - 지시서는 '`calendar.py`의 영업일 계산'을 쓰라고 했다. 그런데 기존 계산에 공휴일이 없어서 목록 파일을 추가했다.
- 마감이 지났는데 이번 주 게시 기록(게시 이력 또는 게시 캐시)이 없으면 모든 화면 위에 배너를 보인다.
  - 배너: `[초안 열기] [오늘 숨기기]`
  - 숨김은 서버 메모리에만 둔다. 화면은 10분마다 다시 확인한다.

### 8. 작업 센터

- `위키 양식 읽기`를 추가했다. 읽는 중·완료·실패와 사유 코드를 보여 준다(0035의 남은 항목).

## 보안·개인정보

- 양식 원본 HTML은 저장·로그하지 않는다. 구조만 저장한다.
- 테스트로 확인했다: 다른 팀원 이름·영역, 데이터 행 글자, 합성 전화번호가 DB 어디에도 남지 않는다.
- 붙여넣기 입력은 크기 제한(요청 크기 413 또는 검증 422)을 받는다. 화면은 붙여넣은 HTML을 DOM에 넣지 않는다.
- 위키 읽기는 같은 출처만 허용한다. 이동한 뒤 주소도 다시 확인한다.
- 칸 연결은 서버가 허용 목록으로 검증한다. 알 수 없는 필드는 거부한다(대량 할당 차단).
- 새 감사 이벤트 `wiki_read`를 추가했다(성공 여부만 기록).
