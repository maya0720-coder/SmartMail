# 0023 제안된 업무 요약 병렬화 · 진행률 · 페이징

- 날짜: 2026-11-15
- 상태: 구현(실제 AI-Ground 화면에서 여러 탭 동시 진행은 사용 후 확인 필요)
- 관련 요구사항: TODO-01, AI-02·03·06, 결정기록 0008·0014·0015·0018·0021

## 배경

- 제안된 업무가 많으면 요청 요약이 몇 분씩 걸리고, 사용자는 진행 상황을 알 수 없었다.
- 요약은 4건 묶음을 순차로 처리했고, 묶음마다 원본을 읽어 AI-Ground 채팅 화면에 1건씩 보냈다.
- 제안 목록은 모든 항목을 한 번에 그려 항목이 많으면 길어졌다.

## 결정

### 진행률(TODO-01)

- 요약 실행 단위로 전체 건수(`total`)와 처리 끝난 건수(`completed`)를 `SummaryState`에 두고, `/api/summaries/status` 응답에 `total`·`completed`·`percent`를 추가했다(기존 필드는 그대로).
- 처리 끝난 건수 = 성공 + 제목 유지 + 이번 실행에서 실패 처리된 것 + 원본이 없어 제목을 유지한 것. AI를 쓸 수 없어 멈춘 항목은 세지 않는다.
- 화면 상단 배너에 `role="progressbar"` 막대, 퍼센트, `완료 n / 전체 m`을 보인다(실행 중에만). 실행 중 폴링은 1초.

### 병렬 처리(AI-06)

- 방식: 서비스가 묶음을 **동시성 제한(`SMARTMAIL_SUMMARY_CONCURRENCY`, 기본 5, 1~10, 범위 밖이면 시작 시 실패)** 만큼 모아 한 번에 어댑터로 넘긴다.
- AI-Ground 어댑터는 브라우저 스레드가 1개(Playwright 동기 API 제약)라 스레드를 늘려도 직렬화될 뿐이므로, **한 번의 브라우저 작업 안에서 묶음마다 새 탭을 열어 질문을 보내고 모든 탭을 번갈아 폴링**해 답을 모은다(`ground_parallel.py`의 `run_chats`, 어댑터의 `summarize_many`).
- 탭마다 자체 마감 시각이 있어, 한 탭이 늦거나 실패해도 다른 탭의 답은 살린다. 탭은 항상 닫는다.
- 게이트웨이(`summarize_requests_many`)는 묶음마다 마스킹 타입·길이·재마스킹 검사, 답변 재마스킹, 호출 기록(성공/실패)을 단독 호출과 똑같이 거친다. AI 전송은 여전히 마스킹 타입만 받는다.
- 원본 메일 읽기(`mail.view`)는 서비스를 부르는 기존 스레드에서 미리 한다(아웃룩 COM은 `SingleThreadRunner`가 전용 스레드로 직렬 처리). AI 호출만 동시에 진행한다.
- 같은 항목을 중복 전송하지 않도록 실행 중 항목(메일 참조 ID)을 추적한다.
- 묶음 답변을 해석하지 못하면 그 묶음만 1건씩 다시 보내고, AI를 쓸 수 없으면(로그인 필요·호출 제한·시간 초과) 더 보내지 않고 멈춘다. 그때까지 끝난 묶음의 결과는 저장한다.
- Fake AI도 `summarize_many`로 실제 스레드 병렬을 흉내 내어(동시 진행 수 기록) 테스트한다.

### 한계: 호출 상한은 그대로

- **AI-Ground 사용 통제(결정기록 0008·0018·0021)는 제거·완화하지 않았다.** 연속 호출 최소 간격 3초, 10분당 20회, 그중 백그라운드(요약) 14회 상한은 어댑터의 `_reserve`가 병렬 호출에도 똑같이 적용한다.
- 병렬 호출의 질문 전송 시각은 최소 간격으로 어긋나게 잡힌다(첫 탭 이후 3초씩). 상한이 모자라면 뒤쪽 묶음은 보내지 않고 `TOO_MANY_CALLS`로 처리해 다음 실행으로 넘긴다.
- 따라서 병렬화는 **상한 안에서 답을 기다리는 시간(스트리밍 대기)을 겹치는 것**이다. 10분에 처리할 수 있는 묶음 수(백그라운드 14회 × 4건)는 늘지 않는다.
- 병렬 호출 하나가 브라우저 스레드를 답이 모두 올 때까지 차지하므로, 그동안 사용자가 누른 해결 방안 요청은 그 뒤에 대기한다(최대 동시성 × 간격 + 답변 시간).

### 본문 전처리(AI-02·03)

- `mail_text.strip_html`: HTML 본문이면 `script`·`style`·`head`·주석 블록을 내용째 버리고, 줄 구분 태그는 줄바꿈으로, 나머지 태그는 지우고, 엔티티를 풀어 AI로 보내는 글자를 줄인다. HTML이 아니면 그대로 둔다. 입력은 20만 자로 제한한다.
- 기존 인용·서명 제거와 '마스킹한 뒤 자르기' 순서는 유지한다.

### 제안 목록 페이징(TODO-01 화면)

- 목록 하단에 대시보드와 같은 페이징 UI(`.pg` · `.pg-info` · `.pager`)를 붙였다. 공용 페이저(`paginate`·`pageNumbers`·`renderPager`)는 `pager.js`로 옮겼다(동작 변경 없음).
- 페이지 크기는 목록이 패널 안에서 스크롤되므로 높이와 무관한 상수 20건(`TRIAGE_PAGE_SIZE`).
- 탭 전환 시 1페이지로, 받은 시각 묶음 머리글은 현재 페이지 항목 기준이다.
- ↑↓ 이동이 페이지 경계를 넘으면 페이지도 넘어가고, 결정(할 일로·나중에·업무 아님)으로 항목이 빠지면 다음 항목이 있는 페이지로 보정한다(범위를 벗어나지 않음).
- '나중에' 목록은 마지막 페이지 끝에만 펼친다. 빠른 정리 모드는 페이지와 무관하게 거른 전체 목록을 쓴다.
