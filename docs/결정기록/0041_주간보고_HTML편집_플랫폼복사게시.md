# 0041 주간보고 HTML 편집 탭, 플랫폼별 복사·게시

- 날짜: 2026-11-17
- 상태: 구현 완료(실제 위키·Teams·Outlook 붙여넣기 모양은 확인 필요)
- 관련 요구사항: WIKI-01·02·03·04·05·06, 결정기록 0024(참고 링크·폴백)·0030(미리보기 편집기)·0037(양식 프로필)
- 근거 문서: `수정사항_20261117072857.md` C1·C2, 결정 D1·D3(기본안 적용)

## 배경

- C1: 위키 형식 편집이 어려워 HTML을 직접 입력하고 싶다는 요청.
- C2: 위키 말고도 Slack·Teams·메일·노션 등 원하는 대상의 형식으로 복사·게시하고 싶다는 요청.

## 결정

### 1. 정리기 허용 목록 확장(D1 기본안)

`domain/weekly/rich.py` 정리기와 `static/js/weekly_editor.js`의 허용 목록을 함께 넓혔다.

| 구분 | 내용 |
|---|---|
| 추가 태그 | `h1`(h3로 낮춤), `hr`, `blockquote`, `pre`, `code`, `s`, `sub`, `sup`, `span`, `div`, `caption`, `colgroup`, `col`, `tfoot` |
| 추가 속성 | `th/td[align, valign, width]`, `col[span, width]`, `ol[start]`, 제한된 `style` |
| `style` 허용 속성 | `color`·`background-color`(16진·`rgb()`·이름 색만), `text-align`, `font-weight`, `font-style`, `text-decoration`, `width`(px·%만), `vertical-align` |
| `style` 금지 값 | `url(`, `expression`, `@import`, `javascript:`, 역슬래시, 주석(`/*`). 하나라도 있으면 style 속성 전체를 버린다. 허용 밖 속성만 있으면 그 속성만 뺀다 |
| 계속 금지 | `script`·`style` 태그, `iframe`, `object`, `embed`, `form`, `input`, `img`, `on*` 이벤트, `javascript:`·`data:` 링크, 주석·CDATA |

- `style` 값 검사는 `domain/weekly/rich_style.py`(신규)로 나눴다.
- `sanitize_report()`는 정리 결과와 함께 **버린 태그·속성의 종류별 개수**를 돌려준다. 미리보기 응답(`removed`)과 HTML 탭 경고줄 "제거됨: script 1, style 속성 3 …"에 쓴다.
- 정리 후 글자 노드마다 마스킹한다. 서식 사이에 걸친 민감정보는 거부한다(0030 규칙 유지).
- `br`·`hr`·`col`은 `<x />`로 쓴다. 정리 결과를 다시 정리해도 같다(멱등).

### 2. HTML 편집 탭(C1)

- 편집 탭: `미리보기 편집 | HTML 편집 | 간단 편집`.
- 화면 구성(`static/js/weekly_html.js` 신규):
  - 왼쪽은 코드 입력이다. 고정폭 글꼴, 줄 번호, Tab 들여쓰기, 200KB 상한.
  - 오른쪽은 실시간 미리보기다. 입력이 500ms 멈추면 갱신한다. 900px 이하에서는 위아래로 놓는다.
- 미리보기는 `POST /api/weekly/clean-html`(서버 정리·마스킹, **저장하지 않음**) 결과를 사용한다. `DOMParser`로 읽은 뒤 허용 노드만 `el()`로 다시 만든다(HTML 문자열을 직접 대입하지 않음).
  - `style`은 허용 속성만 CSSOM `setProperty`로 넣는다(CSP `style-src 'self'`와 호환).
  - CSP 때문에 `DOMParser` 문서는 style 속성을 해석하지 않는다. 그래서 속성 글자를 직접 나눠 다시 검사한다.
- 도구:
  - `[HTML 붙여넣기 정리]`: 서버 정리 결과로 바꾼다.
  - `[줄 맞춤]`
  - `[미리보기 편집으로 보내기]`
  - `[양식 HTML 불러오기 ▾]`: 양식 자동 초안 또는 미리보기 편집 내용.
- 탭 이동:
  - HTML → 다른 탭: 서버 정리 결과를 미리보기 편집으로 넣는다. 간단 편집으로 갈 때는 미리보기 편집을 거쳐 기존 목록 변환과 경고를 그대로 쓴다.
  - 다른 탭 → HTML: 미리보기 편집 내용(간단 편집이면 목록으로 만든 HTML)을 줄 맞춤해 넣는다.
- 저장: 임시 저장·자동 보관은 HTML 탭에서도 동작한다. 서버가 정리·마스킹한 결과만 저장하고, 입력 원문은 저장하지 않는다.
- 미구현: 지시서의 `[양식 HTML 불러오기]` 중 '지난주 보고 불러오기'의 HTML 버전은 만들지 않았다. 지난주 보고는 기존 `[지난주 내 보고 불러오기]`(미리보기 편집)를 쓴 뒤 HTML 탭으로 옮기면 된다.

### 3. 복사 형식 7종(C2)

`domain/weekly/targets.py`(신규)에 형식을 정의하고, `domain/weekly/convert_formats.py`(신규)에 변환기를 뒀다.

| 형식 | 클립보드 | 게시 버튼 |
|---|---|---|
| 위키(Confluence) | `text/html`(본인 영역 HTML) + `text/plain`(위키 마크업) | 위키에 게시(직접, nonce 승인) |
| 위키 편집기용 원본 | `text/plain` = 저장 형식 XHTML | 복사하고 위키 열기 |
| Slack | `text/plain` mrkdwn(멘션 무력화) + `text/html`(굵게·목록, 표는 줄) | 복사하고 Slack 열기 |
| Microsoft Teams | `text/html`(표·굵게·목록 유지) + `text/plain` | 복사하고 Teams 열기 |
| 메일(Outlook) | `text/html`(표 테두리·글꼴 인라인 스타일) + `text/plain` | 복사하고 메일 쓰기(`mailto:?subject=`만) |
| Markdown | `text/plain` Markdown(GFM 표, `\|`·특수문자 이스케이프) | 복사하고 링크 열기 |
| 일반 텍스트 | `text/plain` | 복사 |

- 변환기는 `CleanHtml` 타입만 받는다. 이 타입은 `clean_html()`(정리·마스킹·걸친 민감정보 거부)만 만들 수 있게 잠가 두었다. 따라서 마스킹을 빠뜨린 입력은 코드에서 막힌다(하네스 규칙 5).
- 참고 링크 플랫폼에 `teams`·`mail`·`markdown`을 추가했다(`detect_platform`, 정확한 도메인 또는 하위 도메인만). DB CHECK 확장은 스키마 8에서 한다.
  - 표 재생성 방식이다. 외래 키 검사를 재생성 동안만 끄고, 마친 뒤 `foreign_key_check`로 확인한다.
  - 기존 행은 보존한다.
- 참고 링크를 고르면 그 플랫폼의 기본 형식으로 맞춘다. `[게시 대상 ▾]`에서 바꿀 수 있다.
- `[복사]`: 한 번에 `text/html` + `text/plain`을 넣는다. 실패하면 선택 복사를 쓰고, 그것도 안 되면 수동 복사 칸을 보여 준다(현행 유지).
- `[복사 미리보기]`: Slack·Markdown·텍스트는 글자 그대로 보여 준다. 위키·Teams·메일은 허용 노드만 다시 만든 HTML로 보여 준다.

### 4. 게시 흐름

- 모든 형식이 같은 흐름이다: `미리보기 확인(nonce) → 승인 → 게시`. 승인 전에는 게시 버튼이 꺼져 있다.
- 직접 게시는 **위키 형식만** 한다(`DeliveryTarget.direct`). 위키 편집기 원본은 위키 대상이지만 복사형이다.
- 그 밖의 형식은 승인 후 '복사 + 대상 열기'로 처리한다. 결과는 게시 캐시(`weekly_publish_cache`, 방식 `clipboard`, 마스킹 사본, 본인 이름 머리글 제외)에 남긴다.
- 메일은 `mailto:?subject=<페이지 제목>`만 연다. 받는 사람·본문은 넣지 않는다. 앱에는 메일을 보내는 기능이 없다.
- 같은 주·같은 대상에 게시한 캐시가 있으면 다시 게시할지 묻는다.
- `format`을 보내지 않는 기존 호출은 이전 동작(링크 플랫폼 기준)을 그대로 따른다.

### 5. Slack·Teams 직접 게시(D3 기본안)

- 웹훅·API 직접 게시는 외부 SaaS 전송이다. 개발지침 4장과 기획서 5장에 따라 만들지 않았다.
- `PublishTarget` 인터페이스(`domain/weekly/targets.py`)와 `FakePublishTarget`(`integrations/publish/fake.py`, 메모리 기록만)만 두었다. 앱 조립에는 연결하지 않았다(테스트로 확인).
- 정보보안 승인 뒤 설정으로 켤 어댑터를 붙인다.

## 영향

- API:
  - `POST /api/weekly/clean-html`, `GET /api/weekly/formats` 추가.
  - `POST /api/weekly/convert`·`publish`에 `format`(선택) 추가.
  - `preview` 응답에 `removed` 추가. `publish` 응답에 `format`·`mailto` 추가.
- 스키마 8: `weekly_link`·`weekly_publish_cache`의 platform CHECK를 확장했다. 기존 DB는 처음 열 때 자동으로 옮긴다.
