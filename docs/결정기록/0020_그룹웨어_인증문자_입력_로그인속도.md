# 0020 그룹웨어 인증문자 입력 · 로그인 속도 개선

- 날짜: 2026-11-13
- 상태: 구현(실제 그룹웨어 인증문자 화면 동작 확인 필요)
- 관련 요구사항: AUTH-01·03·05·09, 결정기록 0017·0019

## 배경

- 그룹웨어가 인증문자(OTP)를 요구하면 자동 로그인이 바로 실패하고, 앱 안에서는 로그인할 방법이 없었다(결정기록 0017·0019).
- 사용자 의견: 사이트 로그인 속도가 너무 느리다.

## 결정

### 1. 인증문자를 앱 화면에서 받아 입력(우회 아님)

- 암호를 제출한 뒤 인증문자 입력칸(`login_fields.toml [groupware] otp_input`)이 보이면, 시작 로그인 창에 번호 입력칸을 띄운다.
- 사용자가 입력한 번호를 `POST /api/login/otp`로 받아, 로그인 중인 브라우저 흐름에 넘기고 그룹웨어 입력칸에 넣은 뒤 Enter로 제출한다.
- 번호가 틀렸거나(알림창) 10초 동안 화면이 그대로면 다시 묻는다. **최대 3번**까지만 제출하고, 취소·시간 초과(로그인 대기 180초)·3번 실패는 "인증문자 확인을 완료하지 못했습니다"로 따로 안내한다.
- 번호는 메모리(`LoginProgress`)에서 흐름이 꺼내 가는 즉시 지운다. 저장·로그·응답에 넣지 않는다. 화면 입력칸도 전송 직후 비운다.
- 기다리는 중이 아니면 번호를 받지 않는다(409). 형식은 영문·숫자 4~12자만 받는다. 주소(쿼리)로는 받지 않는다. CSRF·Origin 검사는 기존 미들웨어를 그대로 적용한다.
- 암호는 여전히 한 번만 제출한다(계정 잠금 방지).

### 2. 로그인 속도

브라우저 자동화는 Playwright 동기 API 제약으로 전용 스레드 1개에서 사이트를 차례로 처리한다. 이 구조는 유지하고, 각 단계의 고정 대기를 줄였다.

- 회사 계정 로그인: 버튼을 누른 뒤 **무조건 2초** 쉬던 것을, 누른 화면 요소가 사라지면 바로 다음 단계로 가도록 바꿨다(최대 2초). 이메일·암호·'로그인 상태 유지' 단계마다 시간이 준다.
- 상태 확인 간격 0.5초 → 0.25초.
- 사이트 열기: 이미지 등 모든 리소스를 기다리는 `load` 대신 문서 준비(`domcontentloaded`)에서 진행한다. 그룹웨어는 이 때문에 아이디 칸이 나타날 때까지 최대 10초를 기다린 뒤 입력한다(다른 호스트·로그인 화면이 아니면 입력하지 않는 규칙 유지).

### 3. 추가 보강(같은 날, "입력 화면이 나오지 않음" 신고)

실제 화면을 볼 수 없어 원인을 하나로 확정하지 못했다. 아래 후보를 모두 막았다.

- 인증번호 발송 알림창이 입력칸보다 먼저 뜨면 '암호 틀림'으로 끝냈다 → 알림창 글자에 인증번호·인증문자·OTP·SMS가 있으면 인증 안내로 보고 '확인'을 누른다. 글자는 판별에만 쓰고 저장·기록하지 않는다.
- 발송 확인창을 '취소'로 닫았다 → 인증 안내 확인창은 '확인'을 누른다.
- `#txtM_LoginOTP`(모바일용 숨은 칸)만 보거나 같은 이름의 숨은 칸이 먼저 잡혔다 → id·name에 otp가 들어간 **보이는** 입력칸을 쓴다(`:visible`, 로컬 Chromium으로 동작 확인).
- 인증 화면 주소에 login이 없으면 로그인 성공으로 오인했다 → 인증 입력칸이 보이면 주소와 관계없이 로그인 전으로 본다.
- 실패하면 로그 파일에 화면 구조(주소 경로, 보이는 입력칸·버튼의 태그·type·id·name, 프레임 수, 알림창 횟수)만 남긴다. 입력값·화면 글자·쿼리 문자열은 남기지 않는다(결정기록 0010과 같은 기준). 다음에도 실패하면 이 로그로 실제 선택자를 정한다.

## 확인 필요(실제 화면)

- 인증문자 입력칸이 `#txtM_LoginOTP`가 맞는지, PC 화면용 칸이 따로 있는지.
- 번호 제출을 Enter로 하는지(암호처럼 버튼이 화면 없는 브라우저에서 눌리지 않는지).
- 번호가 틀렸을 때 알림창이 뜨는지, 번호 자릿수·형식.
- 사이트별 실제 소요 시간. 여전히 느리면 사이트별 소요 시간을 재서 병목을 확인한다. 사이트를 동시에 로그인하려면 브라우저 실행 구조 변경(스레드별 Playwright 또는 비동기 API)이 필요하다.
