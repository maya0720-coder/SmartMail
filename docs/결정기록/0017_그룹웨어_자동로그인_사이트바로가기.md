# 0017 그룹웨어 자동 로그인 · 연결 상태 칩 사이트 바로가기

- 날짜: 2026-11-13
- 상태: 구현 완료(실제 그룹웨어 로그인은 사용자 수동 점검 필요)
- 관련 요구사항: AUTH-01·03·09, MAIL-02(수집은 보류 유지)

## 배경

- 그룹웨어는 로그인 어댑터가 없어 로그인할 수 없었다("연동 규격 확인 필요").
- 사용자 요청(2026-11-13)
  - 그룹웨어 로그인이 되게 한다. 그룹웨어 ID는 `@golfzon.com` 없이 아이디만 넣는다.
  - 화면의 로그인 상태 표시를 누르면 해당 사이트로 이동한다.

## 확인한 로그인 화면(2026-11-13, 계정 입력 없이 구조만 확인)

| 항목 | 내용 |
| --- | --- |
| 로그인 방식 | 자체 로그인 화면 `/WebSite/Login.aspx`(회사 계정 SSO 아님) |
| ID 칸 | `#txtPC_LoginID` |
| 암호 칸 | 자리표시 칸 `#txtPC_LoginPWTemp`를 누르면 실제 칸 `#txtPC_LoginPW`로 바뀐다 |
| 제출 | 로그인 버튼이 화면 없는 브라우저에서 눌리지 않아 암호 칸에서 Enter로 제출한다 |
| 추가 인증 | OTP 입력 칸이 화면에 있다(사용 조건은 확인하지 못함) |

## 결정

1. **자동 로그인**: 위키와 같은 방식으로 별도 비저장 컨텍스트에서 로그인 화면을 채운다(`security/login_flows.py::run_groupware_login`, `security/site_login.py::GroupwarePasswordAuthenticator`). 화면 요소는 `config/rules/login_fields.toml`의 `[groupware]`에서 관리한다.
2. **입력값**: 시작 로그인 창의 아이디에서 `@도메인`을 뺀 값 + 공통 암호를 쓴다. 위키 전용 암호는 그룹웨어에 쓰지 않는다.
3. **일괄 로그인 대상**에 그룹웨어를 넣는다(`app/routes/login_all.py`).
4. **성공·실패 판정**
   - 성공: 같은 사이트(https·같은 호스트)에서 주소 경로가 로그인 화면을 벗어남.
   - 실패: 알림창이 뜸 / OTP 화면이 나옴 / 10초 뒤에도 로그인 화면에 머묾 / 60초 초과.
   - 암호는 한 번만 제출한다(계정 잠금 방지). 다른 호스트나 http로 넘어가면 아무것도 입력하지 않는다.
   - 알림창 글자는 읽지 않고 닫기만 한다(로그·응답에 남기지 않음).
5. **상태 칩 바로가기**: `GET /api/connections`가 사이트 주소(`url`)를 함께 내려주고, 상단 상태 칩과 설정 화면의 사이트 이름을 새 탭 링크로 만든다.
   - 주소는 설정(`SMARTMAIL_*_BASE_URL`)에서 검증한 https 주소다(자격증명·쿼리 문자열 없음).
   - `rel="noopener noreferrer"`로 연다. 화면 도우미 `el()`이 https 주소만 링크로 만든다.

## 위험·확인 필요

- **성공 판정은 가정이다.** 로그인 후 이동하는 주소를 실제 계정으로 확인하지 못했다. 로그인에 성공했는데 실패로 나오면 `login_path_marker`를 고친다.
- **OTP**: OTP가 요구되는 계정·환경에서는 자동 로그인이 실패한다. 이때는 `SMARTMAIL_BROWSER_LOGIN_SITES`에 `groupware`를 넣어 직접 로그인 방식을 쓴다(단, 자동 로그인 어댑터가 있으면 자동 로그인을 우선하므로 별도 조정이 필요하다 — 확인 후 결정).
- **실패 안내 문구**: 일괄 로그인 응답은 실패 사유를 구분하지 않고 "입력 내용을 확인해 주세요"로 통일한다(기존 정책). OTP 때문에 실패해도 같은 문구가 나온다.
- **메일 수집은 여전히 보류다.** 그룹웨어 메일함 화면 구조를 확인하지 못해 `collectors/groupware.py`는 로그인 여부만 확인한다. 현재 메일은 클래식 아웃룩으로 수집한다.
- **바로가기로 연 사이트는 따로 로그인해야 한다.** 앱의 로그인 세션은 화면 없는 비저장 브라우저 안에만 있어, 사용자의 평소 브라우저와 공유되지 않는다(세션을 넘겨주지 않는 것이 보안상 의도한 동작이다).
- 회사 계정 암호를 앱이 다루는 점은 결정기록 0011과 같다. 운영 전환 전에 정보보안 담당자의 확인이 필요하다.
