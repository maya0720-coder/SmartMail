# 0011. 연계 사이트 일괄 자동 로그인 + 위키 제목 규칙 화면 설정

- 날짜: 2026-11-12
- 상태: 구현 완료(실제 사이트 로그인은 사용자 수동 점검 필요)
- 관련 요구사항: AUTH-01·02·03·05·09, WIKI-02

## 배경

사용자 요청:
- 연계 사이트(AI-Ground, G-Knowledge, 위키)의 로그인 정보를 한 화면에서 입력하면 앱이 모든 사이트에 자동으로 로그인한다.
- 이미 세션이 있으면 다시 묻지 않는다.
- 로그인 정보는 어디에도 저장하지 않고 삭제한다.

기존 AUTH-09는 다음과 같았다. 이번 요청은 이와 다르므로 기획서를 개정한다.

> SSO 사이트는 사이트 로그인 화면을 직접 띄우고, 앱은 입력값을 받지 않는다.

## 확인한 로그인 방식(2026-11-12, 로그인 안 된 새 브라우저로 확인)

| 사이트 | 로그인 방식 |
| --- | --- |
| AI-Ground | Microsoft Entra ID(회사 계정) |
| G-Knowledge | Microsoft Entra ID(회사 계정, AI-Ground와 같은 테넌트) |
| 위키(Confluence DC) | 자체 로그인 화면 `/login.action`(ID·암호). 로그인하지 않으면 페이지를 읽을 수 없음 |

## 결정

1. **입력 화면**: 설정·연결 화면의 '사이트 일괄 로그인'에서 받는다.
   - 회사 계정(이메일·암호)과 위키 계정(ID·암호)을 받는다.
   - '위키 암호가 회사 계정 암호와 같음'을 선택할 수 있다.
   - 로그인이 필요한 계정만 묻는다.
2. **자동 입력**: 사이트 로그인 화면 자동 입력(`security/login_flows.py`, `security/site_login.py`)
   - 화면 없이(headless) 비저장 컨텍스트에서 로그인 화면을 채운다.
   - 화면 요소는 `config/rules/login_fields.toml`에서 관리한다.
   - 회사 계정 화면 흐름: 이메일 → 암호 → (2단계 인증) → '로그인 상태 유지?'에서 **아니요**(세션을 남기지 않음).
   - 2단계 인증 번호가 나오면 화면에 "Authenticator에서 번호 NN 승인"으로 안내한다(`GET /api/login/progress`, 번호만 노출).
3. **SSO 공용 컨텍스트**
   - 회사 계정 사이트 2개는 브라우저 컨텍스트 1개를 함께 쓴다. 한 사이트에 로그인하면 다른 사이트는 SSO로 입력 없이 연결된다.
   - 사이트별 세션은 '임대'로 나눠 준다. 모든 임대가 닫힐 때(로그아웃·유휴 만료·종료) 컨텍스트를 닫는다.
4. **기존 세션 재사용**
   - 이미 로그인된 사이트는 건너뛴다.
   - 회사 계정 사이트가 하나라도 로그인돼 있으면 회사 계정 입력을 묻지 않는다.
   - 다른 화면에서 로그인이 필요할 때도 먼저 SSO 연결을 시도한다.
5. **자격증명 처리**
   - JSON 본문 → 즉시 bytearray → 사이트별 사본을 넘긴다.
   - 사본은 LoginService가, 원본은 API가 0으로 덮어쓴다.
   - 화면 입력칸은 전송 직후 비운다. 자동완성은 끈다.
   - DB·파일·로그·응답에는 넣지 않는다. 기존 AUTH-10 테스트로 검증한다.
   - 한계(결정기록 0005와 같음): 요청 파싱과 브라우저 입력 단계에서 Python 문자열 사본이 잠시 생긴다. 이 사본은 덮어쓸 수 없고, 참조를 끊어 GC에 맡긴다.
6. **대안 유지**: 자동 로그인이 실패하는 사이트는 `SMARTMAIL_BROWSER_LOGIN_SITES`로 '사이트 로그인 화면 직접 열기' 방식을 계속 쓸 수 있다. 다만 자동 로그인 어댑터가 있는 사이트는 자동 로그인을 우선한다.
7. **제목 규칙**
   - 위키 주간보고 제목 날짜 기본값을 목요일(주 시작일)로 바꾼다(사용자 결정).
   - 실제 위키의 최근 제목은 대부분 금요일 날짜였다(결정기록 0010).
   - 제목 형식과 날짜 기준 요일은 설정 화면에서 바꿀 수 있다. 저장은 `app_setting` 테이블에 하고, 허용된 이름만 받는다.
   - 입력 검증: 1~60자, 날짜 변수 허용 목록, 일(日) 변수 필수, 한글·영문·숫자·공백·`_-.()`만 허용

## 보안 검토 반영(2026-11-12)

| 항목 | 조치 |
| --- | --- |
| M1 공용 SSO 컨텍스트가 한 사이트 로그아웃 뒤에도 남음 | 회사 계정 사이트 중 하나라도 로그아웃·유휴 만료되면 공용 컨텍스트 전체를 폐기한다. 닫힌 세션은 '로그인됨'으로 보이지 않는다. |
| M2 세션 잠금을 쥔 채 브라우저를 닫음, 닫기 실패를 성공으로 처리함 | 잠금 밖에서 닫는다. 닫기에 실패하면 원본을 남겨 두었다가 종료 시 다시 닫는다. |
| M3 닫힌 컨텍스트로 세션을 발급하는 경쟁 조건 | 닫힌 컨텍스트에는 임대를 발급하지 않는다(예외). |
| M4 같은 회사 계정 암호를 여러 번 제출함(계정 잠금 위험) | 암호는 1회만 제출한다. 첫 사이트가 실패하면 두 번째 사이트는 시도하지 않는다. 시도 횟수 제한은 계정 단위로 센다. |
| M5 `.env.example`에 실제 사내 주소가 있음 | 이번 변경 전부터 있던 값이다. 사용자 확인 후 placeholder로 바꾼다(보류). |
| M6 결정기록 누락 | 이 문서로 반영했다. |
| L1 위키 입력 전 호스트를 확인하지 않음 | https이면서 같은 호스트일 때만 입력한다. |
| L2 잘못된 유니코드 입력 시 버퍼를 지우지 못함 | 변환을 try 안으로 옮겨 400으로 응답하고 버퍼를 지운다. |
| L4 SSO 시도 예외를 모두 삼킴 | 입력이 필요한 경우만 조용히 넘기고, 그 밖의 오류는 실패 이벤트로 기록한다. |
| L5 빈 위키 입력과 SSO 시도가 시도 횟수를 소모함 | 빈 위키 입력은 시도 횟수를 쓰지 않는다. SSO는 요청한 사이트(`only`)로만 한정한다. |
| L3·L6·L7·L8·L9 | 남은 한계로 둔다. Playwright 오류 원문 연결, 계정 선택 화면에서 첫 계정을 누름, 2단계 인증 상태가 전역 1개, 브라우저 암호 저장 제안(수동 점검 필요), 미리보기 후 제목 규칙을 바꿀 때의 승인 제목. |

## 위험·확인 필요

- 회사 SSO 암호를 앱이 다룬다. 파일럿 범위에서 사용자가 승인했다. 운영 전환 전에 정보보안 담당자의 확인이 필요하다.
- Microsoft 로그인 화면이 화면 없는 브라우저나 자동화를 막거나, 화면 요소 id가 바뀔 수 있다. 이때는 `login_fields.toml`을 고치거나 직접 로그인 대안을 쓴다.
- 2단계 인증 화면(번호 일치·승인 대기)과 '로그인 상태 유지' 화면의 요소 id는 Microsoft 공개 로그인 화면의 일반적인 id를 썼다. 이 테넌트에서는 아직 확인하지 않았다. 첫 로그인 때 확인한다.
- 위키 ID가 회사 이메일과 같은지는 확인하지 않았다. 사용자가 직접 입력한다.
