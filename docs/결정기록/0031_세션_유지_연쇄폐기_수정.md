# 0031 자동 로그아웃 원인 수정과 앱 실행 중 세션 유지

- 날짜: 2026-11-16
- 상태: 구현(실제 사이트에서 1시간 이상 사용 확인 필요)
- 관련 요구사항: AUTH-02·03·05·06·08, 수정사항 R6(기본값 D2)

## 배경 — 확인한 원인

- **C1**: 회사 계정(Entra) 공용 브라우저를 쓰는 사이트들이 각자 30분 유휴 시계를 가졌다. 한 사이트만 쓰면 나머지가 만료됐고, 공용 컨텍스트도 함께 닫혀 쓰던 사이트까지 끊겼다.
- **C2**: 한 사이트를 다시 로그인하면 이전 세션 항목을 `close()`했다. 이때 같은 공용 컨텍스트가 닫혀 다른 사이트가 연쇄로 로그아웃됐다.
- **M1**: 사용자는 왜 끊겼는지 알 수 없었다. 종료 이유가 기록되지 않았다.
- **H4**(추정): 사이트 자체의 세션 만료는 실제로 호출하기 전까지 알 수 없었다.

## 결정

1. **묶음 유휴 시계**: 같은 공용 컨텍스트(`SharedLease.group`)를 쓰는 사이트는 하나를 쓰면 모두 사용 시각이 갱신된다.
2. **재로그인 시 분리**: 같은 묶음의 이전 항목은 `detach()`한다(공용 컨텍스트는 닫지 않음). 종료 이유는 `REPLACED`로 남긴다.
3. **앱 실행 중 유지**(D2):
   - `SMARTMAIL_SESSION_KEEP_WHILE_RUNNING=true`(기본)이면 유휴 만료를 하지 않는다.
   - 세션은 메모리에만 있고, 앱 종료 때 모두 폐기한다(`APP_STOP`). 디스크에는 저장하지 않는다.
4. **종료 이유**(`EndReason`): `IDLE_TIMEOUT`·`CASCADE`·`REPLACED`·`SITE_EXPIRED`·`LOGOUT`·`APP_STOP`.
   - 로그 형식은 `disconnect … reason=…`이다. 토큰·쿠키·주소는 남기지 않는다.
   - `/api/connections`가 이유를 돌려준다.
   - 예상치 못한 종료면 화면에 '다시 로그인' 알림을 띄운다.
5. **연결 확인**(`security/keepalive.py`):
   - `SMARTMAIL_SESSION_KEEPALIVE_MINUTES`(기본 15, 0이면 끔) 간격으로 AI-Ground·G-Knowledge 화면을 열어 로그인 표시를 확인한다.
   - 다른 호스트(SSO)로 넘어가면 `SITE_EXPIRED`로 정리한다.
   - 확인에 실패했거나 결과가 모호하면 세션을 유지한다.
   - 요약 작업 중이면 건너뛴다.
   - 확인은 유휴 시계를 갱신하지 않는다.
   - 데모 모드에서는 만들지 않는다.

## 보안 영향

- 유지 시간이 길어져, 앱이 켜진 PC를 다른 사람이 쓰면 로그인된 사이트에 접근할 수 있다. 로컬 127.0.0.1 바인딩·CSRF는 그대로다.
- 이 위험이 문제가 되는 환경에서는 `KEEP_WHILE_RUNNING=false`로 기존 유휴 규칙을 쓴다.

## 남은 한계

- 위키·그룹웨어는 로그인 표시(marker)가 없어 연결 확인 대상이 아니다.
- H4가 실제 원인인지는 실사용 1시간 이상 로그로 확인해야 한다.

## 검증

- `tests/unit/test_session_keep.py`: C1(묶음 유지·함께 만료), C2(재로그인 시 공용 컨텍스트 유지), M1(로그아웃 시 묶음 폐기), 8시간 유지, 유지 끔, 연결 확인(만료 감지·실패 시 유지·작업 중 건너뜀·시계 비갱신), 종료 이유 로그에 비밀값 없음.
