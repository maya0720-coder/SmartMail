# 0022 상세 패널 가운데 원본 메일 · 상태 색 세분화 · 업무 구분 배지

- 상태: 구현

## 배경

- 원본 메일이 '내 할 일' 목록 아래(좌측 하단)에 떠서 목록 높이를 줄이고, 상세 패널과 시선이 나뉘었다.
- 상태 배지는 '완료'(녹색)·'진행 중'(파랑) 외에는 회색·주황이 겹쳐 구분이 어려웠다(제안됨·대기 같은 색, 보류는 색 없음).
- 업무 구분(전자결재·일반업무)이 같은 회색 태그라 한눈에 나뉘지 않았다.

## 결정

### 1. 원본 메일을 상세 패널 가운데로

- 좌측 하단 메일 영역(`#mail-pane`)을 없앴다. 목록은 그만큼 행이 늘어난다(페이지 크기는 기존 계산 그대로).
- 상세 패널 순서: 배지·제목·정보 표·AI 요약 → **작업 버튼 행(원본 보기·유사 이력·AI 해결 방안)** → 검색·해결 방안 결과 → **원본 메일(제목·보낸 사람·수신 일시·본문)** → 하단 고정 상태 버튼.
- 메일 영역은 남은 높이를 채우고 본문만 안에서 스크롤한다. 남은 높이가 작으면 최소 높이(220px)를 지키고 상세 본문이 스크롤한다. 위쪽 항목은 줄어들지 않게 했다(제목·정보 표 잘림 방지).
- '원본 보기' 버튼은 가운데 영역 보이기/숨기기 토글이다(`aria-pressed`·`aria-expanded`·`aria-controls`, 글자 '원본 보기'/'원본 숨기기'). 숨긴 메일은 화면 갱신 때 다시 펼치지 않는다(기존 ✕ 닫기와 같은 규칙).
- 원문 비저장 원칙(MAIL-08) 유지: 열 때 원본에서 읽고, 보고 있는 업무의 메일 1통만 브라우저 메모리에 두며 다른 업무를 고르면 지운다. 서버·브라우저 저장소에 넣지 않는다.
- 좁은 패널(280~339px)에서 도구 버튼을 한 줄에 둘씩 놓아 메일 자리를 늘렸다.

### 2. 상태 색

| 상태 | 계열 | 배경·글자·점 토큰 |
|---|---|---|
| 제안됨 | 보라 | `--st-sug*` |
| 대기 | 슬레이트 | `--st-wait*` |
| 진행 중 | 파랑 | `--st-prog*` |
| 완료 후보 | 청록 | `--st-cand*` |
| 완료 | 녹색 | `--st-done*` |
| 보류 | 주황 | `--st-hold*` (새 배지 `.b-hold`) |

- 토큰은 `static/css/status.css`에 두고 다크 모드 값을 따로 정의했다. 상태 도넛·범례 색도 같은 점 색을 쓴다.

### 3. 업무 구분 배지

- 전자결재: 인디고 + 결재 문서 아이콘(`i-file-check`). 기본 구분(목록 첫 항목, 기본값 일반업무): 에메랄드 + 가방 아이콘(`i-briefcase`). 그 밖의 사용자 정의 구분: 웜그레이.
- 어느 구분이 전자결재·기본인지는 서버 설정(`GET /api/task-categories`의 `approval_category`·첫 항목)으로 정한다. 읽지 못하면 기본값으로 그린다.
- 표(구분 열·좁을 때 보조 줄)와 상세 패널 배지에 같은 부품(`task_badges.js` `categoryTag`)을 쓴다.

## 영향·한계

- 서버 API·DB 변경 없음.
- 제안된 업무 화면의 구분 칩(`.tchip.cat`)은 이번 범위(표·상세 패널) 밖이라 기존 색을 유지한다.
- 기본 폭(320px)·높이 900px 화면에서는 메일 본문 일부가 상세 본문 스크롤 아래에 걸친다. 패널 폭을 넓히면(분할선) 더 많이 보인다.
