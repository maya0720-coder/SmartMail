# 0010. 사내 사이트 화면 구조 확인 결과(AI-Ground·G-Knowledge·위키)

- 날짜: 2026-11-12
- 상태: AI-Ground 적용 완료 / G-Knowledge·위키 사용자 확인 대기
- 관련 요구사항: AI-01·05, GK-03·04, SRCH-02, WIKI-02~05

## 확인 방법

- 비저장 브라우저(시크릿과 같음)를 화면이 보이게 띄우고, 사용자가 직접 SSO 로그인했다.
- 입력칸·버튼의 구조 정보(태그, id, class, 짧은 표시 글자)만 읽었다. 쿠키와 입력값은 읽지 않았다.
- 화면 자동화는 파일럿 범위에서 사용자가 승인했다(2026-11-12).

## AI-Ground (적용 완료)

- 로그인: Microsoft Entra ID SSO
- 확인한 선택자: `aiground_fields.toml`에 반영
  - 입력칸 `#messageInput`, 전송 `#chatForm button.send`, 새 대화 `#historyNewChat`
  - 답변 `article.message.assistant .chat-text`, 완료 표시 `.message-meta`
- 확인용으로 개인정보가 없는 테스트 질문 1건을 보냈다("확인"이라고만 답해 달라는 질문).
- 참고: 화면에 'CLI API 키' 메뉴가 있다. 공식 API가 있다면 화면 자동화보다 안정적이므로, 운영 전환 시 검토한다(확인 필요).

## G-Knowledge (구조 확인, 적용 전 사용자 확인 필요)

등록 화면 `/knowledge/new`는 2단계로 되어 있다.

1. 작성
   - 제목 `#title`
   - 본문: Quill 편집기 `.ql-editor`(contenteditable)
   - 'AI 분석' 버튼 `#analyze-btn`
2. 확인
   - AI 분석 결과 칸이 나타난다: `#c-title`, `#c-summary`, `#c-content`, `#c-department`, `#c-category`, `#c-keywords`
   - '등록요청' 버튼 `#confirm-btn`

기존 어댑터는 '제목·본문 입력 → 등록 버튼'의 1단계를 가정했다. 그래서 흐름을 바꿔야 한다. 또 등록 후 이동하는 주소(`result_path`)는 실제로 1건을 등록해야 확인할 수 있다.

## 위키 (구조 확인, 적용 전 사용자 확인 필요)

- 위키 종류: Confluence Data Center
- REST API: SSO 세션 쿠키로 `/rest/api/content` 읽기가 된다(200). 쓰기는 아직 확인하지 않았다.
- 페이지 위치: 분기 부모 페이지(예: `ERP_2026_4Q`) 아래에 주차별 하위 페이지가 있다.
- 제목 날짜: 최근 8개 중 7개가 금요일이다(`ERP_261113` = 2026-11-13 금). 기존 설정(목요일 시작 + 1일 = 금요일)과 같다.
- 본문 양식: 사람별 제목(h2) 구조가 아니라 **팀 공용 표 1개**다.
  - 열: `구분 | 업무 내용 (금주) | 차주 | 비고`
  - 행: 업무 구분(예: SAP ERP 개선과제, 이슈 및 조치, 운영, 상시업무 등 7개)
  - 따라서 기존 템플릿(`own_section_heading` = 본인 이름 h2)과 맞지 않는다.
  - 참고 URL 분석 기능으로 양식을 읽어, 그 표에 맞게 다시 작성하도록 바꿔야 한다.
