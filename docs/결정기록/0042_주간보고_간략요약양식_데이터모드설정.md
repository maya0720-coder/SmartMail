## 1. 기본 초안 양식(skill 양식 적용)

- `find-skills`(vercel-labs/skills, 사용자 영역 `~/.claude/skills`에 설치)로 skills.sh를 검색했다.
- 후보 비교:

| 후보 | 설치 수 | 판단 |
|---|---|---|
| `claude-office-skills/skills@weekly-report` | 5.6K | **채택**. 'Individual Weekly Report' 구조가 개인 주간보고에 맞음 |
| `anthropics/knowledge-work-plugins@status-report` | 3.3K | 경영진 보고(KPI·의사결정 요청) 중심이라 개인 주간보고에는 과함 |

- skill 자체는 설치하지 않았다. 외부 MCP(office-mcp) 전제이고 앱 안에서 쓸 수 없어서, **양식 구조만** 가져왔다.
- 기본 양식(조직 양식 프로필이 없을 때, `domain/weekly/brief_render.py`):

| 순서 | 머리글 | 내용(skill 대응) |
|---|---|---|
| 1 | 요약 | 완료·진행·이슈·회신 대기 건수 한 줄 (Summary) |
| 2 | 금주 실적 | 완료 업무 · 수행 내용 · 완료일 (Accomplishments) |
| 3 | 업무별 현황 | 표: 업무 / 진행 상황 / 수행 내용 / 완료 예정 (In Progress) |
| 4 | 이슈·요청 | 보류·기한 지남 업무 · 진행 상황 · 요청 핵심 (Blockers) |
| 5 | 차주 계획 | 기한이 이른 순 상위 5건 · 기한 · 수행 내용 (Next Week's Priorities) |

- 금주 실적·이슈·차주 계획 머리글은 사내 머리글(참고 링크 양식이 있으면 그 머리글)을 쓴다. 그래서 위키 본인 영역 규칙과 간단 편집 변환은 그대로 동작한다.
- '요약'·'업무별 현황'은 간단 편집(3칸 목록)으로 바꿀 때 목록으로 옮겨지지 않는다. 이때는 기존 경고가 뜬다.
- 조직 양식 프로필(0037)이 있으면 프로필 순서가 우선이다. 다만 목록 항목에도 수행 내용을 붙인다.

## 2. 업무별 간략 요약(`domain/weekly/brief.py`)

- **메일 원문은 다시 읽지 않는다.** 메일을 수집할 때 AI가 본문을 읽고 만든 마스킹된 요약만 쓴다. 초안을 만들 때 AI를 새로 부르지 않는다(속도·호출 상한).
  - 업무 진행 요약 `Task.progress_digest`
  - 메일별 구조화 요약 `MailRef.digest`(요청 사항·기한·필요 조치)
  - 메일 방향·시각
- 수행 내용: 진행 요약이 있으면 그 첫 문장, 없으면 `요청 핵심 → 최근: 마지막 후속 요청`, 둘 다 없으면 필요 조치.
- 진행 상황: `상태 · 기한 지남 · 회신 대기 · 내 회신 n통 · mm/dd 보냄|받음`.
- 완료 예정: 완료일(완료 업무) → 업무 기한 → 메일 요약의 기한 표현 순.
- 개조식 변환(`concise`):
  - 첫 문장만 쓴다. 상한은 60자(요청·후속은 각 40자)이며 넘으면 `…`.
  - 서술형 끝맺음을 명사형으로 바꾼다. 예: `부탁드립니다→요청`, `했습니다→함`, `되었습니다→됨`, `받았습니다→받음`, `막혔습니다→막힘`, `가능할까요?→가능 문의`.
  - 글자 없는 줄(표 구분선 등)은 버린다.
- 마스킹: 저장값도 마스킹돼 있지만, 자르기 전에 한 번 더 마스킹한다. HTML에 넣을 때는 이스케이프한다.
- 간단 편집 목록 줄은 `[구분] 제목 (요청: 부서) — 수행 내용`이다(300자 상한).
- 한계:
  - 요약이 아직 없는 메일(AI-Ground 미로그인·요약 대기)은 수행 내용이 비고 진행 상황만 나온다.
  - 데모(가짜 AI)의 필요 조치는 고정 문구라 요청 사항을 우선한다.

## 3. 데이터 모드 화면 설정(`config/run_mode.py`, `routes/run_mode.py`)

- [설정·연결] 맨 위에 '데이터 모드'(실제 데이터 / 가상 데이터(데모))를 추가했다. 지금 모드를 칩으로 보여 준다.
- 선택값은 DB 폴더 `run_mode.json`에 `{"mode": "real"|"demo"}`만 저장한다. 개인정보·자격증명은 없다.
  - 임시 파일에 쓴 뒤 바꿔 끼운다.
- **다음 시작 때 적용**한다. DB(실제 파일 / 메모리)와 연동(실제 / 가짜)이 시작할 때 정해지기 때문이다.
  - 저장 후 '다시 시작하면 적용' 안내를 띄운다.
  - 실제 데이터로 바꿀 때는 확인 창을 띄운다.
- 우선순위: 실행 스크립트 `-Demo`(환경 변수 `SMARTMAIL_DEMO_MODE`) > 화면 선택값 > `.env`.
  - 환경 변수로 정한 실행이면 화면에 그 사실을 표시한다.
- 파일 형식이 틀리면(알 수 없는 값·다른 키·200바이트 초과) 시작을 거부한다(개발지침 5장).
- API: `GET /api/run-mode`, `PUT /api/run-mode {mode}`(허용 값만, extra 금지, CSRF 공통 미들웨어).
- 남은 일(선택): 화면에서 '지금 다시 시작'은 만들지 않았다. 실행 스크립트가 종료 코드를 보고 다시 띄우는 방식으로 붙일 수 있다.
