## 1. 업무 구분: SAP 모듈 → 사용자 정의 목록

### 배경

- 기획서 TODO-01은 "관련 시스템/모듈(SAP FI·CO·MM·SD 등)"을 추출하도록 정했다. 그래서 메일 키워드로 SAP 모듈을 추정해 왔다.
- 사용자는 업무를 '일반업무'와 '전자결재'로만 구분한다.

### 사용자 결정(2026-11-13)

- 구분은 **사용자 정의 목록**으로 한다. 기본은 일반업무, 전자결재이다.
- 전자결재는 **제목·발신자 키워드**로 판별한다.

### 구현

| 항목 | 내용 |
| --- | --- |
| 구분 목록 | '설정·연결 > 업무 구분'에서 쉼표로 입력한다. 최대 8개, 각 20자 이하, 허용 문자만 쓸 수 있다. 첫 항목이 기본 구분이다. `app_setting.task_categories`에 저장한다 |
| 판별 규칙 | `config/rules/task_categories.toml`. 제목 키워드(전자결재·결재 요청·기안·품의·상신 등)나 발신자 패턴에 걸리면 '전자결재', 아니면 기본 구분 |
| 저장 위치 | 기존 `task.module_tag` 칸(20자)을 그대로 쓴다. 스키마는 바꾸지 않았다 |
| 기존 데이터 | 목록에 없는 값(예전 SAP 모듈 태그)은 앱을 시작할 때와 목록을 저장할 때 업무 제목으로 다시 구분한다 |
| 화면 반영 | 대시보드 '구분' 열, 제안된 업무의 구분 선택, 히스토리 필터(HIST-03, 구분 목록으로 버튼 생성), G-Knowledge R&R의 "업무 구분"(RET-03) |
| SAP 모듈 추정 | 하지 않는다. 코드(`domain/tasks/modules.py`)는 가짜 AI 응답에만 남아 있다 |

## 2. 업무 제목 = 메일 요청 사항 요약

### 배경

사용자 요청: 메일 제목 대신 메일을 읽고 요청 사항을 요약해서 보여 주고, 필요하면 AI-Ground로 일괄 변환한다.

### 구현

- **흐름**: 메일 수집 → 업무 제안(임시 제목 = 정리한 메일 제목) → 요약 작업이 AI-Ground로 요청 요약을 만들어 제목을 바꾼다.
- **임시 제목 정리**: 회신·전달 표시와 말머리(`[외부메일]`, `[골프존]` 등, 규칙 파일)를 반복해서 지운다.
- **요약 작업(`SummaryService`·`SummaryJob`)**
  - 원본 메일은 요약할 때만 다시 읽는다(메모리). 저장하지 않는다(MAIL-08).
  - 회신 인용(`-----Original Message-----`, `From:`, `보낸 사람:` 등) 앞까지만 쓰고, 본문은 700자로 줄인다.
  - 마스킹한 뒤 자르고 다시 마스킹한다. 건당 900자 이하이다.
  - **한 번에 6건을 묶어 1회 호출**하고, 답은 "번호. 요약" 형식으로만 해석한다.
  - 관문(`AiGateway.summarize_requests`)이 각 항목의 마스킹·길이를 다시 검사한다. AI 답변도 다시 마스킹하고 200자로 자른다.
  - 처리한 메일 참조에는 요약을 `mail_ref.summary`에 기록해 다시 보내지 않는다. 원본이 없으면 지금 제목으로 기록하고 다시 시도하지 않는다.
- **실행 시점**
  - AI-Ground에 로그인돼 있을 때만 실행한다. 로그인 전에는 호출 실패를 쌓지 않는다.
  - 2분마다 최대 3회 호출한다(10분당 15회 이하, 어댑터 상한 20회 안).
  - AI-Ground 로그인 직후와 새 업무가 제안된 직후에 바로 1회 실행한다.
  - '제안된 업무' 화면의 [AI로 일괄 요약]으로도 시작할 수 있다.
- **화면**
  - 요약하지 않은 업무에는 '요약 대기' 표시를 붙인다(대시보드·제안된 업무).
  - 제안된 업무 상단에 진행 상태를 보여 준다.

### 개인정보·보안

- 이전보다 AI-Ground로 보내는 범위가 넓어졌다.
  - 이전: 제목 + 근거 문장 500자
  - 이번: 제목 + 본문 발췌 700자(마스킹 후 900자 이하)
- 사용자가 요청한 기능이고, 마스킹·길이 제한·회신 인용 제거를 적용했다.
- 다만 마스킹 규칙에 없는 값(예: 본문에 쓴 사람 이름)은 그대로 갈 수 있다. 운영 전환 전에 개인정보 담당자의 확인이 필요하다.

## 3. 시작 로그인 창(설정 화면의 로그인 입력 제거)

### 사용자 요청

- 설정 화면에서 로그인 정보를 등록하지 않는다.
- 앱을 실행할 때 세련된 팝업으로 ID·암호를 받아 로그인한다.
- AI-Ground·G-Knowledge(Entra ID)는 `ID@golfzon.com`, 위키·그룹웨어는 ID로 로그인한다.
- 암호는 공통 1개로 한다(사용자 결정). 위키 암호가 다르면 따로 입력한다.

### 구현

- **표시 시점**
  - 모든 화면에서 로그인할 사이트가 남아 있으면 시작 로그인 창이 자동으로 뜬다.
  - '나중에'(또는 Esc)를 누르면 이번 실행 동안 자동으로 다시 띄우지 않는다. 이 값은 서버 메모리에만 두고 브라우저 저장소는 쓰지 않는다.
- **입력**: 아이디 칸 옆에 `@golfzon.com`을 표시한다. 도메인은 `login_fields.toml`의 `[entra] account_domain`에서 읽는다.
- **진행 표시**: 사이트 칩(대기 → 연결 중 → 완료/실패)과 2단계 인증 번호를 안내한다.
- **서버**
  - `POST /api/login/all {user_id, password, wiki_password?}`로 받는다.
  - `account_ids()`가 회사 계정은 `ID@도메인`으로, 위키는 `ID`로 바꾼다. 공백·제어 문자는 거부한다.
  - 버퍼 지우기, 회사 계정 1회 제출, 시도 횟수 제한은 결정기록 0011과 같다.
- **다른 화면**: 로그인이 필요할 때도 이 창을 연다(`requireLogin`). 회사 계정은 먼저 SSO 연결을 시도한다.
- **삭제한 것**: 사이트별 ID/PW 모달(`login_modal.html`), 설정 화면 일괄 로그인 카드(`login_all.js`)
- **그룹웨어**: 연동 규격이 확인되지 않아 대상에서 뺐다(보류).

## 검증

- 단위·통합 테스트
  - 구분: 판별 규칙, 목록 검증, 손상된 저장값 무시, 예전 태그 다시 구분, API
  - 요약: 인용 제거, 번호 해석, 마스킹, 묶음 크기·길이 거부, 답변 재마스킹, 다시 보내지 않음, 로그인 전 미호출
  - 로그인: ID 변환, 위키 암호 따로 입력, '나중에'
- 브라우저 테스트: 시작 로그인 창이 자동으로 뜨는지, 로그인 후 닫히고 입력칸이 비는지, '나중에'를 누르면 다시 뜨지 않는지
- 결과: 점검 스크립트(포맷·린트·타입·테스트·시크릿 탐지) 통과
- 데모 화면 캡처(로컬 저장): 로그인 창, 요약 후 제안된 업무 화면, 구분 설정
