## 배경

- 제안 목록은 한 건씩만 결정할 수 있었다. 공지·회람처럼 같은 성격의 제안이 여러 건 쌓이면 A·S·D를 반복해야 했다.

## 결정

1. **목록 선택**(`triage_bulk.js`)
   - 마우스
     - `Ctrl/⌘+클릭`: 한 건씩 넣고 빼기
     - `Shift+클릭`: 범위 선택. **현재 페이지에 보이는 항목 안에서만** 고른다.
     - 체크박스: 행 앞에 있고, 마우스를 올렸을 때와 선택 모드에서만 보인다.
   - 키보드
     - `Ctrl+A`: 현재 페이지 전체
     - `Space`: 지금 항목 넣고 빼기
     - `Shift+↑↓`: 범위 넓히기(현재 페이지 안)
     - `Esc`: 선택 해제
   - 다중 선택을 처음 시작하면 지금 보고 있던 항목도 선택에 넣는다.
   - 탭을 바꾸면 선택을 비운다. 다른 탭의 항목이 몰래 섞이지 않게 하기 위해서다.
   - 체크박스는 Tab 순서에서 뺐다(`tabindex=-1`). 키보드 사용자는 Space와 Shift+↑↓로 같은 동작을 한다.
2. **일괄 작업 바**
   - 2건 이상 고르면 상세 패널 자리에 보인다.
   - 구성: 선택 n건, `[할 일로 A] [나중에 S] [업무 아님 D] [선택 해제 Esc]`, 구분 일괄 변경, `이 탭 전체 선택`(모든 페이지, 최대 100건).
3. **서버**(`app/routes/triage_bulk.py`)
   - `POST /api/triage/bulk {ids[1~100], decision}`
     - 건마다 기존 건별 API 함수(`approve`·`snooze`·`dismiss`)를 그대로 부른다. 그래서 결과가 건별 결정과 같고, '업무 아님' 학습도 건별로 기록된다. 자동 제외 없음 원칙은 그대로다.
     - 제안 상태가 아닌 건과 없는 건은 실패 목록 `{id, error}`로 돌려준다. 나머지는 계속 처리한다.
     - 중복 번호는 한 번만 처리한다. 알 수 없는 필드는 거부한다(대량 할당 차단).
   - 성공한 건의 건별 토큰 n개를 묶어 **일괄 되돌리기 토큰** 1개를 발급한다. 토큰은 메모리에만 두고, 60초 동안 한 번만 쓸 수 있다.
   - `POST /api/triage/bulk/revert {bulk_token}`: 묶인 건을 건별 되돌리기 로직으로 모두 되돌린다. 그 사이 상태가 더 바뀐 건은 실패 목록으로 돌려준다.
   - 건별 토큰 보관 상한을 200에서 400으로 올렸다. 100건을 일괄 결정한 뒤 건별 결정을 이어 해도 일괄 되돌리기가 깨지지 않게 하기 위해서다.
4. **토스트**: "12건을 할 일로 옮겼습니다 [되돌리기]"를 10초 동안 보인다. 일부가 실패하면 실패 건수를 붙이고, 실패한 건은 선택으로 남긴다.

## 지시서와 다르게 정한 점

- **구분 일괄 변경**(`decision: "category"`, `module_tag` 필수)은 결정이 아니라 수정이다. 그래서 되돌리기 토큰을 만들지 않는다. 구분은 화면에서 바로 다시 바꿀 수 있다.
- **좁은 화면(≤900px, 서랍 구간)**: 일괄 작업 바는 상세 서랍 안에 그린다. 서랍은 자동으로 열지 않고 Enter로 연다.

## 보안·개인정보

- 일괄 API도 건별 API와 같은 CSRF·입력 검증을 받는다: 번호 1~2³¹, 최대 100건, 결정 허용 목록, `extra=forbid`.
- 새로 저장하는 값은 없다. 되돌리기 토큰은 메모리에만 있고, 메일 원문은 학습 때 메모리에서만 읽는다(0015와 같음).

  - 101건, 빈 목록, 알 수 없는 결정·필드는 거부하고, 100건은 허용한다.
  - 구분 일괄 변경이 동작한다.
  - 업무 아님 학습이 건별로 기록되고, 되돌리면 줄어든다.
