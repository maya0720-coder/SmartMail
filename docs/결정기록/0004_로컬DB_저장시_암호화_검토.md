# 0004. 로컬 DB 저장 시 암호화 검토

- 날짜: 2026-11-11
- 단계: 03
- 상태: 적용(보안 담당 확인 권장)

## 배경

기획서 5장은 "로컬 DB는 암호화 저장 검토"를 요구하고, 03단계 작업 1은 검토 결과를 남기라고 한다.

## 검토한 방법

| 방법 | 장점 | 단점 |
| --- | --- | --- |
| SQLCipher(sqlcipher3 등) | DB 파일 전체 암호화 | Windows용 네이티브 빌드 의존성이 추가된다. 키를 같은 PC에 둬야 하므로, PC 계정이 탈취되면 보호 효과가 크지 않다 |
| 컬럼 단위 암호화(cryptography + Windows DPAPI) | 표준 라이브러리 수준 구현 | 검색·정렬이 어려워진다. 키는 결국 사용자 계정에 묶인다 |
| 암호화하지 않고 데이터 최소화로 통제 | 의존성 없음 | 파일이 복사되면 내용이 보인다 |

## 결정

로컬 테스트 버전은 DB 파일을 **암호화하지 않는다**. 대신 저장 내용 자체를 줄여 위험을 낮춘다.

- 메일 본문·첨부·자격증명·상대방 주소 컬럼이 없다. 스키마 검사 테스트로 이를 보장한다.
- 완료 후 7일이 지나면 자동 삭제한다. 삭제한 행은 `secure_delete`로 0으로 덮어쓰고, 이어서 VACUUM한다.
- DB 파일은 추적 제외 폴더(`data/`)에 둔다. 사용자 프로필 권한과 BitLocker 같은 PC 디스크 암호화로 보호한다.
- 사용자는 언제든 전체 삭제를 실행할 수 있다.

## 남은 위험과 후속 조치

- 보관 기간 7일 안에는 업무 제목·요청 부서·요약(사용자 확인분)·히스토리 카드가 평문으로 남는다.
- 웹 배포 단계에서는 서버 DB 암호화(TDE 또는 컬럼 암호화)와 키 관리 방식을 다시 정한다.
- 정보보안 담당이 로컬 버전에도 암호화가 필요하다고 판단하면, DPAPI 기반 컬럼 암호화로 바꾼다.
