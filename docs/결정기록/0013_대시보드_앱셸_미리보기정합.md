# 0013. 대시보드 앱 셸 — ui-ux-pro-max 미리보기 정합

- 날짜: 2026-11-12
- 상태: 구현 완료
- 근거 문서: `designMD/03_디자인수정_ui-ux-pro-max_미리보기정합.md`
- 기준 시안: `designMD/02_ui-ux-pro-max.html`
- 관련: 결정기록 0012, 기획서 6장, dev/12

## 배경

1차 적용본(결정기록 0012)은 색·글꼴·아이콘이 미리보기와 같았다. 하지만 두 가지가 달랐다.
- 화면 골격: 한 화면 고정형이 아니었다.
- 조작 기능: 다중 선택, 바로 거르기, 서랍, 되돌리기가 없었다.

명세 03이 이 차이를 정리했다.

## 결정

1. **앱 셸(L1)**
   - 조건: 대시보드, 화면 폭 1025px 이상, 높이 700px 이상
   - 이 조건에서는 `100dvh` 한 화면에 페이지 스크롤 없이 보여 준다. 목록과 상세(320px, 1920px 이상은 360px)가 화면 아래까지 찬다.
   - 다른 화면이나 좁은·낮은 화면은 기존처럼 스크롤하는 문서형으로 둔다.
2. **제목 줄·표로 보기(L2·C3)**
   - 제목 줄을 한 줄로 줄인다.
   - 수집 경로와 보관 안내는 마우스를 올리면 보이는 설명(`title`)으로 옮긴다.
   - '표로 보기'는 화면에 펼치지 않고 모달(`#dlg-mtbl`)로 연다. `#m-tbl`·`#m-desc` id는 유지한다.
3. **KPI(L3·L4·C2)**
   - KPI 4개와 도넛을 한 그리드 5칸으로 둔다. `#mk`는 `display:contents`로 두어 기존 테스트의 `#mk .kpi` 4개 조건을 지킨다.
   - 카드 높이는 83px로 줄인다.
   - **추이 그래프는 유지한다.** dev/12의 요구사항이라 빼지 않고 120×28px로 줄였다(명세 8장 확인 항목 1, 명세 안대로).
   - 지표 정의와 기간은 카드 설명과 그래프 툴팁 첫 줄로 옮긴다.
   - 표본이 모두 0이면 그래프 대신 "데이터 없음"을 표시한다.
4. **상태 도넛(C1)**
   - 범례 6개를 항상 표시하고, 0건인 상태는 흐리게 표시한다.
   - 범례를 누르면 목록 필터가 바뀐다. 대기·보류는 필터 버튼이 없으므로 '전체'로 바뀐다.
5. **목록(L5~L7·F8)**
   - 패널 머리: 필터, 그리고 아이콘 버튼 3개(id 유지)를 둔다. 기간 지정 수집은 버튼 아래 작은 창으로 연다.
   - 페이저는 패널 바닥에 고정한다.
   - 페이지 크기: 앱 셸에서는 목록 영역의 실제 높이로 계산하고(`ResizeObserver`), 문서형에서는 창 높이로 계산한다.
6. **상세(L8)와 서랍(L9·F7)**
   - 상세는 본문(내부 스크롤)과 하단 고정 버튼으로 나눈다. 고정 버튼은 상태별로 다르다(제안됨 → 승인·무시 등).
   - 원본 보기와 유사 이력 결과 영역은 버튼을 누를 때 만든다.
   - 1100px 이하에서는 상세가 오른쪽 서랍으로 열린다.
     - 닫기: 바깥 클릭, ✕ 버튼, Esc
     - 열려 있는 동안 Tab 포커스가 서랍 안에서만 돈다.
     - 닫으면 포커스가 선택한 행으로 돌아간다.
7. **일괄 작업(F1)**
   - 체크박스로 여러 업무를 고르면 일괄 작업 바가 뜬다(명세 8장 확인 항목 2, 명세 안대로 포함).
   - 처리 방식: 기존 API를 건별로, 동시 3건 이하로 호출한다.
   - **상태 전이 규칙은 화면에서 판단하지 않는다.** 서버가 거부한 건은 "실패 n건(허용되지 않는 변경)"으로 집계해 알려 준다.
   - '무시'는 되돌릴 수 없으므로 확인 창을 거친다.
   - 선택 상태는 메모리에만 두고, 목록에서 사라진 업무는 선택에서 정리한다.
8. **되돌리기(F5)**
   - 상태를 바꾸면 토스트에 [되돌리기]를 보여 준다. 누르면 이전 상태로 다시 요청한다.
   - 서버가 거부하면 "되돌릴 수 없는 변경입니다"를 알린다.
   - 승인과 무시는 되돌리는 전이가 없어서 [되돌리기]를 보이지 않는다.
9. **상단 검색(F2)**
   - 대시보드에서는 입력하는 대로(150ms 뒤) 목록을 제목·부서·모듈로 거른다. 서버를 호출하지 않는다.
   - Enter는 기존대로 히스토리 검색으로 이동한다(SRCH 요구 유지, 명세 8장 확인 항목 3).
   - Esc로 검색어를 지운다. 다른 화면은 동작이 바뀌지 않는다.
10. **키보드(F4)**: 대시보드 전체에서 동작한다. 입력칸, 모달, 서랍 안에서는 쓰지 않는다.

    | 키 | 동작 |
    | --- | --- |
    | ↑ / ↓ | 행 선택. 페이지 끝에서는 다음·이전 페이지로 넘어간다 |
    | ← / → | 페이지 이동 |
    | Enter | 서랍 열기 |
    | Esc | 서랍 닫기, 검색어 지우기 |
    | Space | 선택한 행 체크 |

11. **토스트(F6)**
    - `toast(message, options)`로 확장했다. 기존 호출 방식도 그대로 동작한다.
    - 구성: 아이콘, 문구, 행동 버튼(있을 때), 진행 막대
    - 행동 버튼이 있으면 5초 동안 보이고, 마우스를 올리면 멈춘다.

## 파일 구성

| 파일 | 책임 |
| --- | --- |
| `dashboard.js` | 지표, 목록, 키보드, 검색, 이벤트 |
| `dashboard_detail.js` | 상세, 서랍 |
| `todo_actions.js` | 상태 변경, 되돌리기, 일괄 처리 |
| `todo_list.js` | 정렬, 페이지, 도넛 |

모두 500줄 이하다. 아이콘은 alert-triangle, x-circle, chevron-down, info, check-square, square를 추가했다(Lucide 0.460.0, 받은 뒤 검사).

## 검증(데모 데이터, 캡처는 로컬에만 저장)

| 화면 크기 | 결과 |
| --- | --- |
| 1440×900 | 페이지 스크롤 없음, 목록 끝이 화면 높이 − 60px 이상, 상세 320px이고 목록과 높이가 같음, KPI 83px, 첫 행 y=299, 페이지당 13행 |
| 1920×1080 | 페이지당 18행, 상세 360px |
| 1024×768 | 행을 누르면 서랍이 열림(`aria-modal`, 포커스가 ✕로 이동), Esc로 닫으면 포커스가 행으로 복귀, 가로 스크롤 없음 |
| 390×844 | 문서형, 하단 탭바 표시, 가로 스크롤 없음 |

- 동작 확인
  - 범례를 누르면 필터가 바뀐다.
  - 표로 보기 모달이 열리고 닫힌다.
  - 검색 결과가 없으면 안내가 나오고, Esc로 검색어가 지워진다.
  - ↓ 키로 다음 페이지로 넘어간다.
  - 2건을 일괄로 진행 시작하면 "성공 2건"이 나온다.
  - 보류로 바꾼 뒤 되돌리기가 된다.
  - 제안됨 업무의 상세 하단에 승인·무시가 나온다.
- 콘솔 오류와 외부 요청은 0건이다.
- 자동 테스트 2개를 추가했다(앱 셸 배치, 서랍·일괄·되돌리기·검색). 테스트 중 Playwright의 문자열 식 대기가 CSP(`unsafe-eval` 금지)에 막히는 것을 확인했고, 로케이터 대기로 바꿨다.

## 남은 한계

- 실제 업무 데이터(수백 건 이상)와 실제 지표 표본에서의 모습은 확인하지 않았다.
- 일괄 작업은 건마다 요청을 보낸다. 많은 건을 고르면 시간이 걸린다.
