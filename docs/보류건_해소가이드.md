## 1. 01단계 — 커밋 전 시크릿 탐지 훅

### 남은 것

- `.claude/settings.json`(삭제 명령 확인, 편집 후 ruff format)은 이미 적용돼 있다. 결정기록 0002의 상태만 `적용`으로 바꾸면 된다.
- 남은 것은 **커밋 전 시크릿 탐지** 하나다. guard가 `.claude/hooks/` 변경을 막기 때문에 Claude Code가 직접 만들지 않았다.
- AXHub AI 활용 기록은 사용자 지시에 따라 대상에서 뺐다.

### 해소 방법(둘 중 하나 선택)

**방법 A. git pre-commit 훅(권장).** Claude Code 밖에서 커밋할 때도 동작한다.

`.git/hooks/pre-commit` 파일을 만들고 아래 내용을 넣는다(확장자 없음).

```sh
#!/bin/sh
# 커밋 전 시크릿 탐지(detect-secrets). 실패하면 커밋을 막는다.
.venv/Scripts/python scripts/check.py || { echo "점검 실패: 커밋을 중단합니다"; exit 1; }
```

- `scripts/check.py`는 시크릿 탐지(detect-secrets)와 함께 포맷·린트·타입·테스트도 돌리므로 커밋이 1~2분 걸린다. 시크릿 탐지만 빠르게 하려면 저장소에 `.secrets.baseline`을 먼저 만든 뒤 `detect-secrets-hook`을 쓰는 방식으로 바꿀 수 있다(요청하시면 정리).
- `.git/hooks/`는 저장소에 커밋되지 않으므로 PC마다 한 번씩 만들어야 한다.

**방법 B. Claude Code 훅.** `.claude/settings.json`의 `hooks`에 `PreToolUse`(matcher: `Bash`, `git commit` 명령일 때 `scripts/check.py` 실행)를 사용자가 직접 추가한다. Claude Code로 커밋할 때만 동작한다.

### 완료 기준

- 가짜 키처럼 보이는 합성 문자열을 넣은 파일을 커밋하려 하면 커밋이 막힌다(확인 후 그 파일은 지운다).
- 결정기록 0002 상태를 `적용`으로 바꾸고, 00_MAIN 01행을 `완료`로 바꾼다.

## 2. 06단계 — AI-Ground g-llm 연동

### 지금 구현된 것

- `src/integrations/ai/gateway.py`: 전송 전 마스킹 재검사, 길이 상한, 시간 초과(`SMARTMAIL_HTTP_TIMEOUT_SECONDS`), 재시도, 호출 이력(마스킹된 값만), 근거 링크 허용 목록 검사
- (답변 반영 전) API 어댑터 자리는 로그인 여부만 확인하고 '확인 필요' 안내를 냈다. 지금은 아래 '반영 결과'의 화면 자동화 어댑터로 바뀌었다.
- 어댑터가 맞춰야 할 인터페이스(`src/domain/ai.py`의 `KnowledgeAI`)
  - `classify_task(summary: MaskedText) -> Classification`: 메일 요약이 업무인지 분류
  - `suggest_solution(summary: MaskedText, similar_cases: Sequence[MaskedText]) -> AiAnswer`: 비슷한 사례를 참고한 해결 제안

### AI-Ground 담당에게 확인할 것

| 번호 | 질문 | 왜 필요한가 | 답변 |
| ---- | ---- | ---- | ---- |
| A-1  | 외부 프로그램(로컬 앱)에서 g-llm을 호출하는 공식 API가 있는가? 없다면 화면 자동화를 허용하는가? | API가 없으면 구현 방식이 완전히 달라짐             | -> API가 없음                                                        |

### 반영 결과(2026-11-11, 결정기록 0008)

- API가 없으므로 API 어댑터 자리를 지웠습니다. 대신 SSO로 로그인한 비저장 브라우저에서 채팅 화면을 자동화하는 어댑터(`src/integrations/ai/ground_browser.py`)를 만들었습니다.
- 스트리밍 답변이 끝났는지는 '답변 글자가 2초 동안 그대로'로 판단합니다. 화면에 '중지 버튼'이나 '복사 버튼' 같은 표시가 있으면 함께 씁니다.
- 권장값: 답변 대기 90초, 시간 초과 시 재전송 없음, 호출 간격 3초, 10분당 20회.
- 보낸 내용이 저장·학습되므로 마스킹을 유지하고, 매번 새 대화로 시작하고, 다시 보내지 않습니다.

### 남은 일

1. **화면 선택자:** AI-Ground 채팅 화면에서 아래 선택자를 확인해 `src/config/rules/aiground_fields.toml`에 넣습니다. 확인 방법은 3장의 '선택자 확인 방법'과 같습니다.
   - 새 대화 화면 경로(`path`, 필수)
   - 질문 입력칸(`prompt`, 필수)
   - 답변 말풍선(`answer`, 필수)
   - 보내기 버튼(`submit`, 선택. 없으면 Enter로 보냄)
   - 생성 중 표시(`busy`, 선택)
   - 완료 표시(`done`, 선택)
   - g-llm 모델 선택(`model`·`model_option`, 화면에 모델 선택이 있을 때)
2. **정보보안 확인:** 화면 자동화 허용 여부와, 마스킹한 업무 요약이 학습에 쓰여도 되는지 확인합니다(결정기록 0008 '확인 필요' 1·2).
3. **수동 점검:** `.env`에 `SMARTMAIL_AI_ADAPTER=gllm`을 넣고, `SMARTMAIL_BROWSER_LOGIN_SITES`에 `ai-ground`를 넣습니다. 그다음 `docs/수동점검.md` 3-1장 절차를 따라 합성 질문으로 확인합니다.

### 그 전까지

- `SMARTMAIL_AI_ADAPTER=fake`로 두면 외부 전송 없이 가짜 응답으로 화면 흐름을 쓸 수 있습니다.
- `gllm`으로 두면 업무 추출은 규칙 기반으로만 동작합니다. AI 제안 칸에는 '확인 필요' 안내가 나옵니다.

## 3. 08단계 — G-Knowledge 등록·검색

### 지금 구현된 것

- 등록 미리보기, 중복 등록 방지(강제 등록 옵션), 마스킹 검사(`MaskedDraft`)
- `src/integrations/gknowledge/browser.py`: 비저장 브라우저로 화면에 입력·제출하는 틀. 선택자는 설정 파일에서 읽는다.
- `src/config/rules/gknowledge_fields.toml`: 등록 경로(`/knowledge/new`)만 채워져 있고, 선택자는 비어 있다. 비어 있으면 실제 자동화를 하지 않는다.

### G-Knowledge 담당·정보보안에게 확인할 것

| 번호 | 질문 | 왜 필요한가 | 답변 |
| ---- | ---- | ---- | ---- |
| G-1  | 브라우저 자동화(Playwright)로 등록·검색해도 되는가? 금지라면 공식 API가 있는가? | 허용되지 않으면 이 방식은 쓰지 않음  | -> 없음                                          |
| G-2  | 로그인 방식(SSO·2단계 인증 여부)                                                | `SMARTMAIL_BROWSER_LOGIN_SITES` 설정 | -> SSO                                           |
| G-3  | 등록 화면에 필수 항목이 더 있는가(분류, 공개 범위, 첨부 등)?                    | 필드 매핑 추가                       | -> 제목, 내용, 첨부                              |
| G-4  | 등록 후 지식 링크를 어디서 얻는가(주소창 / 결과 화면 요소)?                     | `result_link` 설정                   | -> 차후 확인. 일단 안정성 기반한 추천안으로 진행 |
| G-5  | 검색 화면 주소와 결과 목록 구조                                                 | `[search]` 설정                      | -> 일단 안정성 기반한 추천안으로 진행            |
| G-6  | 같은 내용을 중복 등록하면 문제가 되는가? 삭제·수정 권한은 본인에게 있는가?      | 중복 방지 정책 확정                  | -> 중복 등록 불가                                |

### 선택자 확인 방법(직접 하실 경우)

1. 크롬에서 G-Knowledge 등록 화면을 연다.
2. 제목 입력칸을 마우스 오른쪽 클릭 → '검사'를 누른다.
3. 강조된 요소에서 `id`나 `name` 값을 확인한다. 예: `id="title"`이면 선택자는 `#title`, `name="subject"`이면 `[name="subject"]`.
4. 본문, 태그, 등록 버튼, 검색칸, 결과 항목도 같은 방법으로 확인한다.
5. 확인한 값을 `gknowledge_fields.toml`의 빈칸에 넣거나, 값만 알려 주면 반영한다.

주의: 화면을 캡처해서 전달할 때는 실제 지식 내용·이름이 보이지 않게 가린다. `id`처럼 자주 바뀌지 않는 값을 우선 사용한다(자동 생성된 클래스 이름은 배포 때마다 바뀔 수 있음).

### 반영 결과(2026-11-11, 결정기록 0008)

- **중복 등록 불가(G-6):** 재등록 버튼을 없앴습니다. 아래 세 경우를 모두 거부합니다.
  - 이미 등록한 업무
  - 같은 업무를 동시에 등록하는 경우(두 번 클릭)
  - G-Knowledge에 같은 제목이 이미 있는 경우(검색 설정 후, 보조 수단: 검색이 실패하면 건너뜀)
- **등록 화면 항목(G-3):** 화면 항목은 제목·내용·첨부입니다. 태그 칸이 없으므로 태그를 내용 끝에 `태그: …`로 붙입니다. 첨부는 자동화하지 않습니다.
- **결과 링크(G-4):** 결과 링크 요소(`result_link`)나 결과 주소 형식(`result_path`, 예: `/knowledge/[0-9]+`) 중 하나를 꼭 채워야 등록이 동작합니다. 로그인·오류 화면으로 가면 성공으로 보지 않습니다. 확인하지 못하면 다시 보내지 않고, G-Knowledge에서 직접 확인하라고 안내합니다.
- **검색(G-5):** 검색 경로에 `{query}`를 넣으면 주소로 검색합니다(예: `/search?q={query}`). 결과가 10초 안에 나타나지 않으면 '결과 없음'으로 봅니다.

### 남은 일

1. **화면 선택자:** `gknowledge_fields.toml`에 넣습니다.
   - 등록: 제목·내용·등록 버튼(필수), 결과 링크 요소(선택)
   - 검색: 검색 주소 형식(권장) 또는 입력칸·버튼, 결과 항목·링크
2. **정보보안 확인:** 화면 자동화 허용 여부를 확인합니다(결정기록 0008 '확인 필요' 1).
3. **수동 점검:** `docs/수동점검.md` 3장 절차를 따라 테스트용 지식 1건을 등록·검색합니다. 확인이 끝나면 그 지식을 삭제합니다.

### 그 전까지

- 미리보기와 '복사해서 직접 등록'까지만 쓸 수 있습니다. 직접 등록한 뒤 링크를 업무에 연결할 수 있습니다.

| W-3  | 인증 방식: SSO 쿠키 / 개인 접근 토큰(PAT) / 기본 인증                                                  | 토큰이면 비저장 원칙에 맞춘 입력 방식 설계                        |
| W-4  | 주간보고 공간의 `space_key`와 상위 페이지                                                              | `wiki_template.toml` 설정                                         |
| W-5  | 기존 주간보고 페이지(예: ERP_261113)의 구조: 사람별 영역을 무엇으로 나누는가(h2 제목, 표, 레이아웃 칸) | 본인 영역 찾기 규칙                                               |
| W-6  | 사람별 영역에 이름 대신 고유 앵커(매크로)를 둘 수 있는가?                                              | 동명이인·이름 변경 시 다른 사람 영역 덮어쓰기 방지(결정기록 0007) |
| W-7  | 주간 페이지는 누가 만드는가(첫 작성자가 생성 / 관리자가 미리 생성)?                                    | 페이지 생성 기능을 열지 결정                                      |
| W-8  | 동시에 여러 명이 수정할 때 운영 방식                                                                   | 충돌 시 안내 문구                                                 |

### 미리 준비해 주시면 좋은 것

- 지난 주간보고 페이지 1개의 **구조만** 남긴 샘플: 이름은 '사용자A'처럼 바꾸고, 업무 내용은 지운 뒤 제목·표·매크로 형태만 남긴다. 이 샘플로 본인 영역 찾기 테스트를 만든다.

### 받으면 할 일

1. 결정기록에 API 허용과 인증 방식을 남긴다.
2. `confluence.py`에 조회·생성·수정을 구현한다. 인자는 '마스킹된 본인 영역 값 객체'로 바꾸고, 어댑터 입구에서 마스킹을 다시 검사한다(결정기록 0007의 남은 일 M-3).
3. 받은 구조 샘플에 맞춰 본인 영역 찾기 규칙을 조정하고, 가짜 위키로 다른 사람 영역 보존·충돌 테스트를 추가한다.
4. 테스트 공간이나 테스트 페이지에 `docs/수동점검.md` 절차로 게시를 확인한다.
5. `.env`의 `SMARTMAIL_USER_DISPLAY_NAME`에 위키에 표시되는 본인 이름을 넣는다. 기본값 '본인'이면 게시가 거부된다.

### 그 전까지

- 주간보고 화면에서 초안을 만들고 다듬은 뒤 미리보기 내용을 복사해 직접 붙여넣는다.
