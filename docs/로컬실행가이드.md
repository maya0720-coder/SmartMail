# 로컬 실행 가이드

업무 처리 관리 현황 로컬 테스트 버전을 사용자 PC(Windows)에서 실행하는 방법입니다. 서버는 `127.0.0.1`에만 열려 다른 PC에서는 접속할 수 없습니다.

## 1. 준비

| 항목 | 내용 |
| --- | --- |
| OS | Windows 10/11 |
| Python | 3.11 (`py -3.11 --version`으로 확인) |
| 메일 | 클래식 아웃룩(데스크톱). 새 아웃룩만 쓰는 PC는 그룹웨어 경로로 전환되며, 이 경로는 연동 규격 확인 전까지 쓸 수 없습니다 |
| 네트워크 | 처음 설치할 때만 패키지 저장소와 Playwright 브라우저 다운로드가 필요합니다 |

같은 PC에서는 앱을 한 번만 실행합니다. 두 개를 띄우면 잔존 검사가 서로의 브라우저 임시 폴더를 지울 수 있습니다.

## 2. 설정 파일(.env) 만들기

1. 저장소 루트의 `.env.example`을 복사해 `.env`를 만듭니다. `.env`는 저장소에 올라가지 않습니다.
2. 다음 값을 채웁니다.
   - `SMARTMAIL_APP_PORT`: 1024~65535 사이 포트(예: 8765)
   - 외부 사이트 주소 4개(`SMARTMAIL_*_BASE_URL`): https 주소만 됩니다. 확인 전이라면 `https://example.invalid`처럼 임시 값을 넣고 데모 모드로 실행합니다.
   - `SMARTMAIL_USER_DISPLAY_NAME`: 지표 원장과 G-Knowledge R&R에 쓸 담당자 표시명(별칭 가능)
3. ID·암호는 `.env`에 넣지 않습니다. 정의되지 않은 키가 있으면 앱이 시작을 거부합니다.

## 3. 실행

**가장 쉬운 방법:** 저장소 루트의 `업무처리현황_실행.bat`을 더블클릭합니다.
- 서버가 켜지고 브라우저 화면이 자동으로 열립니다.
- 종료하려면 검은 창에서 `Ctrl+C`를 누르거나 창을 닫습니다.

이전에 실행한 앱이 남아 있으면 "종료하고 새 버전으로 다시 시작할까요? (Y/N)"를 묻습니다.
- 업데이트 후에는 **Y**를 누르세요. 이전 버전이 계속 떠 있으면 새 화면이 열리지 않습니다.

처음 실행하면 최근 30일 메일을 자동으로 수집하고, 이후에는 10분마다 새 메일을 반영합니다(MAIL-04).

**사이트 로그인:** '설정·연결' 화면의 '사이트 일괄 로그인'을 씁니다.
- 회사 계정(AI-Ground·G-Knowledge 공통)과 위키 계정을 한 번 입력합니다.
- 입력값은 저장하지 않고 로그인 직후 지웁니다.
- 이미 로그인된 사이트는 묻지 않습니다.
- 휴대폰 승인이 필요하면 화면에 승인 번호가 표시됩니다.
- AI-Ground나 G-Knowledge 중 하나를 로그아웃하면 둘 다 로그아웃됩니다.

PowerShell에서 직접 실행하려면 저장소 루트로 이동한 뒤 다음을 실행합니다.

```powershell
# 처음 한 번: 가상환경을 만들고, 해시로 검증한 의존성과 Chromium을 설치한 뒤 실행
powershell -ExecutionPolicy Bypass -File scripts\run.ps1 -Install

# 이후 실행
powershell -ExecutionPolicy Bypass -File scripts\run.ps1

# 데모 모드(가상 메일·가짜 연동, 외부 접속 없음)
powershell -ExecutionPolicy Bypass -File scripts\run.ps1 -Demo
```

실제 데이터 / 가상 데이터(데모)는 화면 **[설정·연결] → 데이터 모드**에서도 고를 수 있습니다(결정기록 0042).

- 저장한 값은 앱을 종료한 뒤 다시 실행하면 적용됩니다. 값은 DB 폴더의 `run_mode.json`에 저장됩니다.
- 기본값은 **가상 데이터**입니다. 실제 데이터를 쓰려면 화면에서 '실제 데이터'를 저장한 뒤 다시 실행합니다.
- 우선순위: 실행 스크립트 `-Demo`(환경 변수 `SMARTMAIL_DEMO_MODE`) > 화면 선택값 > 기본값(가상). 설정 파일 값은 시작 모드를 정하지 않습니다.
- `run_mode.json` 형식이 잘못되면 시작을 거부합니다. 이때는 파일을 지우고 다시 실행합니다.

브라우저에서 화면에 표시된 주소(예: `http://127.0.0.1:8765/`)를 엽니다. 종료는 `Ctrl+C`입니다. 종료하면 다음이 자동으로 처리됩니다.

- 모든 사이트 세션을 폐기합니다.
- 브라우저 임시 폴더를 삭제합니다.
- 잔존 검사를 실행합니다.

## 4. 처음 써 보기(데모 모드)

1. 대시보드에서 '메일 수집(이번 주)'을 누르면 합성 메일에서 업무가 제안됩니다.
2. '제안된 업무'에서 승인하거나 무시합니다.
3. 대시보드에서 업무를 고르고 진행 시작 → 완료 확정 → 히스토리 카드 → G-Knowledge 지식 등록(가짜) 순서로 진행해 봅니다.
4. '주간보고'에서 초안을 만들고 미리보기 → 승인 후 게시(가짜 위키)를 눌러 봅니다.
5. '업무 히스토리'에서 검색하면 앱 → G-Knowledge → AI 순서로 결과가 나옵니다.

## 5. 실제 연동 전 확인할 것(확인 필요)

| 연동 | 확인할 내용 | 설정 위치 |
| --- | --- | --- |
| 아웃룩 | 사내 PC의 아웃룩 종류 | `SMARTMAIL_MAIL_SOURCE` |
| 그룹웨어 메일 | API/IMAP 제공 여부 | `src/collectors/groupware.py` 구현 필요 |
| 사이트 로그인 | 2단계 인증·SSO 여부 | `SMARTMAIL_BROWSER_LOGIN_SITES` |
| AI-Ground g-llm | 채팅 화면 선택자, 자동화 허용(API 없음·SSO, 결정기록 0008) | `src/config/rules/aiground_fields.toml` |
| G-Knowledge | 등록·검색 화면 필드, 자동화 허용 | `src/config/rules/gknowledge_fields.toml` |
| 위키 | 주간보고 페이지 구조, API 허용, 인증 | `src/config/rules/wiki_template.toml`, `src/integrations/wiki/confluence.py` |
| 지표 원장 | 장기 보관 여부 | `SMARTMAIL_METRICS_LEDGER_KEEP` |

연동별 확인 절차는 `docs/수동점검.md`를 따릅니다.

## 6. 점검(개발자용)

```powershell
.venv\Scripts\pip-sync requirements-dev.lock   # 개발 의존성
.venv\Scripts\python scripts\check.py          # 포맷·린트·타입·테스트·시크릿 탐지·금지 패턴
.venv\Scripts\python scripts\check.py --audit  # + 의존성 취약점 검사(네트워크 필요)
.venv\Scripts\python scripts\measure_extraction.py  # 합성 메일 추출 정확도
```

## 7. 데이터 삭제

설정·연결 화면에서 '로컬 데이터 전체 삭제'를 누르면 DB의 업무·요약·이력·지표가 모두 지워집니다. 메일 원본은 지우지 않습니다. 로그 파일을 지우려면 `logs/` 폴더를 직접 삭제합니다.
