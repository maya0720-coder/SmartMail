# 수동 점검 절차

자동 테스트는 실제 메일함과 사이트에 접근하지 않습니다. 그래서 아래 항목은 사용자 PC에서 직접 확인합니다.

- 점검할 때는 테스트 계정과 테스트 글만 씁니다.
- 결과에는 건수와 성공·실패만 적습니다. 메일 제목, 본문, 계정은 적지 않습니다.

## 1. 클래식 아웃룩 메일 수집(MAIL-01·03·04·06·07·09·10, 05단계)

| 순서 | 할 일 | 기대 결과 |
| --- | --- | --- |
| 1 | `.env`에서 `SMARTMAIL_DEMO_MODE=false`, `SMARTMAIL_MAIL_SOURCE=auto`로 두고 앱을 실행 | 설정·연결 화면에 'PC 아웃룩(클래식)에서 메일을 읽습니다'가 보임 |
| 2 | 대시보드에서 '메일 수집'(이번 주) 실행 | 목 00:00 ~ 수 23:59에 받은·보낸 메일 건수가 나옴. 공지·뉴스레터·자동발송은 제외됨 |
| 3 | 회신이 있는 메일 스레드를 확인 | 같은 대화가 한 스레드로 묶임 |
| 4 | 업무 상세에서 '원본 보기' 실행 | 본문이 아웃룩 원본에서 표시됨. 첨부는 파일명만 보임 |
| 5 | '아웃룩에서 열기' 실행 | 아웃룩 창에 해당 메일이 열림 |
| 6 | 아웃룩에서 그 메일을 다른 폴더로 옮기거나 지운 뒤 다시 '원본 보기' 실행 | '원문 없음' 표시. 업무는 그대로 남음 |
| 7 | DB 파일(`data/smartmail.db`)을 SQLite 도구로 열기 | `mail_ref`에 참조 ID·스레드 ID·수신 시각만 있고 본문은 없음 |
| 8 | 시각 확인: 오전 9시에 받은 메일을 화면에서 확인 | 같은 시각으로 표시됨(아웃룩 COM 시각 변환 확인) |
| 9 | 새 아웃룩만 쓰는 PC에서 실행 | '그룹웨어 메일함으로 전환합니다' 안내가 나옴 |

## 2. 로그인 창(AUTH-01~09, 04단계)

| 순서 | 할 일 | 기대 결과 |
| --- | --- | --- |
| 1 | 설정·연결에서 사이트별 '로그인' 실행 | 로그인 창에 사이트명과 '저장하지 않음' 안내가 보임. 브라우저가 암호 저장을 제안하지 않음 |
| 2 | 실제 로그인 어댑터가 없는 사이트에서 로그인 시도 | '연동 규격 확인 필요' 안내가 나옴. 규격을 확인한 뒤 어댑터를 추가함 |
| 3 | `SMARTMAIL_BROWSER_LOGIN_SITES`에 지정한 사이트에서 로그인 | 사이트 로그인 화면이 새 브라우저 창으로 열리고, 로그인을 마치면 '로그인됨'으로 바뀜 |
| 4 | 앱을 종료한 뒤 `%TEMP%`에서 `smartmail-pw-*` 폴더를 찾아봄 | 폴더가 없음 |
| 5 | `logs/` 폴더에서 테스트 계정 ID를 검색 | 결과 없음 |

## 3. G-Knowledge 등록·검색(GK-03·04, SRCH-02, 08단계)

먼저 할 일: G-Knowledge 담당자에게 자동화 등록이 허용되는지 확인하고, 화면 필드 선택자를 `src/config/rules/gknowledge_fields.toml`에 채웁니다.

| 순서 | 할 일 | 기대 결과 |
| --- | --- | --- |
| 1 | `.env`의 `SMARTMAIL_BROWSER_LOGIN_SITES`에 `g-knowledge`를 넣고 G-Knowledge에 로그인 | 브라우저 창에서 직접 로그인하고, 앱은 ID·암호를 받지 않음 |
| 2 | 테스트 업무에서 '지식 등록'을 눌러 미리보기 확인 | 제목, 본문(문제·원인·조치), R&R, 태그가 보이고 민감정보는 마스킹됨 |
| 3 | 사용자 승인 후 테스트 글 1건만 등록 | 등록 링크가 업무에 저장됨. 다시 누르면 '중복 등록 불가' 안내가 나오고 미리보기가 열리지 않음 |
| 3-1 | 같은 제목으로 다른 업무를 등록 시도(검색 설정 후) | '같은 제목의 지식이 이미 있습니다' 안내 |
| 3-2 | 태그를 넣고 등록한 글 확인 | 내용 끝에 '태그: …'가 붙어 있음. 첨부는 비어 있음 |
| 4 | 등록한 글을 키워드로 검색 | 이력 조회 2단계 결과에 링크가 나옴 |
| 5 | 테스트 글 삭제 | G-Knowledge 화면에서 직접 삭제함 |

## 3-1. AI-Ground g-llm 호출(AI-01·04·05, 06단계)

먼저 할 일: 정보보안에서 화면 자동화와 업무 요약 학습 활용을 허용하는지 확인합니다(결정기록 0008). 그다음 채팅 화면 선택자를 `src/config/rules/aiground_fields.toml`에 채웁니다. 테스트 환경이 없으므로 실제 업무 내용 대신 합성 질문만 씁니다.

| 순서 | 할 일 | 기대 결과 |
| --- | --- | --- |
| 1 | `.env`에 `SMARTMAIL_AI_ADAPTER=gllm`, `SMARTMAIL_BROWSER_LOGIN_SITES`에 `ai-ground`를 넣고 AI-Ground에 로그인 | 브라우저 창에서 SSO로 직접 로그인하고, 앱은 ID·암호를 받지 않음 |
| 2 | 합성 메일(예: '테스트 전표 확인 부탁드립니다')로 이력 조회 3단계(AI)를 실행 | 브라우저에서 새 대화가 열리고 질문이 들어감. 스트리밍이 끝난 뒤 답변이 'AI 생성 · 검증 필요' 표시와 함께 나옴 |
| 3 | 질문 내용 확인 | 안내문과 마스킹된 요약만 들어가 있음(이름·연락처·메일 원문 없음) |
| 4 | `SMARTMAIL_AI_TIMEOUT_SECONDS=5`로 바꿔 긴 질문 실행 | '응답이 늦어 중단' 안내가 나오고 같은 질문을 다시 보내지 않음 |
| 5 | 점검이 끝나면 AI-Ground 화면에서 테스트 대화를 삭제(가능한 경우) | 대화 목록에 테스트 대화가 남지 않음 |

## 4. 위키 주간보고(WIKI-02~05, 10단계)

먼저 할 일:
- 위키 관리자에게 API 허용 여부와 인증 방식을 확인합니다.
- ERP 주간보고 페이지 구조를 공유받아 `src/config/rules/wiki_template.toml`의 `space_key`·`own_section_heading`·분류 제목을 채웁니다.

| 순서 | 할 일 | 기대 결과 |
| --- | --- | --- |
| 1 | 주간보고 화면에서 초안 생성 | 금주 실적, 차주 계획, 이슈·요청의 3분류 초안이 나옴 |
| 2 | 항목을 고친 뒤 미리보기 | 고친 내용이 마스킹되어 보임 |
| 3 | 실제 게시는 하지 않고 미리보기까지만 확인 | 게시는 사용자가 승인한 뒤 테스트 페이지에서 1회만 진행 |
| 4 | 테스트 페이지에 게시한 뒤 다른 팀원 영역 확인 | 다른 팀원 영역은 바뀌지 않음 |

## 5. 통합 점검표(13단계)

| 항목 | 방법 | 기대 결과 |
| --- | --- | --- |
| 실제 아웃룩 1주 수집 | 1장 순서 1~8 | 제안·제외·스레드 묶음이 정상 |
| 로그인 창 4개 사이트 | 2장 | 저장 안내, 자동완성 없음, 로그아웃 후 세션 폐기 |
| G-Knowledge 테스트 등록 1건 | 3장(사용자 승인 후) | 링크 저장, 중복 등록 방지 |
| 위키 미리보기 | 4장(게시는 승인 후) | 본인 영역만 미리보기됨 |
| 127.0.0.1 바인딩 | 다른 PC에서 `http://<내 PC IP>:<포트>` 접속 | 접속 안 됨 |
| 종료 후 잔존물 | 앱 종료 후 `%TEMP%\smartmail-pw-*`·`logs/`·`data/` 확인 | 브라우저 임시 폴더 없음. 로그에 ID·암호·쿠키 없음 |
| 7일 삭제 | 완료 업무를 하나 만들고 8일 뒤 앱 실행(또는 PC 날짜를 바꾸지 말고 기다림) | 업무·히스토리 삭제, 로그에는 건수만 남음 |
